# Заявленное свойство проверки ломается отдельным входом

**Правило.** Если проверка ЗАЯВЛЯЕТ свойство — «сверяется буквально»,
«симметрично», «ровно N», «все три колонки», — построй вход, который проходит
наивное чтение кода и нарушает заявленное свойство. Полнота отрицательных
предъявлений по ветвям этого не увидит: слабый предикат живёт ВНУТРИ ветви,
которая уже предъявлена красной.

## Чем выстрадано

Фича «справочник наружу» (2026-09-08), четыре дефекта, все в одном страже
`backend/scripts/check_agents_index.py`, все найдены после того, как полнота
предъявлений была объявлена доказанной — 17 ветвей, 25 входов, непредъявленных
0, плюс снятие защиты с самого предъявителя, 3 из 3.

| Заявлено | Что было на деле | Вход, который это ломает |
|---|---|---|
| «сверяется буквально» о заголовке | разделитель после номера читался как `\s+`, то есть три пробела и неразрывный пробел проходили, а слаг отрисовщика при этом ломался | `## 1.` с тремя пробелами |
| «симметрично `check_7`» о ссылках справочника | считалась одна сторона: файл без маршрута ловился, маршрут без файла — нет | ссылка из §4 на несуществующий файл |
| ожидание «тройка номер → заголовок → якорь» | сравнивалась ПАРА: колонка названия отбрасывалась, и название пункта маршрутизатора не сверялось ни с чем | подмена названия пункта при целых номере и якоре |
| «дубль номера — свойство переезда, не этой проверки» | заголовки складывались в словарь по номеру, второй `## 3.` затирал первый | второй раздел с тем же номером |

Три из четырёх нашёл внешний читатель, один — я сам, и все четыре одного рода:
**код заявлял свойство, которого не имел, и заявление читалось убедительнее
кода.**

## Почему полнота по ветвям слепа

Она отвечает на другой вопрос. Счёт ветвей по AST доказывает, что каждая ветвь
достижима и что для каждой есть вход, который её красит. Он ничего не говорит о
том, ДОСТАТОЧНО ЛИ СТРОГ предикат внутри ветви. В трёх случаях из четырёх ветвь
существовала и предъявлялась красной — она просто сравнивала не то, что
обещала; в четвёртом ветви не было вовсе, а раскрытие в докстринге называло
дыру свойством предмета.

Отсюда порядок работы: ветви считает инструмент, а заявления проверяет читатель,
и вход строится на КАЖДОЕ заявление отдельно от входа на ветвь.

## Чего правило не ловит

Свойства, которых никто не заявил. Если докстринг молчит, а предикат слаб,
зацепиться не за что — на это работает раскрытие «чего проверка НЕ проверяет»,
и оно тем ценнее, чем честнее. Правило также не помогает, когда заявление верно
по букве и бесполезно по смыслу: «сверяется буквально» про строку, которую
никто не меняет, ломать нечем и незачем.
