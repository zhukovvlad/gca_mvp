# Параметры варианта с названиями — дизайн (гейт 1)

**Редакция 1, 17.11.2026.** Ветка `feat/variant-params`. Пункт карты
[А11](../../product-roadmap.md); макет —
[`2026-11-17-variant-params/mockup.html`](2026-11-17-variant-params/mockup.html)
(строки настоящие, оффер 76). Ответы пользователя, данные в разговоре
17.11.2026, — в §7.

## 1. Зачем

Под каждой строкой КП на экране «Против нашей цены» и в шапке панели строки
стоит склейка значений: «Устройство жб конструкций · B30 · W6 · рампы»,
«Светопрозрачные перегородки · не уточнено · не уточнено». Названий
параметров нет, поэтому «не уточнено · не уточнено» без каталога не прочитать,
и не видно, откуда значение взято и учитывалось ли оно при подборе аналогов.
Разбор строк КП 13–17.11.2026 каждый раз начинался со скрипта
([случаи с данными](../../data-cases/README.md)); случай 17.11 со сборной
строкой решался бы одним взглядом, будь видно, что тип конструкции взят не
из наименования, а из разделов сметы.

## 2. Что есть сейчас (разведка кода 17.11.2026)

- **Подпись варианта** строит сервер (`crud/our_price_load.py`,
  `_variant_infos`) по **собственной версии схемы варианта**: семья, затем
  значения активных главных параметров по порядку, пустое — «не уточнено».
  Отдаётся одной строкой `variant_label`. Своя версия важна: у вариантов на
  замещённой версии параметров бывает больше, чем у действующей схемы семьи
  (у «Устройства жб конструкций» в вариантах КП три значения, B40 · W6 ·
  перекрытия).
- **Второстепенные параметры** уже приходят парами `secondary: [{name, value}]`;
  в таблице они спрятаны за значком ⓘ (всплывающая подсказка), в панели —
  строкой «Второстепенные».
- **Откуда значение** хранится у строки каталога (контекста) —
  `context_parameter_values.source`: `name` (наименование), `path` (разделы
  сметы), `manual` (задано вручную), `path_conflict` (разделы дают разные
  значения), `none` (нигде нет), `off_list` (текст не из закрытого списка).
  **Какой именно раздел дал значение, не хранится.** Наружу источник сейчас
  не отдаётся.
- **Учитывается ли при подборе.** У работ — лестница из четырёх ступеней
  ([спека лестницы](../specs/2026-11-07-analog-ladder-design.md)): на 1 и 3
  совпадают все главные параметры, на 2 и 4 — только те, у которых в каталоге
  нет отметки «можно отпустить». В ответе строки — `work_rung: {no, released:
  [имена], other_class}`. У систем — своя лестница 4а: «вариант» (все главные),
  «по параметру» (только первый главный), «вся семья» (никакие).
- **Подпись ступени** в таблице — «тот же вариант», «без Марка по
  водонепроницаемости · 3 аналога»; в справочных блоках — «отпущен: …».
- **Аналоги** в ответе панели — объект, договор, наименование строки
  договора, цена; значений их параметров нет. При этом у кандидатов лестницы
  значения главных параметров уже есть (по идентификатору значения).

## 3. Что предлагаю

### 3.1. Строка таблицы КП

Под наименованием (и путём, если он показан) — название семьи отдельной
строкой, под ним **параметры столбиком, каждый своей строкой «название:
значение»**. Порядок — как в схеме варианта: сначала главные, потом
второстепенные. **Видны первые три**; если параметров больше — ссылка
«подробнее · ещё N», по нажатию строка таблицы раздвигается вниз и ссылка
становится «свернуть». Состояние раскрытия не запоминается.

Значение подсвечивается по смыслу:

- «не уточнено» — предупреждающим цветом;
- параметр, не учтённый при подборе аналогов этой строки, — приписка «— не
  учитывается при подборе»;
- значение из разделов сметы — приписка «(из разделов сметы)»; из
  наименования — без приписки (это обычный случай);
- разделы дают разные значения — значение «расходится по разделам» (сегодня
  такое значение неотличимо от «не уточнено»);
- текст не из закрытого списка — «не из списка: «текст»», как во
  второстепенных и в каталоге.

Значок ⓘ уходит: второстепенные теперь в том же столбике.

### 3.2. Подпись под вилкой

Номер ступени и слово «отпущен» из подписей уходят:

- ступень 1/3 — «тот же вариант» (как сейчас);
- ступень 2/4 — «без учёта {названия через запятую}», например «без учёта
  марки по водонепроницаемости · 3 аналога» (первая буква названия —
  строчная внутри фразы);
- «· другой класс» — как сейчас;
- в справочных блоках «отпущен: …» → «без учёта: …».

Номер ступени остаётся только там, где ступень выбирают вручную (лестница
систем в панели).

### 3.3. Панель строки: блок «Работа»

Шапка панели — семья вместо склейки. В секции с ценой КП вместо строки
«Второстепенные» — таблица **«Работа»**:

| Параметр | В строке КП | Откуда | При подборе |
|---|---|---|---|

- **Откуда:** «из наименования», «из разделов сметы», «задано вручную»,
  «разделы расходятся», «нет ни в наименовании, ни в разделах». Сам раздел —
  в соседнем блоке «Где строка», который уже есть.
- **При подборе** — по ступени, на которой строка нашла аналоги:
  «должен совпасть» или «не учитывается». У второстепенных — всегда «не
  учитывается». Строка **без ступени** (нет аналогов, ждёт разбора и т. п.)
  показывает настройку каталога: «должен совпасть» или «можно не
  учитывать» — то, что сделала бы ступень 2/4 (это мой выбор, §6). Вариант на
  замещённой версии схемы ступени 2/4 не имеет — у него все главные
  «должен совпасть».
- Системы — так же, по уровню своей лестницы: «вариант» — все главные
  «должен совпасть»; «по параметру» — первый главный «должен совпасть»,
  остальные «не учитывается»; «вся семья» — все «не учитывается».

### 3.4. Аналоги: значения неучтённых параметров

Если строка нашла аналоги на ступени, где часть главных параметров не
учитывалась, у списка аналогов появляется **по колонке на каждый такой
параметр** со значением этого параметра у строки договора; значение,
отличное от строки КП, подсвечено. Пример из макета: рампы, в КП W6, у трёх
аналогов W8, W12, W12 — то есть аналоги по спецификации дороже, а КП всё
равно выше самой низкой цены на 34 %. На ступени «тот же вариант» колонок
нет — все значения совпадают по определению.

### 3.5. Что отдаёт сервер

- У строки КП (ответ разбора участника и ответ панели) — список главных
  параметров по схеме её варианта: название, значение (или пусто), откуда,
  учитывается ли при подборе на её ступени. Второстепенные — как сейчас,
  плюс «откуда». Сборное значение приходит текстом, как в подписи сегодня.
- У аналога в ответе панели — значения параметров, не учтённых на его
  ступени.
- `variant_label` остаётся: его читает будущий А13 и тесты; экран перестаёт
  его показывать.

Все новые данные — из уже загружаемых таблиц, без новых запросов на строку
(одним запросом на ответ, как второстепенные).

## 4. Что отвергнуто

- **Вариант 2 макета** — значения как сейчас, название только у «не
  уточнено», неучтённого и взятого из разделов. Компактнее, но пользователь
  выбрал полный вариант 1 (§7).
- **Названия из действующей схемы семьи** по порядку значений. Подписи
  разъедутся у вариантов на замещённой версии (жб: два параметра в схеме, три
  значения в варианте).
- **Разбирать `variant_label` на фронте.** Названий в нём нет, а «·» бывает
  внутри значения.
- **Называть конкретный раздел** в «откуда». Не хранится; хранить — менять
  разбор каталога ради подписи. Путь строки уже есть в блоке «Где строка».

## 5. Вне рамок

- Переключатель «должен совпасть / не учитывается» в панели — А12.
- Разбивка плитки «Не с чем сравнить» — А13.
- Скорость панели (11–16 с) — пункт «Скорость 4а и 4б».
- Значения параметров у справочных аналогов (блоки «та же работа в другой
  зоне», «семья по связи») — меняется только подпись «отпущен» → «без учёта».
- Файл подрядчику (4б) — подписи вариантов в нём нет, не трогается.

## 6. Мои решения (поправьте, если не так)

1. **Строка без ступени** показывает в «при подборе» настройку каталога
   («можно не учитывать»), а не прочерк: это подсказка, что сделает ступень
   2, и опора для А12.
2. **Состояние «подробнее / свернуть» не запоминается** между открытиями
   страницы; общего переключателя «показывать параметры» над таблицей нет.
3. **Сборное значение** — одной строкой текстом «трансферные конструкции +
   балки + капители», без разбивки на части в таблице; части уже есть в
   справке «по частям» панели.

## 7. Ответы пользователя (17.11.2026)

1. Нужны названия параметров: «что здесь “не уточнено, не уточнено”???».
2. Вид в таблице — вариант 1, «параметр: значение» рядом, следующий —
   под ним; первые три, остальные по «подробнее», раскрытая строка
   разъезжается вниз, «свернуть» сворачивает.
3. Слово «ступень» в подписях непонятно — заменено на «учитывается / не
   учитывается при подборе».
4. Значения неучтённых параметров у аналогов — в составе А11 (карта, PR #88).
