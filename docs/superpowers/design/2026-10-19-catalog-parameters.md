## 1. Проблема в числах

**Предел в три параметра уже упёрся.** На стенде 320 активных семей; у 92 из
них ровно три параметра, у 90 — два, у 74 — один, у 64 — ни одного. Добавить
четвёртый нельзя ни модели, ни человеку: предел сидит в базе, в разборе ответа
модели, в ручной правке и в окне.

Пользователь называет два параметра, за которые платят и которых нет:

- **«Устройство жб конструкций»** — коэффициент армирования. Куб ж/б — это
  бетон плюс арматура, и по коэффициенту видно, сколько арматуры в кубе;
  без него кубы сравниваются нечестно. У семьи уже три параметра: класс
  бетона, марка по водонепроницаемости, тип конструкции.
- **«Укладка гидроизоляции»** — тип гидроизоляции (битумно-полимерная,
  оклеечная). Параметр «Тип материала» держит марку (Техноэласт ЭПП, Икопал),
  а не тип; ещё два параметра — толщина и число слоёв.

**Армирование — число, и записано оно почти нигде.** В семье ж/б 1 237 строк
последних смет 8 договоров. В договоре 14 коэффициент стоит числом в каждой из
1 049 строк («Балки В25;F150;W8 коэф. армир. 131,73 кг/м3», значения 130–175
кг/м³, десятки разных с точностью до сотых). В остальных 7 договорах (188
строк) армирование не упомянуто ни разу: пишут «Плиты перекрытия B40», и
арматура подразумевается в цене куба. Сделанный по сегодняшним правилам,
такой параметр раздробил бы семью на варианты по каждому числу и упёрся бы в
предел 30 значений одним договором.

**Данных и так мало для дробления.** Замер разброса (предложение, §2.6): на
стенде 8 договоров, у почти каждого варианта наблюдения из 1–3 договоров.
Сегодня вариант — это семья плюс значения **всех** параметров, и каждый новый
параметр делит варианты ещё мельче. Снять предел, ничего больше не меняя,
значит сделать сравнение ещё реже возможным.

**Окно «Править схему» не выдержит больше трёх параметров.** Значения —
свободный текст по строке, параметры — сплошной колонкой, «Убрать параметр»
выглядит подписью, а что затронет правка, не видно до сохранения (пользователь,
19.10.2026: «прокрутка норм, но сам дизайн окна убогий»).

## 2. Решение

### 2.1. Предел снимается для человека, модель остаётся как есть

- **Ручная правка схемы** принимает больше трёх параметров. Новый предел —
  **10 параметров на семью, главных и второстепенных вместе**; одиннадцатый
  окно и сервер не принимают (моё решение, обоснование в §4: модель отвечает
  на значения параметров строки одним вызовом, и длина ответа растёт с
  числом параметров). Предел 30 значений на параметр не меняется.
- **Схему новой семьи модель строит как раньше — до трёх параметров**
  (решение пользователя 19.10.2026). Её схемы проверены на стенде; параметры
  сверх трёх и второстепенные — знание человека о том, за что платят, и из
  наименований модель его не извлечёт.

### 2.2. Главные и второстепенные параметры

У каждого параметра появляется пометка **«главный» или «второстепенный»**.

- **Вариант складывается только из главных параметров** (решение пользователя
  19.10.2026). Перекрытие B25 W8 с армированием 120–140 и оно же с 160–180 —
  один вариант, и норматив фичи 4 у них будет общий.
- **Второстепенный параметр уточняет строку**: его значение записано у
  контекста, видно на карточке контекста, а на экранах фичи 4 — рядом с ценой
  и фильтром; варианта не делит и данных не дробит. Фильтр и показ рядом с
  ценой — фича 4, не эта.
- **Все параметры, существующие сегодня, становятся главными**, и все
  варианты стенда остаются как есть. Параметры, которые предлагает модель, —
  тоже главные.
- Роль меняется в окне схемы в обе стороны. Сделать второстепенный главным —
  варианты делятся; главный второстепенным — варианты сливаются (§2.3).

Армирование пользователь ставит **второстепенным** «пока что»; тип
гидроизоляции, по его словам, главный — у обеих семей станет по четыре
параметра.

### 2.3. Что происходит при правке схемы

Сегодня любое структурное изменение — добавить или убрать параметр, даже
добавить одно значение — заводит новую версию схемы: модель заново отвечает
на значения всех параметров у **всех** строк семьи, и варианты собираются
заново новыми записями. Для второстепенного параметра это неприемлемо: правка,
которая по смыслу ничего не делит, перетряхивала бы варианты и тратила вызовы
модели на уже известные значения. Поэтому фича задаёт правило по смыслу
правки:

| Правка | Варианты | Что спрашивается у модели |
|---|---|---|
| добавить второстепенный параметр | не меняются | только значение нового параметра, у всех контекстов семьи |
| убрать второстепенный параметр | не меняются | ничего |
| добавить значение второстепенного | не меняются | только этот параметр — у строк, где он «не уточнено» |
| слить значения второстепенного | не меняются | ничего — у контекстов значение-источник заменяется целью |
| сделать главным второстепенный, уже сохранённый | делятся по его значениям | ничего — значения уже известны |
| сделать главный второстепенным | сливаются | ничего |
| добавить главный параметр — в том числе новый, сразу отмеченный главным | собираются заново, как сегодня; итоговое число неизвестно до ответов модели | значение нового параметра у контекстов семьи |
| убрать главный параметр, добавить значение главного | собираются заново, как сегодня | значения у строк семьи, как сегодня |
| слить значения главного | как сегодня: варианты с источником сливаются с вариантами с целью | ничего |
| поправить написание | как сегодня | как сегодня |
| перевести заполненный параметр в диапазоны, сменить границы или шаг | второстепенный — не меняются; главный — переносимые значения переходят в варианты нового ключа сразу, неразрешимые — после ответа | только этот параметр — у контекстов с неразрешимым значением (ниже) |
| перевести диапазоны обратно в точные | второстепенный — не меняются; главный — после ответов | только этот параметр — у всех контекстов с его значением |

**Перестройка значений заполненного параметра** — перевод в диапазоны или
смена границ и шага (ревью Codex, второй круг, PR #71). Каждое прежнее
значение система сначала пытается разрешить сама, без модели:

- **точное число** («4», «5.1») однозначно попадает в один новый диапазон —
  значение переносится;
- **прежний диапазон, целиком лежащий внутри нового** (при шаге 40 вместо 20:
  «120–140» ⊂ «120–160»), переносится;
- **прежний диапазон, который делится** (при шаге 10 вместо 20 «120–140»
  накрывает «120–130» и «130–140»), и значение, не являющееся числом, —
  неразрешимы: у контекстов с таким значением этот параметр запрашивается у
  модели заново.

Прежние значения не удаляются — запрет удаления значения держит смысл
значений у строк, и он не нарушается: перенесённое значение **сливается** с
новым диапазоном (у контекстов значение заменяется сразу), неразрешимое
**замещается** — уходит из списка в историю, а у контекстов заменяется
ответом модели. До ответа контекст остаётся в прежнем варианте с прежним
значением и пометкой «уточняется» — так сегодня ведёт себя любой
перезапрос; «не уточнено» до ответа не ставится, чтобы строка не прыгала в
чужой вариант и обратно.

Сводка до сохранения называет: сколько значений перенесётся без модели и
куда («4 мм → „до 5“»), у скольких контекстов значение уточнится у модели и
из-за каких прежних значений; для главного параметра — сколько вариантов
изменится сразу и что итог для остальных станет известен после ответов.

**Слияние значений второстепенного** — отдельная операция по смыслу, а не
сегодняшнее слияние: сегодня оно переписывает наборы значений вариантов и
переводит контексты между вариантами, а у второстепенного параметра в
вариантах значений нет. Слияние «120–140» с «120–140 кг/м³» меняет только
значения у контекстов; варианты и главные значения остаются (ревью Codex,
PR #71).

**Сменить роль «по известным значениям» можно только у параметра, который
уже сохранён и чьи значения модель дала.** Параметр, добавленный в этой же
правке и сразу отмеченный главным, — это добавление главного параметра:
значения запрашиваются, и итоговое число вариантов сводка называет
неизвестным. Если у части контекстов ответ по второстепенному ещё не пришёл,
сводка смены роли называет их число: их вариант уточнится с ответом.

Главное обещание: **правка второстепенного параметра не меняет ни одного
варианта и ни одного значения главных параметров у строк.** Как именно это
устроить — держать второстепенные вне версии схемы или переносить варианты
между версиями — решает спека; дизайн требует результат.

Обещание симметрично: **правка главных параметров, собирающая варианты
заново, не перезапрашивает уже известные значения второстепенных** — модель
отвечает только на главные (моё решение). Иначе добавление одного значения
классу бетона заново спросило бы армирование у всей семьи и могло бы сдвинуть
уже сверенные диапазоны.

Смена роли туда и обратно возвращает **прежние варианты**, а не заводит новые:
если армирование сделали главным, потом второстепенным и снова главным,
варианты «B25 · W8 · перекрытия · 120–140» — те же записи, что в первый раз
(моё решение; фича 4 заведёт на варианты нормативы, и лишняя смена
идентичности ей не нужна).

**Слияние семей:** строки переходят в семью-цель с её схемой, второстепенные
параметры семьи-источника пропадают вместе с её схемой, как сегодня пропадают
главные; предпросмотр слияния называет их (моё решение).

Пока ответа модели нет, значение второстепенного у строки — «не уточнено»,
как у главного сегодня.

### 2.4. «Пересобрать схему» не трогает параметров человека

Сегодня «Пересобрать схему» просит модель построить схему семьи с нуля.
Теперь у семьи бывают параметры, добавленные человеком, — пересборка их не
знает и не должна терять (решение пользователя 19.10.2026):

- **пересборка заменяет только параметры модели**; параметры человека —
  главные и второстепенные, с их значениями у строк и настройкой «только из
  списка» — остаются как есть;
- **параметр модели, который человек правил в окне** (дописал значения,
  поправил имя, сменил роль, включил «только из списка»), становится
  параметром человека и пересборкой тоже не заменяется (моё решение: иначе
  ручная доводка пропадала бы при каждой пересборке);
- модели в запросе пересборки показываются параметры человека с указанием их
  не повторять — имена параметров и так уходят наружу (§2.7);
- модель предлагает до трёх параметров, но не больше, чем оставляет предел
  10 вместе с параметрами человека;
- варианты собираются заново (состав главных меняется); у модели
  запрашиваются значения только её новых параметров, значения параметров
  человека у строк остаются.

### 2.5. Числовые величины — точным списком или диапазонами

Числовой параметр бывает двух видов, и оба — обычные значения списка:

- **значений немного, и каждое что-то значит само по себе** — число слоёв
  (1, 2, 3), толщина гидроизоляции (4, 8, 10 мм), класс бетона: значения
  пишутся точно, как сегодня («Количество слоёв» и «Толщина, мм» у «Укладки
  гидроизоляции» на стенде так и устроены);
- **величина сплошная, и почти каждая строка даёт своё число** — коэффициент
  армирования: значения задаются диапазонами.

**Вид значений у параметра объявлен явно — переключатель «Точные /
Диапазоны»** (решение пользователя 19.10.2026). Без него модель видела бы
только подписи «120–140» и догадывалась, что это диапазон, — на границах и на
«до 120» догадка ошибается, и проверить её нечем.

- **Диапазоны задаются границами, а не текстом:** «от 120 до 200, шаг 20».
  Подписи строит система — четыре диапазона внутри границ и **всегда два
  крайних**, «до 120» и «200 и более» (решение пользователя 19.10.2026: иначе
  строка с 95 или 230 кг/м³ ушла бы в «не уточнено», хотя число в
  наименовании есть). Дыр, перекрытий и спорных подписей не бывает. Единица
  берётся из имени параметра.
- **Модель получает правило вместе с параметром:** «значения — диапазоны;
  найди число в наименовании и отнеси его к диапазону; нижняя граница
  включается, верхняя — нет; числа нет — „не уточнено“». У точных параметров
  запрос не меняется.
- **Диапазоны — только ручные.** Схему с нуля модель строит как раньше
  (§2.1): сплошную величину она заведёт точным списком чисел — так на стенде
  устроена «Толщина, мм» у гидроизоляции, 12 значений, строки у шести, — и
  человек переделывает такой параметр в диапазоны в окне. Шаг диапазона —
  решение человека о том, с какой разницы работа становится другой; из
  наименований его не вывести (ответ пользователю 19.10.2026).

Отдельного типа «число» фича не заводит (моё решение): диапазоны остаются
значениями списка, вид параметра лишь говорит системе, как их строить, а
модели — как выбирать. Шаг 20 кг/м³ для армирования назвал пользователь: с
такой разницы два куба для него перестают быть одной работой. Точное число
остаётся в наименовании.

**Диапазон включает нижнюю границу и не включает верхнюю** (моё решение; так
и пишется в подсказке модели): «до 120» — меньше 120, «120–140» — от 120 до
140, не включая 140, …, «200 и более» — от 200. Граница всегда принадлежит
верхнему диапазону: 140,00 — «140–160», 200 — «200 и более». Последний
диапазон называется «200 и более», а не «больше 200», иначе ровно 200 не
попадало бы никуда (ревью Codex, PR #71).

**«Только из списка».** Сегодня модель, встретив в наименовании значение,
которого нет в списке, дописывает его в список сама. Так на стенде дописано
**115 значений в 32 параметрах**. Иногда это полезно (в смете встретился
«B42»), но список при этом теряет единообразие: в «ЦПС → Толщина стяжки»
модель взяла из наименований «до 100 мм» и «от 40 мм» и поставила их рядом с
точными «100 мм» и «40 мм» — граница смешалась с толщиной, и строку «до 100
мм» не сравнить ни с одной точной; в «Посадке растений → Высота растения»
она сама настроила разношёрстных диапазонов «40-50», «60-80», «200-220»,
«400-500». А на «131,73 кг/м³» модель дописала бы число рядом с диапазонами
армирования и сломала деление. Переключатель
**«только из списка»** запрещает модели дописывать список: она выбирает из
того, что есть, или отвечает «не уточнено»; список меняет только человек
(решение пользователя 19.10.2026).

- У точных параметров по умолчанию выключен — как сегодня; у диапазонов
  включён всегда.
- **Значения не из списка не теряются молча** (моё решение, принято
  пользователем): при закрытом списке модель, увидев в наименовании значение
  не из списка, называет его, а окно показывает рядом с параметром «у 12
  строк встретились значения не из списка: B42 (8), B47 (4)». Человек
  добавляет значение в список или сливает с существующим; уже дописанные
  моделью значения окно помечает, и они сливаются тем же действием.

### 2.6. Окно «Править схему»

Раскладка **«Список и редактор»** (выбор пользователя, макет — вариант Б):

- **окно не выше экрана; шапка и низ — сводка и «Сохранить» — закреплены,
  а список параметров и редактор прокручиваются каждый сам по себе**
  (вопрос пользователя 19.10.2026: с ростом числа параметров прокрутка
  вернётся). Замер макета: 10 параметров в окне высотой с экран ноутбука не
  помещаются и при компактных строках — список прокручивается внутри своей
  колонки, длинные значения выбранного параметра — внутри редактора, ни то
  ни другое не уводит сводку и кнопку;
- окно шире нынешнего; слева — все параметры двумя группами, «Главные —
  определяют вариант» и «Второстепенные — вариант не делят», строка
  параметра компактная — имя и одна строка пометок (вид, число значений и
  строк, «ваш / модели»); ниже — «Добавить параметр» со счётчиком «N из 10»,
  недоступный на пределе;
- справа — выбранный параметр: имя, роль переключателем с пояснением, вид
  значений «Точные / Диапазоны», «Убрать параметр» — явной кнопкой;
  - у точных — значения плашками с числом строк (значение, которого нет ни у
    одной строки, — пунктиром), поле «добавить значение», переключатель
    «только из списка» и при закрытом списке — «встретились значения не из
    списка»;
  - у диапазонов — поля «от — до — шаг», превью получившихся диапазонов с
    числом строк («4 диапазона от 120 до 200 и 2 крайних»), правило, по
    которому модель относит число, и «только из списка», включённый без
    возможности снять;
- значение, как и сегодня, нельзя удалить — только слить с другим;
- внизу — **сводка «что изменит правка» до сохранения**: меняются ли
  варианты и на сколько, у скольких контекстов что будет запрошено у модели.
  Для смены роли сохранённого параметра число вариантов «было → станет»
  считается до сохранения — значения уже известны; для параметра,
  добавленного в этой же правке, сводка называет число запросов к модели, а
  итоговое число вариантов — неизвестным до ответов (§2.3). При переводе в
  диапазоны и смене границ — что перенесётся без модели и у скольких
  контекстов значение уточнится (§2.3, «Перестройка значений»).

Где ещё видна роль: в списке вариантов семьи название варианта собирается
только из главных значений; на карточке контекста второстепенные параметры
показаны отдельно от главных.

### 2.7. Что уходит наружу

Без изменений: имена параметров и списки значений и так уходят во внешнюю
модель (`AGENTS.md` §3) — в том числе параметры человека в запросе
пересборки (§2.4). Роль параметра — служебная пометка; цены, объёмы,
договоры и объекты не уходят.

## 3. Варианты решения и их цена

1. **Только поднять предел** — все параметры делят вариант. Дёшево: одна
   константа в нескольких местах. Цена — данные дробятся дальше, а замер уже
   показал 1–3 договора на вариант; армирование числом раздробило бы ж/б
   окончательно. Отвергнуто.
2. **Главные и второстепенные** (выбрано). Цена — правка второстепенного
   должна обходить нынешнюю механику версий (§2.3), это главная работа фичи.
   Выигрыш — уточнение без дробления и простое правило сравнения для фичи 4:
   «точный вариант → вся семья» вместо лестницы по уровням.
3. **Тип «число» с поправкой цены** (норматив куба ж/б с поправкой на
   армирование). Точнее всего, но новая модель данных и формула, для которой
   на стенде данных у одного договора из восьми. Отложено: диапазоны
   второстепенного параметра сохраняют информацию, и к этому можно вернуться.

## 4. Риски

- **Надёжность ответа модели при многих параметрах.** Значения всех
  параметров строки модель даёт одним вызовом; сегодня у неё не больше трёх.
  Отсюда мягкий предел 10, а на стенде после реализации — проверка: доля
  отвергнутых ответов у семей с 4+ параметрами против нынешней (ошибки схемы
  ответа фичи 2 — 1,17 %).
- **Модель плохо относит числа к диапазонам.** Проверяется на договоре 14:
  1 049 строк с коэффициентом в наименовании дают готовую сверку «число →
  диапазон» без ручной разметки.
- **Устойчивость варианта при правке главных параметров.** Добавление
  значения главному параметру по-прежнему собирает варианты заново новыми
  записями. Пока нормативов нет, это безвредно; фича 4 заведёт нормативы на
  вариант, и для неё это станет вопросом — **фича 3в его не решает и не
  ухудшает**, а называет фиче 4.
- **Стоимость.** Добавление второстепенного параметра в ж/б — 218 вызовов
  модели; по ценам devlog фичи 3а (около 1 200 токенов запроса на вызов) это
  порядка полудоллара. Сводка окна показывает число вызовов до сохранения, а
  предохранитель события очереди (3 000 контекстов, $15) остаётся.

## 5. Приёмка (что пользователь увидит на стенде)

1. В «Устройстве жб конструкций» добавлен второстепенный «Коэффициент
   армирования, кг/м³» видом «Диапазоны» — от 120 до 200, шаг 20, шесть
   значений с двумя крайними: сводка до
   сохранения говорит «варианты не меняются, 72»; после ответов модели
   вариантов по-прежнему 72, у остальных договоров — «не уточнено». Строки
   договора 14 сверяются с числом в наименовании скриптом: **не меньше 95 %**
   строк попали в диапазон своего числа (моё решение). Меньше — подсказка
   модели правится в этой же фиче до приёмки.
2. В «Укладке гидроизоляции» добавлен главный «Тип гидроизоляции»: варианты
   собираются заново, как сегодня.
3. Армирование сделано главным и обратно: сводка показывает «было → станет»,
   варианты делятся и сливаются без единого вызова модели.
4. Окно «Править схему» с семьёй на пределе в 10 параметров на экране
   ноутбука: окно не выше экрана, сводка и «Сохранить» видны всегда, список
   и редактор прокручиваются каждый сам; «Добавить параметр» недоступен.
5. «Пересобрать схему» у гидроизоляции после пунктов 2 и правки модельного
   параметра: «Тип гидроизоляции» и поправленный параметр остались со
   значениями у строк, заменились только нетронутые параметры модели, и
   модель не предложила второй «тип гидроизоляции».
6. У «ЦПС → Толщина стяжки» список закрыт «только из списка»: значения,
   дописанные моделью раньше («10 мм», «до 100 мм», «от 40 мм»), помечены
   в окне; новых модель не заводит, а значение не из списка, встретившееся
   в наименовании, видно в окне с числом строк.
7. «Толщина, мм» у «Укладки гидроизоляции» (все 12 значений — числа)
   переведена в диапазоны: сводка показывает перенос каждого значения без
   модели и ноль запросов; затем шаг уменьшен так, что один диапазон
   делится, — запрос уходит только у контекстов этого диапазона, и до
   ответа они остаются в прежнем варианте с пометкой «уточняется».

Пересмотр схем четырёх семей, провалившихся в замере (щебёночное основание,
обработка бетонных поверхностей, дорожные знаки, гидрошпонка), — работа с
каталогом этим окном, а не условие приёмки фичи.

## 6. Решения пользователя в диалоге гейта (19.10.2026)

- Малая фича делается до фичи 4; переделка окна схемы — в ней.
- Коэффициент армирования ж/б нужен, чтобы сравнивать кубы с разной долей
  арматуры; в сметах обычно пишут «перекрытие В40», подразумевая бетон с
  арматурой.
- Существенная разница в армировании — около 20 кг/м³; параметр пока
  второстепенный.
- Второстепенный параметр вариант не делит.
- Модель строит схемы как раньше — до трёх параметров; сверх этого и
  второстепенные параметры добавляет человек.
- Окно — раскладка «Список и редактор».
- «Пересобрать схему» заменяет только параметры, предложенные моделью;
  параметры человека, в том числе главные, остаются.
- Число слоёв и подобные дискретные числа — точным списком, диапазоны — для
  сплошных величин.
- Вид значений объявляется явно переключателем «Точные / Диапазоны»;
  диапазоны задаются границами и шагом, крайние «до …» и «… и более» есть
  всегда; диапазоны заводит только человек.
- «Только из списка» — в описанном виде, с подсказкой «встретились значения
  не из списка».

## 8. Границы

- Правило сравнения внутри семьи («точный вариант → вся семья», подпись
  уровня сравнения) и показ второстепенных рядом с ценой — фича 4.
- Устойчивость варианта при правке главных параметров — вопрос фичи 4 (§4).
- Ручная простановка значения параметра у отдельной строки в фичу не входит:
  значения, как и сегодня, даёт модель.
- На стенде две активные семьи с названием «Устройство жб конструкций» (72 и
  9 вариантов, у второй — «Класс бетона» и «Тип конструкции») и две —
  «Шпатлевание» (7 и 1 вариант; «Число слоёв» у одной «2 слоя», у другой
  «2»); «Светильники»
  с одиннадцатью строками дешевле 1 % медианы — работа с каталогом, не эта
  фича.
- Предел значений параметра в интерфейсе админа и порог автопривязки — пункт
  А8, не эта фича.
- Модель, предлагающая диапазоны сама, — не эта фича: это правка проверенной
  подсказки схемы с новым замером. Идея на потом, без модели: система
  помечает параметры, где много разных чисел и мало строк на значение, как
  кандидатов в диапазоны.
