## Global Constraints

- **§3, §5 и §8 не тронуты ни одним символом.** Предъявляется diff'ом против
  `55d12d0` (спека DoD 2).
- **Вынесенный инвариант сохраняет силу и правится только ревизией**
  `AGENTS.md` — спека §2.6. Переезд не даёт права переформулировать.
- **Канонизация сверки — только список спеки §2.8.** Расширение канонизации по
  ходу прогона запрещено: если преобразование понадобилось, оно вносится в
  спеку врезкой и называется, а не применяется молча.
- **«Лишняя» правая сторона — только три категории спеки §2.8.** Всё прочее,
  не покрытое единицей карты, — расхождение.
- **Порог размера `AGENTS.md` ≤ 45 000** (спека DoD 1). При промахе — замер и
  предъявление, а не молчаливый пересмотр.
- **Канон нотации `§7.N`.** Исторические документы (32 вхождения) не правятся.
- **Перед пушем — полный `just ci`** (§9.3): фича трогает код.
- **Страж красен с Task 2 по Task 8 включительно** — проверка 5 не разрешает
  v6.20. Это ожидаемое состояние фичи-ревизии, а не поломка; зеленеет на
  Task 9.

**`$SCRATCH` назначается первой командой Task 1**, иначе остальные команды
плана не запускаются буквально:

```powershell
# PowerShell (основная оболочка проекта)
$env:SCRATCH = Join-Path $env:TEMP "gca-reference-out"
New-Item -ItemType Directory -Force $env:SCRATCH
```

```bash
# Bash, если задача исполняется из него
export SCRATCH="${TEMP:-/tmp}/gca-reference-out" && mkdir -p "$SCRATCH"
```

Требование к директории одно, и проверяется оно **структурно, а не по факту
чистого дерева**: `$SCRATCH` лежит ВНЕ дерева репозитория, поэтому файлы оттуда
закоммитить нельзя в принципе. Предъявление — сравнение путей:

```bash
git rev-parse --show-toplevel   # корень репозитория
python -c "import os,sys;print(os.path.commonpath([os.environ['SCRATCH'],sys.argv[1]]))" <корень>
```

Общий префикс не должен совпадать с корнем репозитория. `git status
--porcelain` для этого не годится: **после `git add` он показывает staged-файлы
буквой в первой колонке** (проверено: `A  <файл>`), то есть «пусто» после
добавления — неверное ожидание, и утверждение об этом из предыдущей редакции
плана снято.

Причина самого требования не гигиена, а §9.1: скрипты в репозитории сделали бы
правку «документацией с проверочным инструментарием» со своим набором условий,
а сверщики фичи 2 уже показали, что живут ровно одну фичу.

## Решения плана, которых нет в спеке

1. **Порядок задач:** оракул (Task 1) строится ДО первой правки — иначе он
   перестаёт быть внешним. Переезды (Task 2–5) идут от самого крупного файла к
   самому спорному, чтобы ошибка формы вскрылась на схеме, а не на осях денег.
2. **Страж зеленеет на Task 9**, не раньше: проверка 5 разрешает версии по
   объединению «архив ∪ действующая», а v6.20 появляется в преамбуле последней.
   План обязан это назвать, иначе краснота посреди фичи прочтётся как поломка.
3. **Имена новых проверок стража:** `check_13` (состав §7), `check_14`
   (§4 ↔ `schema.md`), `check_15` (§10 ↔ `money-axes.md`), `check_16` (контекст
   ссылок и адресов в `docs/reference/`). Итого шестнадцать.
4. **`check_16` заводится отдельной проверкой, а не ветвью внутри 13–15:**
   контекст ссылок — свойство ФАЙЛА-приёмника, общее для всех трёх, и в составе
   маршрутизатора ему места нет.
5. **Сверщик живёт в скретче** и в репозиторий не кладётся — как у фичи 2. Его
   вердикт попадает в devlog числами, а не файлом.
6. **Четыре разовых инструмента вместо одного:** сверщик, измеритель, счётчик
   адресов и предъявитель отрицательных входов. Разделены по предмету
   доказательства, а не по удобству: один скрипт, доказывающий и сохранность, и
   размер, и покрытие ветвей, невозможно уронить по одной причине — а значит
   его собственные отказы нечитаемы.
7. **Devlog заводится в Task 9, а не по ходу.** Задачи 2, 5, 6 и 8 производят
   материал для него (карту инвариантов, два сопоставления, замеры, числа
   отчёта стража); писать его частями значило бы девять раз править файл,
   который по §9.2 описывает фичу целиком.


Носитель отрицательных предъявлений — разовый скрипт той же задачи; без него
«предъявлено красным» остаётся словом в devlog:

```python
# $SCRATCH/demo_guard.py
Case = tuple[str, str, str]          # имя входа, файл и правка, ожидаемая ветвь
CASES: tuple[Case, ...]              # не менее десяти входов таблицы спеки §2.9
MUTABLE: tuple[str, ...]             # перечень временно изменяемых файлов
def assert_clean() -> None           # отказ ДО запуска, если вход отличается от HEAD
def branches() -> dict[str, list[str]]   # ветви `details.append` по AST, на проверку
def run_case(case: Case) -> tuple[bool, str]   # правка → прогон → откат в finally
def report() -> tuple[int, int, list[str]]     # ветвей, входов, НЕПРЕДЪЯВЛЕННЫЕ ветви
```

**Утверждения**
- `check_13` сверяет соответствие **конкретного номера пункта конкретному
  якорю** против `EXPECTED_SCREEN_ANCHORS`, а не только число строк и
  существование целей: перестановка двух якорей обязана падать, оставаясь
  биекцией (спека §2.9);
- `check_13` падает и на дубле идентификатора слева, и на дубле цели справа, и
  на удалении раздела из `screens.md` при целом маршрутизаторе;
- `check_14` и `check_15` сверяют маршрут и шапку «Когда читать:» своих файлов;
- `check_16` ловит две вещи, которых не видят 13–15: ссылку `docs/…`, не
  поднятую до `../…`, и неквалифицированный `§N` в файле справочника;
- **каждая фактическая ветвь отчёта предъявлена красной по отдельному входу**;
  у проверок кратности предъявлены **обе** границы (N−1 и N+1);
- число ветвей снимается по AST (вызовы `details.append`), число входов
  считается отдельно, и оба числа записаны в докстринг модуля — как у
  `check_12`;
- **`report()` возвращает ноль непредъявленных ветвей**; ветвь, которую не
  умеет уронить ни один вход, — либо недостижимая, либо непроверенная, и в
  обоих случаях это находка, а не мелочь;

  зелёном отчёте (`docs/pitfalls/runs.md`, укусило фичу 2 дважды);

  работу своим откатом;
- **откат стоит в `finally`**: исключение посреди прогона иначе оставит
  повреждённый файл, и следующая команда будет мерить испорченное дерево;
- после прогона **`git diff --quiet HEAD -- <MUTABLE>`** — код 0. Проверяется
  именно происхождение правок предъявителя, а не чистота дерева целиком:

  говорит «из 16».
