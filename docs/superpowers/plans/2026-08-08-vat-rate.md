# Ф4б: ставка НДС из шапки колонок — Implementation Plan

> **Для исполнителя.** План самодостаточен: 49 шагов с чекбоксами (`- [ ]`),
> каждый несёт команду и ожидаемое число. Внешних инструментов он **не
> требует**. Если в сессии доступны `superpowers:subagent-driven-development`
> или `superpowers:executing-plans`, ими удобно вести пошаговое исполнение, но
> это выбор, а не условие.
>
> **Оболочка — PowerShell 5.1.** Все команды ниже написаны под неё. `&&`, `||`,
> `env`, `grep`, `wc` и продолжение строки обратным слэшем здесь не работают;
> вместо них — `;` с `if ($?)`, `$env:VAR`, `rg`, `Measure-Object` и обратный
> апостроф либо естественный перенос внутри блока.

**Цель:** ставка НДС, заявленная в шапке ценового блока подрядчика, доезжает до
`proposals.vat_rate` как факт файла; деление по блоку итогов служит перекрёстной
проверкой и никогда — источником значения.

**Архитектура:** та же раскладка, что завела Ф4a, — чистое ядро плюс тонкая
оболочка. Новый модуль `parser/vat_rate.py` не знает о `Worksheet`: в нём
распознавание суффикса, согласование двух шапок, сверка с блоком итогов и тексты
предупреждений. Ячейки читает `get_proposals` — единственное место, где блок
подрядчика и результат `get_summary` уже рядом. Смещения групповых шапок выдаёт
`parse_contractor_row`, где раскладка уже определена.

**Стек:** Python 3.12, openpyxl, SQLAlchemy 2.x, Alembic, pytest, `Decimal`
end-to-end.

**Спека:** [2026-08-08-vat-rate-design.md](../specs/2026-08-08-vat-rate-design.md)
**Рамка фазы:** [phase7-frame.md](../../phase7-frame.md)
**Ветка:** `feat/vat-rate` (создана; спека закоммичена в `79d78a4`, правки гейта 2 — `2080e1a`, `d82b7cf`)

## Global Constraints

- **Деньги и ставки — `Decimal`, никогда `float`** (`AGENTS.md` §3). В JSON —
  строки; в тестах сравнивать `Decimal` с `Decimal`.
- **Ставка хранится в процентных пунктах** (`20`, не `0.20`) — в JSON, в БД и в
  текстах предупреждений одинаково.
- **Все четыре предупреждения Ф4б — parser warnings** (`ParseResult.warnings`,
  сессия A). Нового **вида** доменного предупреждения фича не заводит; защитная
  конверсия при импорте может дополнить существующее агрегированное
  `value_problems` (спека §2.7, §2.9).
- **Предупреждения не каскадируют**: ставка не получена или шапки противоречат →
  сверка не запускается и «сверка не проведена» не добавляется. Отсутствие обоих
  ключей блока итогов тоже не даёт предупреждения (спека §2.6).
- **Предупреждения агрегированные**: по одному на вид, перечень внутри, усечение
  до `MAX_SUMMARY_WARNING_EXAMPLES` (уже есть в `summary_block`, не заводить
  второй константы).
- **Тексты предупреждений не несут ничего, что различается между лотами** —
  иначе дедупликация `dict.fromkeys` в `estimate.py` перестанет их схлопывать
  (спека §2.8).
- **`parser/` не импортирует из `services/`** — направление зависимости
  зафиксировано Ф4a и не меняется.
- **Локальный контекст `Decimal` для деления**: `prec = ARITHMETIC_PRECISION`,
  трапы на `Overflow`, `DivisionByZero`, `InvalidOperation`; трапов на `Inexact`
  и `Rounded` **нет** — деление неточно по природе (спека §2.4). Глобальный
  контекст приложения не меняется, это отдельный тест.
- **Числа, которые нельзя «поправить»:** база `1190` собранных,
  `1184 passed / 6 skipped`, vitest `175`; `tests/unit/parser` — `334`;
  `tests/integration/test_import_fixture_e2e.py` — `25`. Пофайлово:
  `test_parse_contractor_row` `17`, `test_get_proposals` `21`,
  `test_summary_block` `63`, `test_estimate` `50`. Fixture —
  `2576 / 746 / 222 / 485 / 39 / 38 / 16` и `EXPECTED_PRICED_ROWS`.
  Расхождение — повод разбираться, а не обновлять ожидание.
- **`samples/` не коммитится**; реальные суммы и реквизиты не попадают ни в код,
  ни в тесты, ни в доки, ни в сообщения коммитов. В fixture добавляются только
  заголовки колонок.
- **Кириллица в терминал не печатается** исполнителями: вердикты ASCII, русский
  текст — в файл, `rg -c` вместо `rg`, `Read` вместо `Get-Content`. Кодировка
  дочернего python — отдельным пунктом ниже.
- Команды бэкенда — из `backend/` через `uv run`; системный python не вызывать.
  Git — из корня репозитория.
- **Разовые скрипты живут вне репозитория.** Каталога `scratchpad/` в проекте
  нет и в `.gitignore` он не внесён, поэтому обещание «в репозиторий не
  попадёт» обеспечивается расположением, а не игнором:

  ```powershell
  $scratch = Join-Path $env:TEMP 'gca-vat-rate'
  New-Item -ItemType Directory -Force $scratch | Out-Null
  ```

  Скрипт — **файлом** в `$scratch`, не через `python -c`. Для импорта модулей
  `backend` нужен `PYTHONPATH`. Каталог сносится на финале (Task 8).
- **Кодировка дочернего python** выставляется один раз на сессию оболочки,
  а не префиксом каждой команды:

  ```powershell
  $env:PYTHONIOENCODING = 'utf-8'; $env:PYTHONUTF8 = '1'
  ```

- **Точечный прогон integration.** `TEST_DATABASE_URL` обязателен,
  `DATABASE_URL` снимается — и **возвращается** в `finally`, иначе следующая
  команда пойдёт не в ту базу:

  ```powershell

  try {
      if (Test-Path Env:DATABASE_URL) { Remove-Item Env:DATABASE_URL }
      uv run pytest -q tests/integration/<файл>.py
  } finally {
      if ($null -ne $saved) { $env:DATABASE_URL = $saved }
  }
  ```

  Успех читать по числу `passed`, а не по коду возврата
  ([silent-test-runs.md](../../insights/silent-test-runs.md)).
- Стенд `gca_dev` — порт 5459, `psql` из

  **Стенд не чистить и не пересоздавать.**
- **Поиск по репозиторию — `rg`**, счёт — `Measure-Object`. `grep` и `wc` в

- **Код возврата блока читать нельзя, читать надо напечатанные числа.**

```python
def money_group_offsets(colspan: int) -> tuple[int, int]:
    """Смещения якорей `unit_cost` и `total_cost` относительно `column_start`.

    Смещения ВЫВОДЯТСЯ из того же перечня ключей, по которому строятся сами

    return (
        keys.index(f"{JSON_KEY_UNIT_COST}.{JSON_KEY_MATERIALS}"),
        keys.index(f"{JSON_KEY_TOTAL_COST}.{JSON_KEY_MATERIALS}"),
    )
```

## Task 2: Fixture — суффикс в две групповые шапки

Идёт до кода, читающего шапку, и порядок здесь **обязателен**, а не удобен: с
