# План: дорожная карта под гит

**Спека:** `docs/superpowers/specs/2026-09-17-roadmap-under-git-design.md`
**Ветка:** `docs/roadmap-under-git`, от `main` `2135dbe`

## Global Constraints

- **Факт живёт в одном месте** (§9.2). Правило пересмотра карты существует
  ровно в одном экземпляре — в §9.2; в карте остаётся указатель без пересказа.
  **Состояния «правила нет нигде» не существует ни на одном коммите:** снятие
  правила из карты и заведение его в §9.2 — один коммит (задача 2).
- **Форма таблицы §9.2 не меняется:** клетка «Где» — одиночный путь в
  бэктиках у всех строк, включая новую. Маршрут для стража живёт в прозе.
- **Продуктовые пункты карты не меняются.** Горизонты А–Г, восемнадцать
  пунктов, строка «Состояние на 09.09.2026» — не тронуты. Служебный раздел
  меняется ровно одним блоком (правило 3).
- **`/tasks` остаётся в `.gitignore` целиком**, негатор не заводится.
- **Разовый сверщик переезда в репозиторий не попадает** — он живёт в
  `$SCRATCH`, существует до мержа и удаляется последним шагом задачи 5. Это
  действующая практика, записанная в докстринге `check_agents_index.py`:
  «разовый сверщик переезда фичи (`$SCRATCH/verify_move.py`), который
  существует до первой правки и в репозиторий не попадает (§9.1)». **Путь
  `$SCRATCH` фиксирован и инициализируется буквально одной командой** — она в
  «Командах проверки», и её же форма у плана «история наружу». Фиксирован, а не
  `mktemp -d`, потому что digest источника и сам сверщик обязаны дожить от
  задачи 1 до задачи 5.
- **Страж красен до задачи 4.** План не обещает зелёного `check-agents-index`
  ни на одной задаче раньше той, что заводит ревизию: проверка «каждое
  упоминание версии разрешается» краснеет на спеке и плане, называющих
  `v6.23` (`docs/pitfalls/process.md`).
- **Команду, чей код возврата и есть предмет, запускать без конвейера**
  (`docs/pitfalls/runs.md`).
- **Основная оболочка — PowerShell**, Bash приводится альтернативой. В
  PowerShell нет `&&` и `||`: цепочки пишутся `;` либо `if ($?)`. Рекурсивное
  удаление — `Remove-Item -LiteralPath … -Recurse -Force` одной оболочкой, а не
  `rm -rf`.
- **Кириллица:** `read_text(encoding="utf-8")` при чтении; при печати из
  дочернего python — `$env:PYTHONIOENCODING = "utf-8"`, назначенная **в блоке
  инициализации**, а не префиксом команды: POSIX-форма `VAR=value python …` в
  PowerShell не запускается, поэтому все команды плана начинаются прямо с
  `python`. Существующие файлы править точечно, а не перезаписью целиком:
  перезапись переводит файл в LF и делает `git status` грязным при пустом
  `git diff`.
- **Ни один тест не пишет в рабочий репозиторий.** Входы собираются списками
  строк, отсутствие файла подменяется через `monkeypatch` модульной константы
  `ROOT` — образец `backend/tests/unit/test_check_agents_index.py`.
- **В `main` не коммитить; перед каждым пушем — `just ci` целиком** (§9.3):
  фича правит `.py`, освобождение «правки только в `docs/`» к ней не относится.
  Пушей у фичи **два** (задача 5), и `just ci` идёт перед каждым.

## Решения плана, которых нет в спеке

1. **Порядок задач.** Перенос → правило пересмотра (карта и §9.2 одним
   коммитом) → страж → ревизия → финал. Порядок вынужден дважды: `check_18`
   краснеет, пока §9.2 не несёт маршрут (значит задача 2 раньше задачи 3), а
   тест зелени `check_18` требует существующего файла карты (значит задача 1
   раньше задачи 3).
2. **Снятие правила из карты и заведение его в §9.2 — ОДНА задача.** Порознь
   между ними существует коммит, на котором правила нет ни в карте, ни в
   `AGENTS.md`: карта уже ссылается на §9.2, а §9.2 ещё молчит. Обратный
   порядок дал бы окно с двумя экземплярами — тоже нарушение, но менее опасное;
   атомарный коммит не даёт ни того, ни другого.
3. **Оракул переноса и его тесты живут в `$SCRATCH`, а не в `backend/`.**
   Постоянной функции у них нет: после задачи 5 источника не существует, и
   сверять больше нечего. Семь проверок при этом остаются — меняется место, а
   не объём доказательства.
4. **Полный digest источника сохраняется файлом** `$SCRATCH/roadmap-source.sha256`
   на задаче 1 и сверяется на задаче 5 ПЕРЕД удалением. `tasks/ROADMAP.md`
   игнорируется, и его правка между задачами не видна ни `git status`, ни
   ревью; удалять файл, не убедившись, что он тот же самый, — потеря данных.
5. **Каталог `$SCRATCH` удаляется явным шагом, а не «умирает сам».** Обещание
   «живёт до мержа» без шага очистки не исполняется ничем: временный каталог с
   фиксированным именем переживёт и фичу, и следующую. Удаление идёт **после**
   финального прогона, который обязан вернуть 2, и **только** если разрешённый
   путь буквально равен ожидаемому: рекурсивное удаление по неподтверждённой
   переменной здесь опаснее оставленного мусора.
6. **Замеры выбора у scratch-команд считаются по СОБРАННЫМ тестам, а не по коду
   возврата.** Замерено 18.09.2026: `--collect-only` на несуществующем пути
   даёт код **4**, на пустом существующем каталоге — код **5** и «no tests
   collected». Ни то, ни другое не ноль, поэтому «ДО» формулируется как «ноль
   собранных при существующем каталоге», а команда ДО запускается уже после
   `mkdir`.
7. **Имя константы `ROADMAP_REL`** — по образцу `IMPL_REL`, `SCHEMA_REL`,
   `AXES_REL`.
8. **Тесты `check_18` живут в существующем `test_check_agents_index.py`**, не в
   новом файле: `-k check_agents_index` отбирает по имени модуля, и новые
   тесты попадают в тот же выбор, что старые.
9. **Шапку «Когда читать:» карта уже несёт** — задача 1 её не заводит и не
   правит; `check_18` проверяет, что она ровно одна.
10. **Якорь `#92-таксономия-документов`** — правило слага существующих ссылок на
   подразделы (`docs/reference/screens.md#1-договорыобъекты`): нижний регистр,
   точки и слэши удалены, пробелы в дефисы.
11. **Devlog датируется 2026-09-18** — днём реализации, а не днём спеки.

**Interfaces**

  (`C:\Users\zhukov_v\Projects\GCA_MVP\tasks\ROADMAP.md`) — только на чтение; в
  worktree этого файла нет по построению.
- Производит (внутри `$SCRATCH`, ни одно имя не переживает фичу):

```python
LINK_MOVES: tuple[tuple[str, str], ...]   # десять пар «было → стало», данные скрипта
LINK: re.Pattern[str]                     # markdown-ссылка, группа 1 — ЦЕЛЬ

def strip_link_targets(text: str) -> str
def digest(text: str) -> str              # sha256 текста с LF-нормализацией
def link_targets(text: str) -> list[str]
def verify(source_text: str, moved_text: str, docs_root: Path) -> tuple[bool, list[str]]
def main(argv: list[str]) -> int          # 0 — сошлось, 1 — расхождение, 2 — нет источника
```

**Утверждения**
- у перенесённой карты **ноль** целей, начинающихся с `../docs/`, и десять
  локальных markdown-целей всего;
- список пар «было → стало» совпадает с `LINK_MOVES` поимённо И по кратности:
  `../docs/TECH_DEBT.md` → `TECH_DEBT.md` четырежды,
  `../docs/proposals/2026-08-18-amendments-delta-model.md` →
  `proposals/2026-08-18-amendments-delta-model.md` дважды, и по одному разу для
  четырёх остальных целей;
- каждая из десяти новых целей разрешается в существующий файл относительно
  `docs/`;
- `digest(strip_link_targets(источник))` равен
  `digest(strip_link_targets(перенесённая))` — кроме целей ссылок не изменился
  ни один байт;
- **негативный: изменённый байт ВНЕ целей ссылок краснит оракул**, даже когда
  все десять пар на месте;
- **негативный: потерянная ссылка краснит оракул, хотя остаток сходится** —
  вход, на котором одна сумма без перечня целей молчала бы;
- **негативный: лишняя ссылка краснит оракул при сошедшемся остатке** — вторая
  половина того же: сходимость не доказывает разбиения, и обе стороны
  предъявляются раздельно;
- **негативный: замена не по карте** (`../docs/TECH_DEBT.md` → `../TECH_DEBT.md`)
  краснит оракул: такой пары нет в `LINK_MOVES`;
- **негативный: новая цель не разрешается** в существующий файл — краснит,
  даже если пара из `LINK_MOVES`;
- **отсутствие файла-источника даёт код 2 и названную причину**, а не молчаливый
  ноль;
- карта переносится копированием БАЙТОВ, а не перезаписью из Python;
- **полный sha256 источника записан в `$SCRATCH/roadmap-source.sha256`** — на
  17.09.2026 он равен
  `7ff5e21b944f4aa40f5a9b67fd30550c48f684ebd350af726b89f6388a17dac5`, и задача
  фиксирует ФАКТИЧЕСКИЙ на момент копирования, а не переписывает это число;
- новый файл отслеживается (`git ls-files docs/product-roadmap.md` печатает
  путь), а `/tasks` остаётся игнорируемым целиком: `git check-ignore -q tasks`
  возвращает 0 и `git ls-files tasks/` пуст — негатор не заведён.

### Task 5: Финал — два круга проверки, артефакт, удаление источника, devlog

Задача идёт **пятью шагами в этом порядке**, и порядок несущий: факт нельзя
записать в devlog раньше, чем он случился, а случиться он может только после
того, как файл виден в удалённой ветке.

1. `just ci` целиком → **первый push**.
2. Подтвердить файл в удалённой ветке:
   `git ls-tree origin/docs/roadmap-under-git -- docs/product-roadmap.md`.
3. Перепубликовать артефакт; сверить sha256 источника и удалить его.
4. Записать свершившиеся факты в devlog, закоммитить.
5. `just ci` целиком → **второй push**.
6. Прогнать сверщик последний раз (обязан вернуть **2** — источника больше
   нет), затем удалить каталог `$SCRATCH` одной оболочкой — PowerShell:

   ```powershell
   $resolvedScratch = (Resolve-Path -LiteralPath $SCRATCH).Path
   if ($resolvedScratch -ne (Join-Path $env:TEMP "gca-roadmap-under-git")) {
       throw "путь скретча не тот, удаление не выполняется: $resolvedScratch"
   }
   Remove-Item -LiteralPath $resolvedScratch -Recurse -Force
   if (Test-Path -LiteralPath $resolvedScratch) { throw "scratch-каталог не удалён" }
   ```

   Путь **разрешается и сравнивается с ожидаемым буквально** до удаления:
   рекурсивное удаление по неподтверждённой переменной опаснее оставленного
   мусора. Финальная проверка **положительная** — отсутствие каталога
   завершает блок кодом 0, а не кодом 1: последняя команда фичи не должна
   выглядеть провалом.

**Files**
- Create: `docs/devlog/2026-09-18-roadmap-under-git.md`
- Delete: `tasks/ROADMAP.md` — **в основном дереве пользователя**, вне гита.
- Read: `$SCRATCH/roadmap-source.sha256` (задача 1).
- Delete: `$SCRATCH` целиком — шаг 6, после финального прогона сверщика.

**Interfaces**
- Потребляет внешний вход, которого нет в репозитории: **артефакт
  `https://claude.ai/code/artifact/7bd9313a-ee8b-4a41-ba47-81f083d800cf`**.
- **Исполнитель публикации называется здесь, а не подразумевается:**
  перепубликацию делает агент инструментом `Artifact` (действие `publish` с
  `url` этого артефакта) **после явного разрешения пользователя** — правка
  внешнего носителя необратима и наружу. Если пользователь публикует сам, шаг 4
  ждёт его подтверждения: факт пишется в devlog только после ответа, а не
  после отправки просьбы.
- Производит: devlog фичи (§9.1 шаг 5).

**Утверждения**
- `just ci` целиком зелёный **перед каждым** из двух пушей;
- новый файл существует в удалённой ветке — подтверждено `git ls-tree`, а не
  предположено по успеху `git push`;
- **перед удалением источника его sha256 сверен с сохранённым на задаче 1**:
  файл игнорируется, его правка между задачами не видна ни `git status`, ни
  ревью, и удаление разошедшегося файла — потеря данных. **При расхождении
  задача останавливается**, перенос повторяется с нового источника, и только
  потом удаление;

## Команды проверки

- **По задаче:** указаны в самой задаче.
- **По фиче целиком:** `just ci` (§9.3), дважды — перед каждым пушем. Экранов
  фича не трогает, прогон на стенде не нужен; Postgres нужен только цепочке
  `just ci`, самой фиче — нет.
- **`$SCRATCH` назначается первой командой задачи 1**, иначе остальные команды
  плана не запускаются буквально. Основная оболочка проекта — PowerShell;
  форма взята у плана «справочник наружу»:

  ```powershell
  # Назначаются ОБЕ величины: $SCRATCH раскрывает сам PowerShell,
  # $env:SCRATCH читают дочерние процессы — это разные переменные.
  $SCRATCH = Join-Path $env:TEMP "gca-roadmap-under-git"
  $env:SCRATCH = $SCRATCH
  $env:PYTHONIOENCODING = "utf-8"   # кириллица в выводе дочернего python
  $repoRoot = git rev-parse --show-toplevel
  New-Item -ItemType Directory -Force $SCRATCH
  python -c "import os,sys; r=os.path.realpath(sys.argv[1]); s=os.path.realpath(os.environ['SCRATCH']); raise SystemExit(os.path.commonpath([r,s]) == r)" $repoRoot
  ```

  ```bash
  # Bash, если задача исполняется из него
  export SCRATCH="${TEMP:-/tmp}/gca-roadmap-under-git"
  export PYTHONIOENCODING=utf-8
  mkdir -p "$SCRATCH"
  ```

  Путь фиксирован, а не `mktemp -d`: `verify_roadmap_move.py` и
  `roadmap-source.sha256` создаются задачей 1 и читаются задачей 5, а свежий
  каталог на каждый запуск потерял бы их между задачами.

  **Последняя строка PowerShell-блока — предъявление, а не украшение:** код
  **0** означает, что общий путь скретча и корня репозитория короче корня, то
  есть скретч лежит СНАРУЖИ дерева и файлы оттуда закоммитить нельзя в
  принципе. Требование проверяется структурно, а не по факту чистого
  `git status`.

  Оба блока — инициализация и очистка шага 6 задачи 5 — **прогнаны на этой
  машине 18.09.2026** на пробном каталоге: `init exit: 0`, разрешённый путь
  совпал с `Join-Path $env:TEMP …` буквально (коротких имён `8.3` в пути не
  оказалось), `Remove-Item` сработал, положительная финальная проверка дала 0.
  То есть команды плана не только записаны, но и исполнимы в заявленной форме.
- **Оракул переноса** живёт в `$SCRATCH` и в репозиторий не попадает;
  воспроизводимость доказательства после мержа обеспечивает devlog, называющий
  его вывод **перечнями**, а не кодом возврата. Каталог удаляется шагом 6
  задачи 5 — обещание «не переживает фичу» исполняется командой, а не
  формулировкой.
