# Стартовый дашборд — Implementation Plan

> **Для исполнителей:** задачи идут по порядку, каждая заканчивается коммитом.
> Шаги помечены чекбоксами (`- [ ]`). **Все коммиты делает оркестратор.**

**Goal:** маршрут `/` показывает дашборд базы вместо заглушки фазы 1: денежные итоги с
охватом, рейтинг объектов, диаграмма ₽/м², и отдельный таб «На что обратить внимание» для
`admin`.

**Architecture:** два эндпоинта в существующем `routers/analytics.py`, расчёт — новый
`crud/dashboard.py` поверх `v_category_totals` и `money/vat.py`. Ничего нового в схеме:
миграций **нет**. Фронтенд — новая страница на месте `Home.tsx`, табы на существующем
shadcn `tabs.tsx`.

**Два слоя охвата — несущая конструкция, а не деталь.** Договорный охват защищает деньги,
объектный — рейтинг и диаграмму; у каждого своя строгая лестница причин (спека §2.5).
Больше всего кругов правок соберёт именно она, если исполнитель сочтёт её одним фильтром.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.x sync ORM, psycopg3, PostgreSQL 16;
React + TS, Vite, shadcn/ui, TanStack Query, vitest + MSW.

**Спека:** [2026-08-16-home-dashboard-design.md](../specs/2026-08-16-home-dashboard-design.md)
(гейт 2 закрыт 2026-08-16). **Макет гейта 1:**
[2026-08-14-home-dashboard-mockup.html](../specs/2026-08-14-home-dashboard-mockup.html).

## Global Constraints

Требования этого раздела входят в **каждую** задачу неявно.

**Процесс**

- В `main` не коммитить. Ветка одна — `feat/home-dashboard`.
- **Перед пушем — `just ci`**, шагами и в форме CI. Правки только в `docs/` от него
  освобождены (`AGENTS.md` §9.3).
- Коммиты делает **оркестратор**, не исполнитель задачи.
- Субагентам **запрещено печатать кириллицу в терминал**: вердикты ASCII, русский текст —
  в файл отчёта, `rg -c` вместо `rg`, `Read` вместо `Get-Content`.

**Оболочка — PowerShell 5.1, не bash**

- После **каждой** нативной команды внутри `try` обязательно
  `if ($LASTEXITCODE -ne 0) { throw "<что> failed: $LASTEXITCODE" }`.
- **Вердикт читается по напечатанным числам, а не по коду возврата**; код возврата после
  конвейера (`| tail`, `| Select-Object`) принадлежит последней команде конвейера, а не
  прогону ([silent-test-runs](../../insights/silent-test-runs.md)).
- **Кириллица в SQL, переданном через `psql -c`, ломается** (`invalid byte sequence for
  encoding "UTF8"`) — замерено этой фичей на гейте 2. Метки в запросах только ASCII.
- Не работают: `env -u`, `VAR=value` префикс, `&&`, `||`, `grep`, `wc`, heredoc.
- Разовые скрипты — в `$env:TEMP\gca-dashboard`.
- Один раз на сессию: `$env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'`.
- Команды бэкенда — из `backend/` через `uv run`; `vitest` — **только из `frontend/`**.

**Домен**

- **Деньги:** `Numeric` в БД ↔ `Decimal` в Python ↔ **строки в JSON**. `decimal_json`
  обязателен для **любого** ответа, несущего `Decimal`.
- **Ставка показа — только `money.vat.effective_display_rate`.** Своей формулы не заводить
  (спека §2.3): второе представление одного понятия разъедется при первой правке.
- **Пересчёт — построчно, ДО накопления** (спека §2.6): `restate_gross` на каждую строку
  `v_category_totals`, и только результат складывается. На одном предложении ошибка порядка
  **невидима**.
- **Матрица, отчёты и оба паспорта не меняются.** Их тесты — контроль неизменности: если
  задача роняет хоть один, она задела не то.

**Проверки**

- Тест, доказывающий защиту, обязан быть проверен **снятием защиты**
  ([verifying-guards](../../insights/verifying-guards.md)): снять — увидеть красный —
  вернуть из побайтовой копии, не через `git checkout --`. Снятия — **порознь**, список у
  каждой задачи.
- **У теста охвата обязателен вход, разводящий две лестницы.** Тест, где объект исключён
  отовсюду сразу, пройдёт и на реализации с одним общим фильтром — то есть докажет не то.
- На финале строить соответствие «требование DoD спеки → тест» списком
  ([replaying-new-rules](../../insights/replaying-new-rules.md)).

## Task 4: Эндпоинт «На что обратить внимание»

**Цель:** пять строк решения 12, только для `admin`.

**Ответ — ПЯТЬ СЧЁТЧИКОВ, без списков затронутых сущностей.** Списки нужны были бы
действиям, а действия отложены (Task 6, отступление от макета). Возвращать их «на будущее»
нельзя: неиспользуемое поле ответа никем не проверяется и тихо разъезжается с расчётом.

- [ ] **Шаг 1: тесты** — `GET /api/v1/analytics/dashboard/attention`: `admin` получает
      пять строк; **`member` получает 403**. Каждая строка проверяется на своём входе:
      смета без ставки; объект с несколькими договорами; договор без сметы; объект без
      площади; импорт с ошибкой за 30 дней (и **не** попадает импорт старше 30 дней).

      **Строка «без ставки» считается ТОЙ ЖЕ семантикой, что договорная лестница —
      `effective_display_rate`, а не наброском решения 12** (спека §2.3а). Макет пишет
      `COALESCE(vat_rate_base_override, vat_rate) IS NULL`, то есть смотрит только на
      **базу** и не знает правила единогласия.

      **Входы — две РЕАЛЬНЫЕ причины `effective_display_rate == None`**, обе достижимы
      штатными средствами:

      | Вход | Наивный запрос | Деньги (§2.3) | Что увидит человек |
      |---|---|---|---|
      | предложения `20 %` и `22 %` — разногласие | молчит | исключён | договор пропал из итогов **без диагностики** |
      | предложения `20 %` и `NULL` — часть неизвестна | молчит | исключён | то же |
      | только `base_override` | молчит | учтён | **зелёный контроль**: не диагностика и не исключение |

      **Вход «только `vat_rate_target`» использовать НЕЛЬЗЯ как основной:** штатный сервис
      такого состояния не создаёт — при `target != NULL`, пустом `base_override` и хоть
      одной неизвестной ставке предложения `services/estimate_vat.py` отвечает
      `unknown_base` (422). Тест на нём пришлось бы городить в обход сервиса, и он
      доказывал бы недостижимое состояние.

      Контроль `base_override` остаётся **зелёным** во всех прогонах: наивный запрос его
      тоже распознаёт, поэтому уронить его возвратом к наброску невозможно — он стережёт
      не набросок, а то, что диагностика не выдумывает проблему на ровном месте.

- [ ] **Шаг 3: реализация** — пять счётчиков в `crud/dashboard.py` плюс `require_admin` в
