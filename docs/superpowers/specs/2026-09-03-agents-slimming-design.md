# `AGENTS.md`: указатель §12 и преамбула — сжать без потери фактов

**Гейт 1 пройден 03.09.2026** в диалоге. Спека **тонкая** по §9.1: дизайн
зафиксирован и проверен фактами на разведке, здесь только источник и дельта.

**Класс правки:** документация с проверочным инструментарием (§9.1) — вводится
один read-only скрипт, стерегущий DoD. Плана нет по тому же исключению;
`just ci` обязателен.

---

## 1. Проблема с замерами

`AGENTS.md` — **1 214 строк, 128 052 символа, ~42 700 токенов**, и `CLAUDE.md`
предписывает читать его в начале каждой сессии. Ядро, нужное в любой сессии
(§1–3, §8, §9, §10), — около 7 600 токенов, то есть **18 % файла**.

Две крупнейшие статьи не несут своего содержания:

| Что | Символов | Токенов | Чем занято |
|---|---|---|---|
| Указатель §12 | 18 236 | ~6 080 | 16 строк, каждая пересказывает свой инсайт; самая длинная — **3 401 символ** |
| Преамбула | 19 232 | ~6 430 | 16 врезок ревизий v6.1–v6.16 |

**Указатель §12 противоречит собственной вводной.** §12 объявляет разделение
труда прямо: «в **файле** указано, чем именно выстрадано и чего правило не
ловит». Строка указателя обязана отправлять к файлу, а не заменять его. Сейчас
она весит 6–37 % своего файла и пересказывает его целиком — то самое
дублирование, которое §9.2 запрещает («факт живёт в одном месте»).

**Проверено, а не объявлено.** Механическая сверка (числа и идентификаторы в
бэктиках из каждой строки указателя против текста связанного инсайта) дала три
расхождения на 16 строк, из них **одно настоящее**: строка про
`verifying-guards` сообщает «четырнадцатый слой заведён внешним ревью **PR
#34**», и этой атрибуции в самом инсайте нет. Два других — переформулировки
(`exit 0` против `exit code 0`, `just ci | tail` против `tail -40`).

**Про преамбулу первоначальная гипотеза была неверна.** Я считал её мёртвой
историей, которую не читают. Замер: на конкретные ревизии **66 ссылок** в
`docs/`, и шесть номеров цитируются внутри самого `AGENTS.md` вне преамбулы
(`v6.7` — 14 раз, `v6.10` — 10, `v6.5` — 9). Выносить её целиком значит лишить
эти ссылки локальности.

**Инвариант правят только 4 ревизии из 16** — `v6.15`, `v6.12`, `v6.10`,
`v6.8`. Остальные двенадцать записывают пополнение §11/§12 и решения по
экранам, и почти все ссылаются на спеку или devlog, где деталь и живёт.

## 2. Решение

### 2.1. Указатель §12 — одно предложение на инсайт

Строка = название + одна фраза «когда пригодится» + ссылка. Деталь живёт в
файле, как §12 и обещает.

**Перед обрезкой** факт про `PR #34` переносится в
`docs/insights/verifying-guards.md`, к описанию четырнадцатого слоя. Иначе
обрезка теряет атрибуцию — единственную, что живёт только в указателе.

### 2.2. Преамбула — инвариантные ревизии целиком, остальные строкой

- **Полным текстом остаются** `v6.16` (текущая) и четыре, правящие инвариант:
  `v6.15`, `v6.12`, `v6.10`, `v6.8`. Основание: §9.2 делает этот документ
  источником истины по инвариантам, а v6.15 и v6.16 заведены ровно потому, что
  правка инварианта обязана быть видна в истории источника. Увозить эту историю
  в соседний файл значило бы повторить тот класс ошибки.
- **Остальные 11** — одной строкой: версия, дата, что правила (§11 / §12 /
  экраны), ссылка на спеку или devlog. Полный текст переезжает в
  `docs/AGENTS-revisions.md`.
- Ссылки вида «ревизия v6.7» остаются рабочими: строка с номером остаётся в
  преамбуле и ведёт в `AGENTS-revisions.md`.

### 2.3. Проверка DoD скриптом

`backend/scripts/check_insight_index.py` — read-only: для каждой строки
указателя §12 сверяет числа и идентификаторы с текстом связанного инсайта и
падает, если что-то живёт только в указателе. Это ровно та проверка, которой
получено «одно настоящее расхождение» выше, и после обрезки она обязана быть
зелёной.

Скрипт объявлен здесь, ДО гейта 2, а не добавлен по ходу — прошлая фича
показала, чем стоит обратное.

## 3. Отвергнутые альтернативы

1. **Вынести все 16 врезок, оставив в преамбуле только строки.** Экономия
   больше (~5 000 токенов против ~3 200), но история правки ИНВАРИАНТОВ уезжает
   из документа, который объявляет себя их источником, — класс ошибки v6.15.
2. **Вынести §11 и §12 в `docs/reference/` целиком.** Отдельная фича, и
   предложение `2026-09-02-pitfalls-as-mechanisms.md` требует иного порядка:
   сперва разобрать §11 по пунктам (механизм / устарел / проза), потом выносить.
   Вынести раньше значит сделать правила невидимыми, оставив их ненадёжными.
3. **Оставить в указателе два-три предложения на инсайт.** Экономия вдвое
   меньше (~3 500 токенов), а критерий «сколько предложений достаточно» —
   резиновый, и указатель отрастёт снова.
4. **Сжать §11.** Замер против: 46 пунктов §11 суммарно 6 301 символ при медиане
   78 — обрезать там почти нечего, вес раздела в прозе между пунктами.

## 4. Что меняется

- `AGENTS.md` — указатель §12 (16 строк) и преамбула (11 врезок из 16).
- `docs/AGENTS-revisions.md` — новый файл, полный текст 11 врезок.
- `docs/insights/verifying-guards.md` — принимает атрибуцию `PR #34`.
- `backend/scripts/check_insight_index.py` — новый read-only скрипт (§2.3).
- **Ни одно правило не меняется.** Ни §11, ни §12 по составу не трогаются,
  инварианты не пересматриваются. Ревизия `AGENTS.md` поэтому **не заводится**:
  правится форма преамбулы и указателя, а не то, что документ утверждает.

## 5. DoD

1. `AGENTS.md` — не больше **105 000 символов** (сейчас 128 052);
2. `check_insight_index.py` зелёный: ни одного факта, живущего только в
   указателе;
3. все 16 ссылок указателя §12 ведут в существующие файлы;
4. ссылки вида `v6.N` из `docs/` и из тела `AGENTS.md` разрешаются — номер
   находится либо в преамбуле, либо в `AGENTS-revisions.md`;
5. `just ci` зелёный (правка с инструментарием, §9.1).

Проверяется командами:

```bash
wc -c AGENTS.md                                    # <= 105000
uv run python scripts/check_insight_index.py       # из backend/, exit 0
grep -c '^- \*\*\[' AGENTS.md                      # 16 строк указателя
grep -ohE 'v6\.[0-9]+' AGENTS.md docs/**/*.md | sort -u | wc -l
```
