# Parse cost tracking — design

**Date:** 2026-07-16
**Status:** approved (design), pending implementation plan
**Approach:** A — накопительные колонки на `documents` (отвергнут B — отдельная таблица `parse_runs`; YAGNI до появления реальной потребности в аудите вызовов).

## Цель

Показывать пользователю **реальную стоимость ИИ-разбора каждого документа** в $ —
в карточке документа и сразу после загрузки. Стоимость **накапливается** по всем
разборам документа (upload + reparse + deskew-reparse), потому что каждый вызов
OpenRouter стоит денег.

Источник цифры — **реальная стоимость от OpenRouter** (`usage.cost` в ответе при
`usage: {include: true}`), а не расчёт по токенам × прайс-лист. Причины: точнее,
включает стоимость OCR-плагина (`mistral-ocr` тарифицируется постранично), не
требует держать и обновлять прайс модели вручную.

## Инвариант (ядро фичи)

> Если OpenRouter вернул HTTP 200 — деньги потрачены, и `parse_cost_usd` должен
> быть учтён, **независимо** от того, сохранилась ли СФ.

Это главное, что легко потерять: самые обидные траты — это как раз неудачные
разборы (обрезка по токенам, битый JSON, провал сверки итогов), где СФ не
сохранилась, но вызов был платным (и порой дорогим).

## 1. Схема БД (`documents`)

Две накопительные колонки:

| Колонка | Тип | Ограничения | Смысл |
|---|---|---|---|
| `parse_cost_usd` | `Numeric(10, 6)` | `NOT NULL`, `server_default="0"` | Суммарная стоимость всех разборов документа, $. 6 знаков — доли цента. Потолок $9999.99 на документ, с запасом. |
| `parse_count` | `Integer` | `NOT NULL`, `server_default="0"` | Число платных вызовов OpenRouter (для честности накопления и подписи «N разборов»). |

`server_default="0"` гарантирует: свежесозданный документ после `db.refresh(doc)`
(в `create_document`) имеет `Decimal("0")`, а не `None` — значит `+=` работает без
защиты от `None`.

Миграция: `alembic revision --autogenerate` → применение `just db-migrate`. Файл
миграции в `backend/alembic/versions/` руками **не** правим (правило AGENTS.md).

## 2. Захват стоимости — `pdf_parser.parse_invoice_pdf`

**Структурный инвариант вместо перечисления веток.** После `data =
response.json()` в коде шесть платных выходов; перечислять их в коде хрупко
(следующая правка добавит `return` и забудет ключ). Вместо этого:

```python
async def parse_invoice_pdf(...):
    cost: Decimal | None = None          # объявляем ДО try
    try:
        ...
        payload = {
            ...,
            "usage": {"include": True},  # просим OpenRouter вернуть реальную стоимость
        }
        ...
        data = response.json()
        # СРАЗУ после парсинга ответа, ДО всех guard'ов:
        cost = Decimal(str(data.get("usage", {}).get("cost") or 0))
        logger.info(f"[doc={document_id}] Стоимость вызова: ${cost}")
        ...
        # каждый return после этой точки — через _with_cost(...)
        return _with_cost({...}, cost)
    except httpx.TimeoutException:
        return {"error": "..."}          # до платного ответа — cost остаётся None
    except Exception:
        return _with_cost({"error": "..."}, cost)  # cost может быть None
```

> **Амендмент (пост-ревью Codex, коммит `248144d`):** `cost` теперь инициализируется
> `Decimal(0)` **сразу после проверки `status_code == 200`, до `response.json()`**
> (значение уточняется из `usage.cost` после парсинга). Причина — см. амендмент к
> «неустранимому случаю» ниже: он оказался устраним. Так HTTP 200 с непарсящимся
> телом тоже биллится, а инвариант «был 200 → есть `parse_cost_usd`» стал абсолютным.

Хелпер (модульного уровня, с докстрингом):

```python
def _with_cost(result: dict, cost: Decimal | None) -> dict:
    """Кладёт parse_cost_usd в результат, только если вызов OpenRouter состоялся
    (cost известен). Так правило «был 200 → есть parse_cost_usd» не зависит от
    числа веток выхода из parse_invoice_pdf."""
    if cost is not None:
        result["parse_cost_usd"] = cost
    return result
```

- **Все** post-`response.json()` выходы оборачиваются `_with_cost(..., cost)`:
  `finish_reason == "length"`, `JSONDecodeError`, `doc_type != "invoice"`,
  провал `_reconcile_totals`, успех.
- `except Exception` тоже через `_with_cost` — `cost` может быть `None` (падение
  до `response.json()`), хелпер тогда просто не добавит ключ.
- Не-200 ([pdf_parser.py:190](../../../backend/pdf_parser.py#L190)) и `TimeoutException`
  ([:361](../../../backend/pdf_parser.py#L361)) — до платного ответа, ключ не
  добавляется.
- `usage.cost` отсутствует / `None` → `cost = Decimal("0")` (через `or 0`), ключ
  всё равно кладётся (вызов был платным), в лог — предупреждение. Падения нет.

## 3. Накопление — `routers/invoices.py`

В `upload_pdf` **и** `_reparse_from_s3` — сразу после
`result = await parse_invoice_pdf(...)` и **до** ветвления `if result.get("error")`:

```python
if "parse_cost_usd" in result:          # был платный 200-ответ
    doc.parse_cost_usd += result["parse_cost_usd"]   # Decimal += Decimal
    doc.parse_count += 1
```

> **Амендмент (пост-ревью Codex, `248144d`):** накопление переведено на атомарный
> SQL-инкремент — `doc.parse_cost_usd = Document.parse_cost_usd + result[...]` —
> вместо read-modify-write, см. последний пункт списка.

- Размещение до `if result.get("error")` критично: иначе неудачные (но платные)
  разборы — unknown, обрезка, битый JSON, провал сверки — не забиллятся.
- Коммит уже есть в обеих ветках (там, где ставится `doc.status`) — отдельный
  коммит не нужен.
- `deskew_reparse_document` идёт через `_reparse_from_s3`, поэтому третий эндпоинт
  покрывается автоматически — отдельной правки не требует.
- ~~`+=` без защиты от гонок: для workflow проекта (verified-check, один активный
  пользователь) конкурентные reparse одного документа не рассматриваем — YAGNI.~~
  **Амендмент (пост-ревью Codex, `248144d`):** YAGNI-довод снят — накопление
  переведено на атомарный SQL-инкремент (`x = x + :v` на flush), чтобы параллельные
  reparse одного документа не теряли обновления. Фикс дешёвый, `db.refresh` уже был.

## 5. Фронтенд

- В TS-тип документа — `parse_cost_usd: number`, `parse_count: number`.
- Формат-хелпер `formatUsd(value: number): string` (дефолт — фиксируем):
  - `value >= 0.01` → два знака (`"$0.06"`).
  - `0 < value < 0.01` → до 4 знаков с обрезкой хвостовых нулей (`"$0.0021"`).
    Показываем реальную цифру, а не флаг `<$0.01`: иначе все дешёвые разборы
    (типичный `mistral-ocr` — $0.002–0.01) выглядят одинаково и теряют смысл.
  - `value == 0` → `"$0.00"` (cost не пришёл / бесплатный вызов).
- Подпись в карточке/детали документа — приглушённая: «ИИ-разбор: $0.0021»; при
  `parse_count > 1` — «$0.06 · 3 разбора».
- Валюта — **USD** без конвертации в ₽: это инфра-затраты, а не доменные деньги;
  фиксированный курс из настроек — ложная точность и лишняя настройка.

## 6. Тесты

- Добавить `usage.cost` во **все** фикстуры `tests/fixtures/openrouter/*.json`
  (`happy_path`, `incomplete_totals`, `invalid_json`, `truncated_length`,
  `unparseable`), не только в happy path.
- Для кейса «cost отсутствует → `Decimal("0")`» завести отдельную фикстуру
  `happy_path_no_cost.json` (копия `happy_path` без `usage.cost`). Иначе после
  предыдущего пункта сценария без cost не останется, и тест не на чем гонять
  (мок в conftest отдаёт фикстуру как есть через `_load()`). Отдельная фикстура
  чище программной модификации словаря и в духе существующей структуры сценариев.
- Unit (`pdf_parser`): parse возвращает `parse_cost_usd` из мока (happy_path);
  на `happy_path_no_cost` → `Decimal("0")`, ключ присутствует.
- Integration (happy path): upload → `parse_cost_usd > 0`, `parse_count == 1`;
  reparse → сумма растёт, `parse_count == 2`.
- **Integration (ключевой инвариант):** upload со сценарием `incomplete_totals`
  → документ `status == "error"`, но `parse_cost_usd > 0` и `parse_count == 1`.
  Прямая проверка «биллим даже провал»; моки уже готовы.
- Докстринги на всех новых/изменённых функциях (правило проекта, ≥80%).

## 7. Открытые пункты для верификации при внедрении

- **Включает ли `usage.cost` стоимость OCR-плагина** — не принимать на веру.
  Первым реальным вызовом сверить строку лога `Стоимость вызова: $X` с
  дашбордом OpenRouter (одна проверка вручную).
- **~~Единственный небиллимый платный случай, неустраним по построению~~ (устранён
  пост-ревью Codex, `248144d`):** ранее 200 с непарсящимся телом → `response.json()`
  бросал исключение **до** присвоения `cost` → `except Exception` с `cost is None` →
  вызов не биллился, и «неустранимость» объяснялась тем, что цифра живёт внутри того
  самого JSON. Формулировка оказалась неверной: биллить нужно **факт** вызова, а не
  его стоимость. Теперь `cost = Decimal(0)` присваивается сразу после
  `status_code == 200`, до `response.json()`; при битом теле стоимость остаётся 0, но
  `parse_count` растёт. Инвариант «был 200 → есть `parse_cost_usd`» выполняется строго.
  Регресс-тест — `test_200_invalid_json_is_billed`.

## Заметки (проверено при ревью дизайна)

- Дедуп по `file_hash`: колонка в `documents` есть, но в коде **не используется** —
  скрытой ветки «вернули существующий документ без платного вызова» сейчас нет.
  Когда дедуп появится, он естественно не будет инкрементить счётчик.
- `create_document` делает `db.refresh(doc)` → `parse_cost_usd` после создания —
  `Decimal("0")`, не `None`.
