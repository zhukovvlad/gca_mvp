# Зона как предпочтение подбора, а не фильтр — спека (гейт 2)

**Дизайн:** [`2026-11-20-zone-as-preference.md`](../design/2026-11-20-zone-as-preference.md)
(редакция 3; гейт 1 принят Codex 20.11.2026 на `15a27ef`, пользователь —
«переходим к спеке»), макет и замер рядом с ним. Проблема, замер, варианты и
отвергнутое — там; здесь — контракт, правила и проверки.

**Редакция 1, 21.11.2026.**

**Редакция 2, 21.11.2026** — по ревью Codex к `a37ae0e` (P2): прогон
«до/после» нормализует `work_rung` перед сравнением — новое поле
`zone_scope` проверяется отдельно, иначе любая прежняя строка выглядела бы
изменившейся (§7 п. 13).

**Редакция 3, 21.11.2026** — по реализации, задача 1: отказ архивной семье
на маршруте флажка — 409, а не 422: код `update_archived` уже отображается в
409 у `PATCH` семьи (`routers/semantic.py`, `_STATUS_CONFLICT`), один код —
один статус (§4 п. 2, §7 п. 7).

Спека меняет правила, закреплённые раньше, и в части зоны заменяет их:
- [спека лестницы аналогов](2026-11-07-analog-ladder-design.md) §2.8 (ступень
  берёт строки только зоны строки КП), §2.10 (состояние `no_zone` и причина
  `no_zone_match` у всех семей);
- [спека справочных аналогов](2026-11-15-reference-analogs-design.md) §2.5
  (блок А «та же работа в другой зоне» у любой строки с `no_zone_match`);
- [спека упрощения каталога](2026-11-10-catalog-simplify-design.md) §2.8
  (справка «по частям» — только зона строки КП).

Остальное в этих спеках действует без изменений.

## 1. Подбор работы (`services/analog_ladder.py`)

1. **Область подбора** (`ZoneScope = Literal["own", "other", "any"]`) — из
   каких зон берутся кандидаты:
   - `own` — зона строки КП;
   - `other` — все зоны, кроме зоны строки КП, **и** строки договоров без
     зоны (п. 3), одной выборкой;
   - `any` — все строки истории семьи, с зоной и без.
2. **Порядок.** Семья строки без флажка «зона обязательна» (§4):
   - у строки КП есть зона — ступени 1–4 в области `own`; ни одна ничего не
     нашла — ступени 1–4 в области `other`. Своя зона на любой ступени
     побеждает: «`own`, ступень 4» раньше «`other`, ступень 1»;
   - у строки КП нет зоны (и она дошла до подбора, §2) — ступени 1–4 в
     области `any`.

   Семья с флажком — как сегодня: только `own`, строки договоров без зоны не
   кандидаты, строка КП без зоны до подбора не доходит.

   Внутри области ступень, класс, выбросы, остаток, «самая низкая», «самая
   свежая», «с этим подрядчиком», порядок справки и близость места — как
   сегодня, без изменений правил: меняется только набор кандидатов.
3. **Строки договоров без зоны** (`WorkHistoryLine.zone is None`) — кандидаты
   только в областях `other` и `any` и только у семей без флажка. В область
   `own` не входят никогда.
4. **Выпавшие по базе НДС** (`vat_dropped`) считаются в той же области, что
   ступень; у строки без ступени — в первой паре «область, ступень», где они
   нашлись бы, в том же порядке, что подбор.
5. **Причина без ступени.** У семьи без флажка `no_zone_match` не выдаётся:
   если ни в одной области ничего нет, это `no_family`, `path_conflict`,
   `composite` или `no_params` (правило §2.10 лестницы, по кандидатам всех
   зон). У семьи с флажком — как сегодня, включая `no_zone_match`.
6. **Справка «по частям»** (`parts_reference`): у каждой части — кандидаты в
   области `own`; у части без кандидатов в `own` — в области `other`; у
   строки КП без зоны — `any`; у семьи с флажком — только `own`. Часть несёт
   свою область (§3).
7. **Справка «та же работа в другой зоне»** (`zone_groups`, блок А) и подпись
   `other_zones` — без изменений кода; приходят только у семей с флажком,
   потому что только у них бывает `no_zone_match`.

Имена (интерфейс, гейт 3 их закрепит):
- `KpWork.zone_required: bool = False`;
- `WorkHistory(lines, families, contracts, factors=…, zone_required:
  frozenset[int] = frozenset())` — семьи с флажком; пул такой семьи не
  берёт строки договоров без зоны;
- `WorkLadder.zone_scope: ZoneScope | None` — `None` ⇔ `rung_no is None`;
- `Analog.zone: Zone | None` — зона строки договора;
- `PartReference.zone_scope: ZoneScope | None` — `None` у части без
  кандидатов.

## 2. Строка КП (`services/our_price.py`)

1. `KpLine.zone_required: bool = False` — флажок семьи варианта строки.
2. **Состояние `no_zone`** — только `line.zone is None and
   line.zone_required` (на том же месте проверок, что сегодня). Строка без
   зоны у семьи без флажка идёт в подбор с областью `any`.
3. **Приоритет у строки без зоны** — правило `in_progress` не меняется
   (`crud/our_price_load.py`: живое задание зоны цепочки и захват не
   остановлен — «разбирает», пауза провайдера по времени `in_progress` не
   снимает). Поэтому:
   - захват остановлен (`claim_paused`) при живом задании — не
     `in_progress`; семья без флажка — подбор `any`, с флажком — `no_zone`
     и «ждёт решения», как сегодня;
   - живое задание, в том числе в паузу провайдера, — `in_progress`;
   - иначе — подбор `any` (без флажка) или `no_zone` (с флажком).
4. **«Ждёт решения администратора»** (`_waiting_admin`, счётчик плашки) —
   код не меняется: он считает строки в состоянии `no_zone`, а их теперь
   дают только семьи с флажком.
5. `_line_ladder` (панель, справочные блоки) — то же условие, что п. 2.

## 3. Загрузка и ответ API

1. **`load_work_history`** больше не фильтрует `SectionChain.zone IS NOT
   NULL`: строки договоров с цепочкой без зоны приходят с `zone = None`.
   Строки без цепочки (`section_chain_id IS NULL`) по-прежнему не приходят
   (на стенде таких строк-работ договоров 0). Справочный поиск по договорам
   (`load_reference_lines`) не меняется.
2. **Флажки семей** — один запрос `_zone_required_families(db) ->
   frozenset[int]` на сцену; он же даёт `KpLine.zone_required` (по семье
   варианта строки) и `WorkHistory.zone_required`.
3. **Ответ** (разбор участника, экран этапа, панель строки, файл
   подрядчику — общая форма строки):
   - `line.work_rung` получает `zone_scope: "own" | "other" | "any"`;
   - `analogs[]` панели — `zone: SectionZone | null`;
   - `parts_reference[].parts[]` — `zone_scope: "own" | "other" | "any" |
     null`;
   - новых полей уровня строки нет: строгая семья узнаётся по
     `no_history_reason == "no_zone_match"` или `state == "no_zone"`, имя
     семьи — `line.family`.
4. Файл подрядчику и шаблон комментария не меняются: они не говорят ни о
   ступени, ни о зоне.
5. **Сохранённые цели.** Справочная цель состояния строки не проверяет
   (`resolve_target`) и остаётся действующей у строки, ставшей сравнимой;
   её карточка показывает существующую подсказку `own_analogs` («у строки
   появились свои аналоги»). Цели вида «аналог», «самая свежая», «с этим
   подрядчиком» у строк, сравнимых сегодня, не сдвигаются (§7 п. 1).

## 4. Флажок семьи «зона обязательна»

1. **Миграция `0028`** (`work_families`):
   - `zone_required boolean NOT NULL DEFAULT false`;
   - `zone_required_changed_by integer NULL` → `users.id` `ON DELETE
     RESTRICT`; `zone_required_changed_at timestamptz NULL`;
   - `CHECK (zone_required_changed_by IS NULL OR zone_required_changed_at IS
     NOT NULL)` — автор без времени не бывает; время без автора — запись
     миграции;
   - **стартовый список** той же миграцией: `zone_required = true`,
     `zone_required_changed_at = now()`, автор `NULL` у семей, где
     `lower(btrim(title))` — одно из `двери`, `облицовка керамогранитом`,
     `покраска стен`, `вывоз и утилизация грунта`, `светильники`, `монтаж
     воздуховодов вентиляции`, `изоляция воздуховодов`, и `status <>
     'archived'`, во всех единицах. Каких названий не нашлось — печатается в
     вывод миграции; база без них проходит миграцию;
   - откат удаляет три колонки и ограничение.
2. **Маршрут** `PUT /api/v1/semantic/families/{family_id}/zone-required`,
   тело `{"zone_required": bool}`, только `admin` (`require_admin`, у `member`
   — 403 как у прочих маршрутов семей). Блокировка строки семьи `FOR UPDATE`.
   Отказы: семьи нет — 404 `family_not_found`; семья в архиве — 409
   `update_archived` (существующие коды `services/work_families.py`).
   Значение то же — 200 без смены автора и времени; иначе пишутся значение,
   `actor_id` и `now()`. Ответ — строка семьи (`_serialize_family`).
3. **Строка семьи** (`GET /families`, ответы мутаций семей) получает
   `zone_required: bool`, `zone_required_changed_at: string | null`,
   `zone_required_changed_by: {id, email} | null`.
4. **Слияние** (`merge_families`): после блокировок, если флажок есть у
   источника, а у цели нет, — у цели `zone_required = true`, автор — кто
   сливает, время — `now()`, в той же транзакции. У цели есть, у источника
   нет — цель не меняется. Перенос отдельных контекстов в другую семью
   флажок не трогает.
5. **Чтение подбором** — флажок на момент чтения сцены; кэшей подбора
   нет (кэш `/semantic/status` сбрасывается любым не-GET, как сегодня).

## 5. Экран

По дизайну §4 и макету (состояния 1–6). Закрепляется:

1. **Таблица строк** (`workRungCaption`): к подписи ступени добавляется
   « · другая зона» при `zone_scope == "other"` и « · зона не определена» при
   `"any"`; при `"own"` — как сегодня. `workRungLabel` не меняется (им же
   подписаны группы справки А).
2. **«Сравнение» панели** (`WorkComparison`): при области не `own` — вторая
   метка `Badge variant="secondary"` «другая зона» / «зона не определена»
   рядом с меткой ступени, и под ними строка-пояснение:
   - `other`: «В зоне «{zoneTitle(line.zone)}» аналогов нет — взяты из
     {список}.», где список — по зонам аналогов в порядке `SECTION_ZONES`
     (`pages/families/labels.ts`):
     «зоны «Надземная часть» (2)», несколько — «зон «Надземная часть» (2) и
     «Весь объект» (1)»; аналоги без зоны — последним пунктом «строк без
     зоны (N)»;
   - `any`: «Зона раздела не определена — аналоги из всех зон. Когда зону
     выберут, сравнение пересчитается.»
3. **Список аналогов панели** (`AnalogsTable`): при области не `own` — у
   каждого аналога метка `Badge variant="secondary"` «зона: Надземная»
   (`ZONE_LABEL`), у аналога без зоны — «зона: не определена». При `own`
   меток нет.
4. **Семья с флажком в панели:**
   - при `no_history_reason == "no_zone_match"` — над справкой строка «У
     семьи «{line.family}» зона обязательна: аналоги из других зон не берутся
     в сравнение. Они ниже — для справки.»;
   - при `state == "no_zone"` — к сегодняшнему тексту «Сравнения» спереди
     «У семьи «{line.family}» зона обязательна. ».
5. **Справка «по частям»** (`PartsReference`): у части с `zone_scope ==
   "other"` к подписи « · другая зона», с `"any"` — « · зона не определена».
6. **Тексты блока «Зона места»** (`ourPriceCopy.ts`):
   - `ZONE_HINT` — последняя фраза «Аналоги строке ищутся сначала в договорах
     с той же зоной; если там нет ни одного — в договорах других зон. У семей
     с отметкой «зона обязательна» — только в той же зоне.»;
   - `zoneScopeContracts(n)` — «Строки договоров этого раздела ({n}) служат
     аналогами для строк других КП — в первую очередь той же зоны: решение
     меняет и их сравнение.»
7. **Карточка семьи** (страница «Семьи», только `admin`, как вся страница):
   блок «Зона при подборе» между «Схемой и вариантами» и «Связями» —
   заголовок `h4`, `Switch` (shadcn) «Зона обязательна», пояснение по
   значению (тексты макета, состояние 5) и подпись автора: «Поставил {email},
   {дата}» / «Снял {email}, {дата}» / «Поставлен при обновлении, {дата}» (автор
   `NULL`); без записи — подписи нет. Переключение — сразу, без «Сохранить»
   (как категория), `Switch` занят на время запроса. Архивная семья —
   `Switch` недоступен.
8. **Окно слияния** (`MergeFamilyDialog`): при разных флажках у выбранной
   пары — строка под предупреждением о схеме:
   - флажок у источника: «У семьи «{источник}» зона обязательна — у
     «{цель}» после слияния она тоже будет обязательной.»;
   - флажок у цели: «У семьи «{цель}» зона обязательна — строки
     «{источник}» после слияния тоже будут подбираться только в своей
     зоне.»
9. **Перечитывание.** Мутация флажка (`useSetFamilyZoneRequired`) и
   слияние (`useMergeWorkFamilies`) сбрасывают `qk.workFamilies.all` и
   `qk.tenders.ourPriceAll`.

## 7. Проверки

**Критические свойства** (снятие защиты в копии дерева обязано дать красный
тест):

1. **Сравнимые сегодня не меняются.** Своя зона на любой ступени
   побеждает чужую: строка, у которой в `own` есть кандидат только на ступени
   4, а в `other` — на ступени 1, получает ступень 4 `own`. Снятие —
   поиск сначала по всем зонам.
2. **Семья с флажком — как сегодня:** только `own`, строки договоров без
   зоны не кандидаты, строка без зоны — `no_zone`, справка А и
   `no_zone_match` есть. Снятие — флажок не читается подбором.
3. **Строка договора без зоны никогда не `own`.** Снятие — строка без
   зоны попадает в область `own`.
4. **Приоритет строки без зоны** — каждое состояние §2 п. 3 отдельно
   (остановка захвата, живое задание, живое в паузу провайдера, предложение,
   «не знаю», ошибка, удержание, ответа нет), для семьи без флажка и с ним.
5. **Миграция:** список — с флажком во всех единицах, архивная — без,
   остальные — без; база без таких семей проходит; откат.
6. **Слияние:** флажок у источника → у цели есть (автор — сливающий); у
   цели → без изменений; ни у кого → нет. Снятие — слияние не трогает флажок.

**Остальные проверки:**

7. Маршрут флажка: 200 и автор/время при смене, без смены при том же
   значении; 403 у `member`; 404; 409 у архивной.
8. `vat_dropped` в той же области, что ступень; без ступени — первая пара
   «область, ступень».
9. Справка «по частям»: `own`, затем `other`; `any` у строки без зоны;
   только `own` у семьи с флажком.
10. Ответ: `work_rung.zone_scope`, `analogs[].zone`, `parts[].zone_scope`;
    `no_zone_match` не приходит у семьи без флажка.
11. Плашка «ждёт решения администратора» не считает сравниваемые строки без
    зоны и считает строки без зоны семей с флажком.
12. Экран: подписи таблицы, метки и пояснения «Сравнения», метки аналогов,
    тексты семьи с флажком, справка «по частям», тексты блока «Зона места»,
    блок в карточке семьи (значение, подпись автора, архив), предупреждение
    окна слияния, перечитывание после мутаций.
13. **Прогон «до/после» по стенду** скриптом замера дизайна, перенесённым
    на код фичи: снимок «до» — ответы разбора всех КП кодом базового
    коммита ветки (до первой задачи), «после» — кодом ветки; у строк,
    сравнимых «до», ответ совпадает полностью (проекция замера: состояние,
    ступень, вилка, три цифры, число аналогов, разница). **Нормализация
    перед сравнением** (ред. 2): у `work_rung` «после» сравниваются только
    прежние поля `no`, `released`, `other_class`, а `zone_scope` проверяется
    отдельно — у каждой строки, сравнимой «до», он ровно `"own"`; остальные
    поля проекции, в том числе все денежные и источники цифр
    (`analog_id`, `contract_id`), сравниваются без послаблений. Прибыль — по
    источникам: чужая зона, строка без зоны, строки договоров без зоны. Ожидание
    по замеру дизайна: ~+3 086 без строк договоров без зоны; число с ними —
    новое. Снимки — в `tasks/` (не под гитом: в них цены).
14. Снимки стенда по макету: строка со сравнением из чужой зоны, строка без
    зоны, строка семьи с флажком, карточка семьи, окно слияния — в обеих
    темах.
