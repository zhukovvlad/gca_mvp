# «Должен совпасть / не учитывается» в панели строки — спека (гейт 2)

**Дизайн:** [`docs/superpowers/design/2026-11-28-line-param-toggle.md`](../design/2026-11-28-line-param-toggle.md)
(одобрен 28.11.2026 после двух кругов ревью Codex), макет —
[`mockup.html`](../design/2026-11-28-line-param-toggle/mockup.html). Ветка `feat/line-param-toggle`,
PR #114. Миграций нет. `AGENTS.md` не меняется.

Термины. **Правило каталога** — набор главных параметров, которые лестница отпускает на ступенях 2
и 4 (`FamilyLadderInfo.releasable_ids`). **Правило пользователя** — набор главных параметров,
которые пользователь пометил «не учитывать» в панели. **Просмотр** — ответ панели по правилу
пользователя, отличному от правила каталога.

## 1. Что меняется и что нет

- Маршрут панели строки `GET …/our-price/offers/{offer_id}/lines/{position_item_id}` принимает
  правило пользователя (§2) и отвечает по нему (§3, §4). Без правила ответ **побайтно прежний**,
  кроме двух новых полей (§4.1), которые есть в любом ответе.
- Лестница `services/analog_ladder.py` получает режим «только значения» (§3). Поведение для
  обычного подбора не меняется.
- Фронт: переключатели в разделе «Работа», плашка просмотра, скрытие блоков (§5).
- Не меняются: разбор участника, экран этапа, таблица КП, итоги, цель, ступень, «согласовано»,
  комментарии, отметки «не аналог», файл подрядчику, каталог, кэш этапа. Просмотр ничего не пишет
  в базу и не сбрасывает кэш: маршрут — `GET` под `get_db`, записей нет (критерий 8).

## 2. Запрос

- Новый параметр запроса `ignore` — **строка**: id главных параметров через запятую, без
  пробелов, в любом порядке; пустая строка `ignore=` — «все главные должны совпасть».
  Параметр отсутствует — правило каталога, обычный ответ.
- Разбор на сервере, не валидацией FastAPI: любой отказ — `DomainError(422)` с кодом
  `rule_not_applicable` и русским текстом (как `unknown_rung` у `level`/`scope`). Отказ, если:
  1. строка — не работа, без варианта, комплект (`is_lump`) или лестница у неё не строится
     (`work_ladder_of` вернул `None`: в работе, без базы НДС, без цены или веса, без зоны у семьи
     с флажком) — текст «Для этой строки подбор по своему правилу недоступен.»;
  2. вариант строки на прежней версии схемы (`line.schema_id != info.schema_id`) — «Строка на
     прежней версии схемы семьи: переключение доступно после пересчёта варианта.»;
  3. в `ignore` не число или id, которого нет среди `info.main_parameter_ids` — «Параметр N не
     главный параметр семьи строки.»;
  4. вместе с `ignore` пришли `level` или `scope` — «Правило подбора и ступень системы не
     задаются вместе.».
- **Нормализация:** набор `ignore`, равный правилу каталога (`set(ignore) ==
  info.releasable_ids ∩ main_parameter_ids`), — это не просмотр: ответ строится обычным путём и
  побайтно равен ответу без `ignore` (критерий 1). Повторы id в `ignore` схлопываются.

## 3. Подбор по правилу пользователя

Только для одной строки и одной семьи; оценка остальных строк оффера не пересчитывается.

1. **Своя история семьи.** `WorkHistory(lines=history.lines_of(family_id), families={family_id:
   replace(info, releasable_ids=frozenset(ignore))}, contracts=history.contracts,
   factors=history.factors, zone_required=history.zone_required)`. Пулы строятся заново только для
   этой семьи: ключ значений (`_values_key`) зависит от отпускаемых. Общая `WorkHistory` сцены не
   трогается (кэшированная сцена неизменяема).
2. **Только ступени 2 и 4.** `ladder_for(..., values_only=True)` (новый ключевой аргумент,
   по умолчанию `False`): обход пар «область, ступень» без ступеней 1 и 3 — в том же порядке
   областей (`_scopes`) и классов (2 → 4). То же для `dropped_on`, `_dropped_on_first_rung` и
   `excluded_trace`, если они вызываются для просмотра.
3. **Ступень 2 и при пустом наборе.** В режиме `values_only` `_Search.releasable_ladder` истинно при
   совпадении схемы строки и семьи, даже если `releasable_ids` пусто: тогда ключ — значения всех
   главных параметров, подпись ступени «те же значения параметров» (`workRungLabel` уже так пишет
   при пустых `released` и `nearest`).
4. **Остальное — как сегодня:** сборное значение снятого параметра требует того же набора
   (`same_set`, форма в ключе); конфликт по параметру, который должен совпасть, блокирует ступень;
   зона (своя → другие; флажок — только своя); класс (2 — класс тендера, 4 — другой); отметки «не
   аналог» строки (`kp.excluded`) и «ошибка в цене»; отсев выбросов; самая низкая, самая свежая и
   подрядчик тендера.
5. **Ближайшее значение (А14).** `_narrow_scales` обходит `_releasable_ids(info)` подменённых
   сведений, а шкалы (`info.scales`) загружаются для **всех** главных точных параметров
   (`_family_scales`) — поэтому снятая пользователем шкала сужается до ближайших значений без
   новой логики. Неотпущенная шкала не сужается (её значение и так совпадает).
6. **Результат строки** — `_evaluate_work` с этой лестницей и **без сохранённых решений** строки
   (цель, «согласовано» в расчёт не подставляются): состояние, вилка, самая низкая, самая свежая,
   подрядчик, аналоги, выпавшие по НДС. Группа семьи (`group_index`) в просмотре не строится.

## 4. Ответ

### 4.1. Новые поля в любом ответе

- `line.params[*].parameter_id` — id параметра (главного и второстепенного) из `row.params`.
- Верхнее поле `rule`:
  - `null` — переключателей нет (строка из отказов 1–2 §2);
  - иначе `{"catalog_ignored": [id, …], "preview": null | {…}}`: `catalog_ignored` — правило
    каталога (главные параметры из `releasable_ids` по порядку схемы), начальное положение
    переключателей; `preview` — `null` в обычном ответе.

### 4.2. Ответ просмотра

- `rule.preview = {"ignored": [{"parameter_id", "name", "by": "user" | "catalog"}, …],
  "required_by_user": [{"parameter_id", "name"}, …]}` — по порядку схемы. `by: "catalog"` — параметр
  не учитывается и по каталогу; `"user"` — снят пользователем. `required_by_user` — отпускаемые
  каталогом, которые пользователь пометил «должен совпасть».
- По правилу пользователя (§3): `line` (`state`, `no_history_reason`, `work_rung` с `released`,
  `nearest`, `zone_scope`, `range`, `lowest`, `freshest`, `contractor`, `analogs_count`,
  `to_lowest`/`to_freshest`, `params` с `match` и `nearest`), `analogs`, `analog_columns` (колонки
  снятых параметров), `contracts`, `vat_dropped`, `excluded`.
- `line.params[*].match` в просмотре — правило применения в правиле пользователя (`params_rule`
  с подменёнными сведениями и ступенью просмотра; без ступени — основание `catalog` по подменённым
  сведениям). `releasable` — по-прежнему правило каталога.
- Пустыми (ключи есть, форма та же): `group_lines`, `reference_zones`, `reference_links`,
  `parts_reference`. `line.choice` и поля решений — как у строки без решений; `comment`,
  `zone_chain` — как в обычном ответе (от правила не зависят).

## 5. Экран

1. **Переключатель.** В `WorkParamsSection` у главного параметра, если `rule !== null`, колонка
   «При подборе» — `ToggleGroup` (shadcn/ui) из двух положений «должен совпасть» / «не учитывать».
   Положение: в обычном ответе — `rule.catalog_ignored`, в просмотре — правило пользователя.
   Второстепенные и строки с `rule === null` — прежняя подпись `matchText`.
2. **Подпись применения под переключателем** (`paramsCopy.ts`, новая функция), только когда
   применение отличается от положения:
   - положение «не учитывать», `match = required` — «сейчас совпал: найдены точные аналоги»;
   - `match = same_set` — «по-прежнему нужен такой же набор: {value}»;
   - `match = nearest` — нынешний `nearestMatchText` («ближайшее: B40»);
   - `match = matched` — «совпал»;
   - положение «должен совпасть» при `match = ignored` не бывает (не проверяется отдельно).
   Подпись заголовка «(аналогов нет — настройка каталога)» при основании `catalog` — как сегодня.
3. **Состояние правила** — `useState` в `LineSheetBody` рядом с `rung`; сбрасывается при смене
   строки (тело панели живёт, пока открыта одна строка) и при закрытии панели. В адрес не пишется.
   Запрос — `useOurPriceLine` с новым аргументом `ignore: number[] | null`; ключ `ourPriceLine`
   получает сегмент `ignore` (отсортированный список или `null`); `axios` шлёт `ignore` строкой.
   `null`, когда набор равен `catalog_ignored`, — тогда запрос и ключ совпадают с обычным.
4. **Плашка просмотра** при `rule.preview !== null` — над «Где строка»: заголовок «Просмотр: ваше
   правило подбора»; «Не учитывается: тип остекления/заполнения (вы), разрывная нагрузка
   (каталог)»; «Должен совпасть: … (вы)», если `required_by_user` не пуст; «Цифры строки в таблице,
   итоги, цель и файл подрядчику не меняются.»; кнопка «Как считает система» — сброс правила.
   Цвет — нейтральный информационный (токены `index.css`), не предупреждение.
5. **Пометка изменённого** у параметра, чьё положение отличается от `catalog_ignored`: «изменено
   вами · в каталоге: должен совпасть» / «… не учитывать».
6. **Скрыто в просмотре:** справочная цель, `ReferencePanel`, «По частям», «Вся семья в этом КП»,
   «В файл подрядчику» (`ExportBlock`), `LumpBlock`, «К самой низкой» в «Ценах»; в
   `TargetCards` и `AnalogsTable` — кнопки выбора цели, «комплект», «не аналог»; в
   `ExcludedAnalogs` — кнопки (список виден). `Ladder` и `RungSaveBar` у работы и так не
   показываются.
7. **Нет аналогов в просмотре** — в «Сравнении» фраза «По вашему правилу аналогов тоже нет.»;
   если причина — сборное значение снятого параметра (`no_history_reason = composite`): «Аналогов
   нет: сборное значение требует такого же набора частей. Аналоги по частям — в «Как считает
   система», блок «По частям».».
8. Пересчёт — прежний `RecalcOverlay` с `placeholderData` (старые цифры под серым слоем).
9. Тексты — в `paramsCopy.ts` и `ourPriceCopy.ts`.

## 6. Скорость

Тёплый вызов панели с `ignore` на оффере 76 (тендер 7, этап 23, ряд 1) — медиана из трёх не дольше
**1,5 с**; тёплая панель без правила — по замеру кэша этапа 0,45 с. Замер — скриптом в
`docs/superpowers/design/2026-11-28-line-param-toggle/`, на `gca_dev` только чтение.

## 7. Критерии готовности

1. `ignore`, равный правилу каталога (в любом порядке, с повторами), — ответ побайтно равен
   ответу без `ignore` (сравнение полного текста `decimal_json`).
2. Строка с аналогами на ступени 1: `ignore` с отпускаемым и ещё одним параметром даёт пул
   ступени 2 по правилу пользователя, не точные аналоги; вариант с другой второстепенной частью
   при тех же главных значениях попадает в пул.
3. Ужесточение (`ignore` без отпускаемого параметра каталога) сужает пул: строки договоров с
   другим значением этого параметра пропадают; `required_by_user` его называет.
4. `ignore=` (пусто) — ступень 2 с ключом из всех главных значений; подпись `released` пуста.
5. Снятая шкала сужается до ближайших значений (`work_rung.nearest`, `params[*].match =
   nearest`); снятый параметр не-шкала — любые значения (`ignored`); сборное значение снятого
   параметра — `same_set`.
6. Порядок областей и классов: аналоги своей зоны раньше чужой; ступень 4 — только если на 2 нет
   никого; у семьи с флажком — только своя зона; отметки «не аналог» строки не попадают в пул.
7. Отказы 1–4 §2 — `422` с кодом `rule_not_applicable` и своим текстом каждый.
8. Ничего не пишется: после серии вызовов с разными `ignore` поколение `stage_scene_cache` то же,
   строк в `kp_line_*`, `kp_family_rungs`, `kp_sent_files`, `family_parameters` не прибавилось и
   не изменилось; ответы разбора участника и экрана этапа побайтно прежние.
9. Просмотр не трогает общую историю сцены: обычный ответ панели той же строки после просмотра
   побайтно равен ответу до него (пулы общей `WorkHistory` не подменены).
10. `rule`: `null` у системной строки, комплекта, строки без варианта, без лестницы и на
    прежней схеме; у остальных работ `catalog_ignored` равен отпускаемым каталога.
11. Фронт: переключатели только у главных при `rule !== null`; положение по `catalog_ignored`;
    подписи применения §5 п. 2 (четыре случая); плашка и пометки только в просмотре; «Как считает
    система» возвращает обычный запрос; смена строки сбрасывает правило; кнопок решений в просмотре
    нет; блоки §5 п. 6 скрыты; фразы §5 п. 7.
12. Скорость §6.

## 8. Границы и риски сверх дизайна

- **Строка без цены, без базы НДС, в работе** — без переключателей: у них нет лестницы и сегодня.
  Подбор по правилу для них — отдельный вопрос, если понадобится.
- **Строка на прежней версии схемы** — без переключателей до пересчёта варианта (§2 отказ 2): id
  параметров варианта и действующей схемы расходятся, правило не сопоставить.
- **Бессмысленное правило** («тип конструкции» не учитывается) — допустимо в просмотре, плашка
  называет его целиком; при будущем сохранении правила нужна защита (дизайн, §3 п. 4).
- **Время.** Пул одной семьи строится на каждом вызове с правилом; у крупных семей (жб, сотни
  строк истории) — проверяется критерием 12, кэш пулов по правилу не делаем, пока замер в пороге.
