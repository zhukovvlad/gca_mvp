## 1. Контракт

`GET /api/v1/tenders/{t}/rounds/{r}/our-price/offers/{o}/lines/{p}` (панель
строки, доступ как сегодня — любой вошедший) получает поле верхнего уровня
`zone_chain` рядом с `line`, `analogs` и прочими. В `line` (общую форму со
строками экрана этапа) ничего не добавляется.

`zone_chain = null` — у системы (`line.kind == "system"`) и у строки без
цепочки разделов (`section_chain_id is None`). Иначе объект:

| Поле | Тип | Значение |
|---|---|---|
| `id` | int | `section_chains.id` |
| `titles` | string[] | названия цепочки сверху вниз |
| `zone` | `SectionZone \| null` | зона цепочки |
| `zone_source` | `"rule" \| "model" \| "human" \| null` | источник; `null` ⇔ `zone = null` |
| `decided_at` | ISO-строка \| null | момент решения человека; не `null` только при `human` |
| `rows_kp`, `rows_contracts` | int | строки цепочки во всех сметах КП и договоров — тем же запросом, что элемент очереди «Зоны» |
| `model_state` | см. ниже \| null | `null` ⇔ `zone ≠ null` |
| `model_answer` | `{zone, confidence, reason} \| null` | ответ модели; `zone` — код зоны или `"unknown"`, `confidence` — строка |
| `threshold` | string | `SEMANTIC_ZONE_AUTO_ACCEPT_THRESHOLD` (сегодня `"0.95"`) |

`model_state` у цепочки без зоны — первое подходящее сверху:

1. `"stopped"` — есть задание `section_zone` в `pending`/`running`, а захват
   заданий остановлен до человека (`semantic_worker_state.claim_paused`,
   читается `_claim_paused`; ставится `_stop_claim`, например
   `reserve_exceeded`, `provider_credits`);
2. `"paused"` — живое задание, остановки нет, но идёт пауза провайдера по
   времени (`budget_paused_until > now`, как в `crud/semantic_queue.py`);
3. `"running"` — живое задание без остановки и паузы;
4. `"unknown"` — `proposed_zone == "unknown"`;
5. `"proposed"` — `proposed_zone` — код зоны;
6. `"failed"` — есть задание в `error`/`privacy_hold`;
7. `"none"` — иначе.

Порядок повторяет правило строки: `in_progress` — живое задание без
остановки (пауза провайдера по времени строку из «разбирает» не выводит);
«ждёт решения» — спорная, застрявшая или живая при остановке. Поэтому подпись
блока не противоречит состоянию строки.

`model_answer`: у цепочки без зоны — `proposed_*` (при `unknown`/`proposed`),
иначе `null`. У цепочки с зоной — разбор (`parse_zone_answer`)
`raw_response` последней по `id` попытки с `outcome = "ok"` среди всех
заданий `section_zone` этой цепочки; такой попытки нет или ответ не
разбирается — `null` (без ошибки ответа панели).

Ничего не пишет; наружу ничего не уходит. Решение — существующий
`PUT /semantic/section-chains/{id}/zone` (только `admin`), без изменений.

## 2. Экран

По дизайну §4 и макету. Закрепляется:

1. Блок «Зона места» — в секции «Где строка» сразу под `LineWhere`, только
   у работы (`line.kind == "work"`). Секция «Где строка» показывается и тогда,
   когда статьи и пути нет, но блок есть.
2. Кнопки зон, «открыть в очереди «Зоны» →» (`zoneQueueHref(id)`) и окно —
   только у `admin`; у `member` — строка «Зону раздела меняет
   администратор.».
3. Окно подтверждения нужно при выборе зоны `z`, когда
   `z ≠ zone` и (`zone ≠ null` или `rows_contracts > 0`). Нажатие стоящей
   зоны (закрепление) и первая установка без строк договоров — сразу.
4. Блокировка — общая с очередью «Зоны» (`zoneDecisionMutationKey`); серый
   слой «Сохраняем…» с `placement="center"`. **Решение из панели держит
   мутацию в работе до конца перечитывания `qk.tenders.ourPriceAll`**, а с
   ним — ответа панели: сегодня `invalidateAfterLadderDecision(qc, "zones")`
   ждёт только очередь «Зоны», а экраны КП перечитывает фоном, и кнопки
   ожили бы на старом `zone = null` — второй выбор ушёл бы без обязательного
   окна. Очередь, карточка входа и «Принять все» ждут, как сегодня.
   Очередь «Зоны» и панель строки — на разных страницах: решение из очереди
   при открытой панели в той же вкладке невозможно; по возврату на экран КП
   панель перечитывается сброшенным ключом.
4а. Ожидание перечитывания не отличает успех от ошибки: `invalidateQueries`
   не отклоняет обещание при ошибке, а запрос панели при ошибке держит
   прежний ответ — и в кэше, после закрытия и повторного открытия панели.
   Поэтому кнопки зон открыты, только когда ответ панели подтверждён: у
   запроса панели нет ошибки, не идёт перечитывание и данные не
   заимствованы (`!isError && !isFetching && !isPlaceholderData`). Признак
   передаёт `LineSheet` из того запроса, чьи данные показывает панель;
   правило не зависит от времени жизни блока. При ошибке — текст п. 9 §3 и
   кнопка «Обновить»: перечитывает активные экраны «Против нашей цены»
   (`qk.tenders.ourPriceAll`); пока идёт перечитывание, у администратора
   блок под слоем «Обновляем…». Окно подтверждения и решение по
   неподтверждённому ответу недостижимы.
5. Строка без цепочки у работы — блок одной строкой, без кнопок, ссылки,
   охвата и подсказки «?».
6. У работы в состоянии `no_zone` — секция «Сравнение» с текстом п. 3 §3.
   Строка состояния над панелью и её ссылка — как сегодня.
7. `WHERE_ARTICLE` = «статья классификатора» (в панели и в таблице аналогов).

## 3. Тексты

Копия — в `ourPriceCopy.ts`; числа уверенности и порога — `formatConfidence`
(`@/lib/format`), зоны в строках — `ZONE_CAPTION`, в окне — `ZONE_CAPTION`
с заглавной буквы, дата — `formatDate`.

1. Заголовок «Зона места»; подсказка у «?» — дизайн §2 дословно.
2. Источник: `rule` — «по правилу»; `model` — «поставила модель · {conf}»
   (без « · {conf}», если `model_answer = null`); `human` — «поставил человек ·
   {дата}». Без зоны — «не определена» и рядом: `running` — «модель
   определяет» (и у `paused`), `none` — ничего, остальные — «ждёт решения
   администратора».
3. «Сравнение» при `no_zone`: «Не с чем сравнить: зона раздела не
   определена»; у `admin` с цепочкой — с « — выберите её выше»; без цепочки —
   «Не с чем сравнить: строка вне разделов сметы».
4. Охват: «Зона назначается строкам раздела во всех сметах: КП — {kp},
   договоры — {ct}.»; при `ct > 0` второй строкой «Строки договоров этого
   раздела ({ct}) служат аналогами для строк других КП той же зоны: решение
   меняет и их сравнение.»
5. Модель, цепочка без зоны: `proposed` — «Модель предлагает: {зона} · {conf} —
   «{reason}»; ниже порога {threshold}, решает администратор.»; `unknown` —
   «Модель не смогла определить зону — «{reason}»; решает администратор.»;
   `running` — «Модель определяет зону.»; `paused` — «Модель ждёт сброса лимита
   провайдера; можно не ждать и выбрать зону.»; `stopped` — «Разбор моделью
   остановлен до решения администратора; зону выбирает администратор.»; `failed` — «Модель не
   ответила; решает администратор.»; `none` — «Ответа модели нет; решает
   администратор.»
6. Модель, цепочка с зоной и `model_answer ≠ null`: «Модель предлагала: {зона
   или «не знаю»} · {conf} — «{reason}»». Без ответа — строки нет.
7. Строка без цепочки: «Зона места · не определена — строка стоит вне
   разделов сметы, зону назначить некуда».
8. Окно: заголовок «Сменить зону раздела?»; ««{titles через " / "}»: {было
   или «Не определена»} → {стало}.»; охват п. 4 обеими строками; кнопки
   «Отмена» и «Сменить зону».
9. Ответ панели не подтверждён ошибкой: «Панель не обновилась: зона на
   экране может быть устаревшей. Обновите панель, прежде чем менять зону.»;
   кнопка «Обновить»; слой при перечитывании — «Обновляем…».

## 4. Проверки

Дизайн §7, п. 1–8. Сервер: каждое значение `model_state` на своей фикстуре,
включая порядок (живое задание у цепочки со спорным предложением →
`running`; `claim_paused` → `stopped`; будущий `budget_paused_until` →
`paused`, прошедший → `running`), `model_answer` из журнала у решённой цепочки и `null` при
неразбираемом ответе, `zone_chain = null` у системы и у строки без цепочки.

Экран (ред. 4): PUT → 204, перечитывание панели → 500 — текст п. 9 §3,
кнопки закрыты, второй выбор не уходит и окна нет; «Обновить» снова → 500 —
текст остаётся; ответ → зона видна, смена требует окна. На настоящей
`LineSheet` с одним клиентом запросов: сохранение → 500 → панель закрыта и
открыта снова → 500 — кнопки закрыты до успешного ответа, после него смена
требует окна. Снятия защиты: без признака ошибки и без признака
перечитывания — красные.
