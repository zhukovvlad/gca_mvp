# «Не аналог» — спека (гейт 2)

**Дизайн:** [`2026-11-23-not-analog.md`](../design/2026-11-23-not-analog.md)
(гейт 1 принят Codex на `f458036`, пользователь — «одобряю, едем дальше»,
24.11.2026), макет рядом с ним. Зачем, варианты, пример и отвергнутое — там;
здесь — контракт, правила и проверки.

**Редакция 1, 24.11.2026.**

Спека меняет правила, закреплённые раньше:
- [спека лестницы аналогов](2026-11-07-analog-ladder-design.md) §2.10
  (причины «нет аналога») — новая причина `excluded`, раньше всех прочих;
  §2.14 (таблица сброса цели) — новая причина `excluded`;
- [спека справочных аналогов](2026-11-15-reference-analogs-design.md) §2.14 —
  справочная цель на исключённую строку недействующая (§6);
- [спека строк-сумм](2026-11-22-lump-sum-lines-design.md) §1 п. 2 — пул
  обычной ставки не берёт строки с «ошибкой в цене» (§5 п. 4).

Остальное в этих спеках действует без изменений.

**Уточнения дизайна** (дизайн — вход спеки, при расхождении побеждает спека):
- **Фильтра состояний в таблице строк нет** (так и в спеке строк-сумм §8 п. 1),
  поэтому пункт дизайна §4 п. 9 «фильтр состояний получает это значение» пуст:
  строка с новой причиной — в плитке и фильтре «не разобраны», как прочие
  «нет аналога».
- **Отмечаются только строки-работы.** Системы (`SYSTEM`) подбираются другим
  путём (ставки по ступеням семьи системы), их отметка — вне фичи (§11).
- **Единица строки формы** — `position_items.unit_id` строки КП: та, что
  видна в таблице строк (подпись `UnitOfMeasure`), а не каталожная. Строка КП
  без единицы даёт ключ с пустой единицей; он совпадает только с такими же.
- **Строки с неизвестной базой НДС** (`vat_dropped`, «выпал бы при известной
  базе») с отметкой не перечисляются: отметка сильнее подсказки о базе.

## 1. Данные

1. **Миграция `0030`**, две таблицы.

   `price_error_marks` — «ошибка в цене»:
   - `position_item_id bigint PRIMARY KEY` → `position_items.id` `ON DELETE
     CASCADE`;
   - `reason text NOT NULL CHECK (char_length(reason) BETWEEN 1 AND 300)`;
   - `set_by integer NOT NULL` → `users.id` `ON DELETE RESTRICT`; `set_at
     timestamptz NOT NULL`.

   `not_analog_marks` — «не аналог в этом тендере»:
   - `id bigserial PRIMARY KEY`;
   - `tender_id bigint NOT NULL` → `tenders.id` `ON DELETE CASCADE`;
   - `form_title text NOT NULL CHECK (form_title <> '')` — наименование строки
     формы, приведённое `normalize_title` (`services/zone_rules.py`);
   - `form_unit_id integer NULL` → `units_of_measure.id` `ON DELETE RESTRICT`;
   - `position_item_id bigint NOT NULL` → `position_items.id` `ON DELETE
     CASCADE` — строка договора;
   - `reason`, `set_by`, `set_at` — как выше;
   - `UNIQUE NULLS NOT DISTINCT (tender_id, form_title, form_unit_id,
     position_item_id)`; индекс по `tender_id`.

   Откат удаляет обе таблицы.
2. **Ключ строки формы** строки КП — `(normalize_title(job_title_in_proposal),
   position_items.unit_id)`. Загрузчик строк КП (`load_kp_lines`) кладёт его в
   `KpLine.form_key: tuple[str, int | None]`.
3. **Чтение без кэша.** Отметки тендера читаются одним запросом на сцену по
   `tender_id` (`load_not_analog_marks(db, tender_id) -> Mapping[form_key,
   Mapping[position_item_id, Mark]]`); «ошибка в цене» — в загрузке истории
   работ (`WorkHistoryLine.price_error: bool`) и одним запросом по
   идентификаторам для подписей (автор, причина, время) там, где они
   показываются (панель, поиск). Кэш обычных ставок (`StatusCache`) отметки
   сбрасывают, как любой не-GET запрос.

## 2. Маршруты (только `admin`, `require_admin`; у `member` — 403)

1. **«Ошибка в цене»:**
   - `PUT /api/v1/position-items/{position_item_id}/price-error`, тело
     `{"reason": string}`;
   - `DELETE /api/v1/position-items/{position_item_id}/price-error`.
2. **«Не аналог в этом тендере»** — от строки КП, ключ формы берётся с неё:
   - `PUT /api/v1/tenders/{tender_id}/rounds/{round_id}/our-price/offers/{offer_id}/lines/{kp_item_id}/not-analog/{position_item_id}`,
     тело `{"reason": string}`;
   - `DELETE` по тому же пути.

   Строка КП проверяется так же, как маршрутами строки сегодня (`_LINE`:
   оффер этапа тендера, строка в его КП) — те же 404. Отметка пишется на
   `(tender_id, form_key строки КП, position_item_id)`.
3. **Отказы** (строка договора блокируется `FOR UPDATE`):
   - строки нет — `404 position_item_not_found`;
   - строка не годится для отметки — `422 not_analog_not_applicable`: смета
     не договора (`estimates.contract_id IS NULL`), глава, контекст строки
     `SYSTEM`. Вариант, цена, база НДС и поправка «комплект» отметку не
     запрещают (дизайн §8: отметки и поправка независимы);
   - `reason` после обрезки краёв пуст или длиннее 300 символов — `422`
     валидации тела.
4. **Запись.** Та же причина — `200` без смены автора и времени; иначе
   пишутся причина, автор и `now()`. `DELETE` без записи — `204`, с записью —
   удаляет, `204`. Ответ `PUT` — `MarkView` (§7 п. 1).
5. **Замена сметы договора** (`_replace_existing`,
   `services/estimate_import.py`) — до удаления старой сметы считаются
   отметки обоих видов на её строках; если есть, в `warnings` задания —
   «Отметки «не аналог» по строкам прежней сметы ({n}) не перенесены —
   поставьте заново», рядом с предупреждением о поправках «комплект или
   ставка». Удаление договора, тендера уносит отметки каскадом без
   предупреждения.

## 3. Подбор (`services/analog_ladder.py`)

1. **«Ошибка в цене» — в пуле семьи.** `_build_pool` не берёт строку с
   `price_error` в кандидаты (рядом с `lump`), в том числе в строки с
   неизвестной базой. Это одно место для всех читателей пула: ступени,
   остаток, выбросы, самая низкая, свежая, «с этим подрядчиком», блоки А, Г,
   связи, «по частям», `vat_dropped`.
2. **Тендерная отметка — у строки КП.** `KpWork.excluded: frozenset[int]` —
   строки договоров с отметкой тендера сцены на ключ формы строки
   (`kp_work_of` заполняет из отметок сцены). Кандидаты из `excluded` не
   берёт ни один читатель пула **для этой строки КП** — список закрыт:
   - `ladder_for` — срезы ступеней (`known`) и `dropped_on`;
   - `parts_reference` — кандидаты частей;
   - `services/reference_blocks.py` — блок зон (через `ladder_for`) и блок
     связей (кандидаты связанной семьи).
3. **Лестница идёт дальше.** Ступень, у которой после исключений не осталось
   кандидатов класса, — пустая; подбор переходит к следующей паре «область,
   ступень», как сегодня. Выбросы, медиана, вилка и три цифры считаются по
   оставшимся.
4. **Пул без отметок.** `WorkHistory.pool_unmarked(family_id)` — тот же
   расчёт без пропуска `price_error`; строится лениво, только когда нужен
   (п. 5, п. 6). Пропуск `lump` в нём остаётся: комплект — не отметка.
5. **След исключённого** — `excluded_trace(kp, history, *, tender_class_id)
   -> ExcludedTrace`: подбор проходит пары «область, ступень» в порядке
   `ladder_for` дважды — по пулу без отметок без `kp.excluded` и по обычному
   пулу с ним. `S0` — первая пара, где нашлись бы кандидаты без отметок,
   `S1` — первая пара с отметками (или конец обхода). В след входят
   отмеченные кандидаты (с `price_error` или из `kp.excluded`), которые стоят
   в парах от `S0` до `S1` включительно, каждый — с парой, где он стоял бы
   (первой по порядку). `S0` нет — след пуст.

   ```
   ExcludedStep = (zone_scope: ZoneScope, rung_no: RungNo)
   ExcludedTrace = tuple[tuple[_Candidate, ExcludedStep], ...]  # порядок обхода, внутри пары — порядок ladder_for
   ```
6. **Причина `excluded`** — новое значение `NoHistoryReason`, **первое** в
   цепочке `_no_history_reason`: ступень с отметками не найдена, а без
   отметок нашлась бы (`S0` есть). Иначе — прежняя цепочка; `no_family` при
   семье, все кандидаты которой с «ошибкой в цене», не наступает — это
   `excluded`. Пул без отметок строится только для строк без ступени в
   семьях, где отметки есть.

## 4. Строки КП (`services/our_price.py`)

1. `KpLine.form_key` (§1 п. 2) и `KpWork.excluded` (§3 п. 2) — новые поля;
   `work_ladder_of` и `_evaluate_work` получают отметки сцены и передают их
   в `kp_work_of`.
2. Состояния строки КП не меняются: исключение — свойство подбора. Строка, у
   которой после исключений аналогов нет, — `no_history` с причиной
   `excluded`; есть — как сегодня.

## 5. Справки и обычная ставка

1. **«Найти в договорах»** (`reference_lines_query`, `ReferenceLine`):
   строки с отметкой **остаются** в выдаче, `SEARCH_LIMIT` и порядок не
   меняются. Строка несёт отметки, действующие для строки КП поиска:
   «ошибка в цене» и тендерная отметка на её ключ формы. Свёртка выдачи
   добавляет к ключу наличие отметок, а строка с отметкой не сворачивается
   ни с кем (как строка с поправкой, спека строк-сумм §6 п. 1).
2. **Справочные блоки** А, Г, связи и «по частям» — из кандидатов (§3 п. 1,
   п. 2), отмеченных в них нет.
3. **Цель из поиска** на строку с отметкой недоступна (§6 п. 3).
4. **Обычная ставка** (`load_typical_rates`, `crud/lump_sum.py`) — пул не
   берёт строки с «ошибкой в цене»; тендерные отметки ставку не трогают.

## 6. Цели

1. **Причина** `excluded` («строка исключена из аналогов») — новое значение
   `TargetResetReason` (бэкенд и тип фронта).
2. **`resolve_target`** — порядок проверок:

   | Условие | Причина |
   |---|---|
   | строка КП — система | `kind_changed` (как сегодня) |
   | строка КП `lump_sum` либо цель на строку-комплект | `lump_sum` (как сегодня) |
   | цель `analog` или `reference` на строку договора с «ошибкой в цене» или из `excluded` строки КП | `excluded` |
   | далее — как сегодня | `reference_unavailable`, `not_comparable`, `analog_unavailable`, `no_freshest`, `no_contractor` |

   Признак считает вызывающий (`target_excluded`, как `target_lump`) из
   отметок сцены. Запись цели остаётся; действует то, что действует у строки
   без выбора.
3. **Запись цели:** `put_reference_target` на строку с отметкой, действующей
   для строки КП, — новый `422 reference_is_excluded`, раньше проверок
   пересчёта; код входит в `REFERENCE_DRIFT_CODES` фронта. `put_target`
   (аналог) отказывает, как сегодня: исключённой строки нет в остатке.
4. **Файл подрядчику и комментарий** кода не меняют: наша цена берётся из
   сравнения и цели (дизайн §4 п. 7).

## 7. Ответ API

1. **`MarkView`**:

   ```
   MarkView = {
     kind: "price_error" | "tender",
     reason: string,
     set_by: {id, email},
     set_at: string
   }
   ```
2. **Панель строки** (`GET …/lines/{position_item_id}`) — новый список
   `excluded: ExcludedAnalogView[]` из следа §3 п. 5, в его порядке:

   ```
   ExcludedAnalogView = <поля аналога из analogs[] без outlier_ratio и меток цели>
                        & { step: {rung: 1|2|3|4, zone_scope: "own"|"other"|"any"},
                            marks: MarkView[] }   // «ошибка в цене» первой
   ```

   Цены — в ставке показа участника, как у аналогов. Строки без пары — нет:
   у строки без ступени по причине, не связанной с отметками, список пуст.
3. **Строка разбора** — `no_history_reason` получает `"excluded"`;
   `choice.reset_reason` — `"excluded"`.
4. **Строка поиска** (`reference_row_view`) — `marks: MarkView[]` (пусто —
   отметок нет).
5. **Аналог панели** (`analogs[]`) — новых полей нет: отмеченная для этой
   строки КП строка аналогом не бывает.

## 8. Экран

По дизайну §4 п. 9 и макету (разделы 1–4). Закрепляется:

1. **Меню аналога** (`AnalogsTable`, только `admin`): `DropdownMenu` (shadcn)
   с тремя пунктами — существующее «это комплект — убрать из сравнения»,
   «Не аналог в этом тендере…», «Ошибка в цене — не аналог нигде…». Пункт
   отметки открывает `AlertDialog` с текстом области действия (макет) и
   полем причины (`Textarea`, обязательное, до 300 символов, счётчик);
   «Исключить» занят до ответа.
2. **«Исключены (N)»** под аналогами — `Collapsible` (свёрнут), есть только
   при непустом `excluded`. Карточка — как карточка аналога (договор, цена,
   наименование, `LineWhere` статьи и пути в смете договора), приглушённая;
   при нескольких парах следа — подписи пар («ступень 4 · своя зона»); у
   строки, стоявшей не на паре, где подбор остановился, — метка «был бы на
   ступени N · {область}». Каждая отметка — отдельно: вид с областью
   («ошибка в цене · во всех тендерах», «не аналог в этом тендере»), причина,
   автор, дата и у `admin` своё «Снять»: «Снять в этом тендере» — сразу,
   «Снять во всех тендерах…» — через `AlertDialog` (текст — макет, раздел 4).
3. **Почему подбор ушёл дальше.** Если в `excluded` есть пары раньше пары
   `work_rung`, над вилкой «Сравнения» — строка «Ступень {N}, {область}: на
   {пара следа} аналоги исключены вручную ({K})»; несколько пар — через «;».
4. **Новая причина.** `NO_HISTORY_REASON_LABEL.excluded` — «Аналоги
   исключены вручную»; в панели — пояснение «Найденные строки договоров
   отмечены «не аналог». Сравнить не с чем.» и раскрытый список «Исключены».
5. **«Найти в договорах»** (`SearchMarks`, `ReferenceRows`): метки отметок с
   причиной в подсказке; «сделать целью» недоступно с подсказкой «Исключена
   из аналогов»; у `admin` — те же пункты меню и «Снять».
6. **Цель.** `TARGET_RESET_REASON.excluded` — «строка исключена из
   аналогов».
7. **Перечитывание.** Мутации отметок сбрасывают префиксы
   `qk.tenders.ourPriceAll` и `kpFilePreviewsAll` (как поправка строк-сумм).

## 9. Проверки

**Критические свойства** (снятие защиты в копии дерева обязано дать красный
тест):

1. **«Ошибка в цене» не кандидат нигде** — ступень, остаток, выбросы, три
   цифры, блоки А, Г, связи, «по частям», обычная ставка. Снятие — пропуск в
   `_build_pool`; отдельно — в пуле обычной ставки.
2. **Тендерная отметка — ровно на свой ключ.** Действует у всех офферов и
   этапов тендера и у строки с тем же текстом в другом разделе; не действует
   в другом тендере, при другой единице строки КП и при другом тексте;
   совпадает после приведения регистра, «ё» и пробелов. Снятие — ключ без
   тендера, без единицы, без приведения.
3. **Тендерная отметка не кандидат для своей строки КП** — ступень,
   `dropped_on`, «по частям», блок зон, блок связей; у соседней строки КП с
   другим ключом та же строка договора — кандидат. Снятие — по одному месту
   из закрытого списка §3 п. 2.
4. **Лестница идёт дальше**: последний кандидат пары исключён — подбор
   берёт следующую пару (другой класс, другая область); выбросы пересчитаны
   по оставшимся. Снятие — исключение после выбора ступени.
5. **Причина `excluded`** — только когда без отметок ступень нашлась бы;
   раньше `no_family` (все кандидаты семьи с «ошибкой в цене»), `path_conflict`,
   `composite`, `no_params`, `no_zone_match`; строка без кандидатов и без
   отметок — прежняя причина. Снятие — проверка после цепочки.
6. **След**: состав — пары от `S0` до `S1` включительно; пример двутавра
   тендера 6 в виде синтетики (кандидат своей зоны исключён → ступень в
   других зонах, след из одного кандидата с парой своей зоны); все исключены
   — след по всем парам до конца; отметки, не задевшие подбор, в след не
   входят. Снятие — след только по паре `S1`.
7. **Две отметки**: снятие одной оставляет строку исключённой по другой.
   Снятие — исключение по одному виду.
8. **Цели**: аналог и справочная цель на исключённую строку — `excluded`
   раньше `analog_unavailable` и `reference_unavailable`; `put_reference_target`
   — `reference_is_excluded`; в файле подрядчику у такой строки цена —
   самая низкая. Снятие — справочная цель не проверяет отметки.

**Остальные проверки:**

9. Маршруты: `PUT` пишет и не меняет автора при той же причине, меняет при
   другой; `DELETE` идемпотентен; 403 у `member`; 404 строки договора и
   строки КП; `422 not_analog_not_applicable` на каждое условие §2 п. 3;
   422 тела (пусто, 301 символ).
10. Миграция: вверх и вниз; уникальность тройки с пустой единицей.
11. Замена сметы договора с отметками — предупреждение с числом.
12. Ответ: `excluded` панели (поля, `step`, `marks`, порядок),
    `no_history_reason`, `reset_reason`, `marks` строки поиска; свёртка
    поиска не прячет строку с отметкой.
13. **Скорость**: разбор КП, этап и панель строки на стенде — не медленнее
    +10 % к сегодняшнему без отметок и с двумя отметками.
14. **Стенд**: «ошибка в цене» на строках VEER (плинтус, позиция по случаю
