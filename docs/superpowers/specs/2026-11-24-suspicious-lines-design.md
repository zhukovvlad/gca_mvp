# Подозрительные строки договоров — спека (гейт 2)

**Дизайн:** [`2026-11-24-suspicious-lines.md`](../design/2026-11-24-suspicious-lines.md)
(гейт 1 принят Codex на `73973e0`, пользователь — «вроде всё ок … едем дальше»,
24.11.2026), макет рядом с ним. Зачем, варианты, пример и отвергнутое — там;
здесь — контракт, правила и проверки.

**Редакция 1, 24.11.2026.**

**Редакция 2, 24.11.2026** — по ревью Codex к `8297121`: `PUT` «не ошибки» подтверждает только
основания, которые видел администратор, при расхождении — `409` (P2, §3 п. 1); проверки `DELETE`
отделены от `PUT` (P2, §3 п. 2); решения «не ошибка» — массивом, у каждого основания свои
причина, автор и дата (P2, §4 п. 1); «Разобраны» читают строки решений отдельно от кандидатов,
цена строки может отсутствовать с причиной (P2, §2 п. 7, §4 п. 2).

**Редакция 3, 24.11.2026** — по ревью Codex к `6c6a4fe`: непригодная цена отмеченной строки не
сливается с отсутствующей — отрицательное и нечисловое значение отдаются как есть со своей
причиной, «цены нет» — только пусто и ноль (P2, §4 п. 2, §7 п. 6а).

Спека меняет правила, закреплённые раньше:
- [спека «Не аналог»](2026-11-23-not-analog-design.md) §2 п. 5 — предупреждение замены
  сметы договора считает и решения «не ошибка» (§1 п. 4).

Остальное в ней действует без изменений.

**Уточнения дизайна** (дизайн — вход спеки, при расхождении побеждает спека):
- **Считаем в Python поверх загрузчика подбора, а не SQL-запросом** (решение пользователя
  24.11.2026; заменяет дизайн §2 «Считать в базе», §3 вариант 3 и расчётную часть §4.7). Медиану
  в SQL нельзя посчитать без строк-комплектов: признак комплекта (`lump_check`) живёт в Python, а
  его копия на SQL — второе место одного правила. Замер на стенде
  (`tasks/suspicious-lines/python_path_measure.py`, `profile_work_history.py`): загрузка истории
  тем же загрузчиком, что у подбора, — ~1,7 с, из них ~1,1 с — запросы к базе; сама статистика
  групп — 40 мс. Рост с числом договоров упирается в запросы загрузчика — тот же, что у панели
  строки сегодня (долг, §8).
- **Выбор строки в паре двойника уточнён** (§2 п. 4) по замеру
  `tasks/suspicious-lines/twin_pick_measure.py`. Правило дизайна помечало бы мраморную плитку
  VEER (её цена обычная, ×1,02; ошибка — у плинтуса рядом, а он не кандидат) и обе строки пары
  с плинтусом VEER, как только тот отмечен «ошибкой в цене» и выпал из статистики. Уточнённое
  на стенде даёт 5 строк: плинтус VEER, озеленение VEER «шт» по цене м² газона, водопонижение
  МИРА (спорно) и обе строки «маячного ряда» Cityzen; мрамор не помечается.
- **Статистика групп — по всем договорам**, включая объект тендера: подозрение — свойство
  строки, а не тендера, и цифры подсказки в панели обязаны совпасть со списком. Аналоги панели
  по-прежнему без договоров объекта тендера.
- **Единица группы** — каталожная (`WorkHistoryLine.unit_id`, как у обычной ставки);
  **единица двойника** — единица строки сметы (`position_items.unit_id`): правило ловит
  расхождение того, что написано в смете.

## 1. Данные

1. **Миграция `0031`**, таблица `not_error_marks` — решения «не ошибка», по строке на
   основание:
   - `id bigserial PRIMARY KEY`;
   - `position_item_id bigint NOT NULL` → `position_items.id` `ON DELETE CASCADE`;
   - `kind text NOT NULL CHECK (kind IN ('outlier', 'twin'))`;
   - `family_id integer NULL` → `work_families.id` `ON DELETE CASCADE`; `unit_id integer NULL`
     → `units_of_measure.id` `ON DELETE RESTRICT`; `direction text NULL CHECK (direction IN
     ('up', 'down'))` — основание выброса;
   - `neighbor_item_id bigint NULL` → `position_items.id` `ON DELETE CASCADE` — основание
     двойника;
   - `CHECK` формы: у `outlier` заданы `family_id`, `unit_id`, `direction` и пуст
     `neighbor_item_id`; у `twin` — наоборот;
   - `reason`, `set_by`, `set_at` — как у `price_error_marks` (1–300 символов, `users.id`
     `ON DELETE RESTRICT`, `now()`);
   - `UNIQUE NULLS NOT DISTINCT (position_item_id, kind, family_id, unit_id, direction,
     neighbor_item_id)`; индекс по `position_item_id`.

   Откат удаляет таблицу. Семья ушла (слияние, удаление) — основание уходит каскадом, и строка
   при новом подозрении снова «не разобрана»: это и есть «другое основание».
2. **Основание** (`Basis`) — то, что проверил администратор: у выброса — `(family_id, unit_id,
   direction)`, у двойника — `neighbor_item_id`. Множитель в основание не входит (дизайн §4.6).
3. **Индекс подозрений в кэше.** `suspicion_cache: StatusCache` (`services/status_cache.py`),
   срок — новая настройка `SUSPICION_CACHE_TTL_S` (по умолчанию 300, `0` — выключен).
   Значение — `SuspicionIndex` (§2 п. 6) по всем договорам. Сбрасывают его — список закрыт:
   - `PUT`/`DELETE` «ошибки в цене», «не ошибки» и поправки «комплект или ставка»;
   - конец задания импорта (`run_import_job`, рядом со сбросом `typical_rates_cache`);
   - удаление договора.

   Прочие записи (правки каталога, решения торга) индекс **не** сбрасывают: прослойка
   `main.py`, сбрасывающая кэши на любой не-GET, его не трогает. Иначе любая запись на экране
   торга возвращала бы панели холодный пересчёт ~2 с. Цена — правка каталога видна в
   подсказках не позже срока кэша.
4. **Замена сметы договора** (`_replace_existing`, `services/estimate_import.py`): число строк
   прежней сметы с отметками «не аналог», «ошибка в цене» или решением «не ошибка» — одно
   предупреждение вместо нынешнего: «Отметки «не аналог» и «не ошибка» по строкам прежней сметы
   ({n}) не перенесены — поставьте заново». `n` — число строк (строка с несколькими решениями
   считается один раз). Решения уходят каскадом со строками.

## 2. Правила (`services/suspicious_lines.py`, чистый модуль)

1. **Кандидаты.** Строки `load_work_history` по сметам, которые выбрал `load_history` **без
   исключения объекта** (`exclude_object_id: int | None`, `None` — все договоры; сегодняшние
   вызовы передают объект, как раньше), у которых: не `lump`; база НДС известна; каталожная
   единица есть; нетто `gross_to_net(unit_price, vat_base)` не меньше `MIN_NOMINAL` (1 ₽).
   Строки с `price_error` — кандидаты (их показывает «Разобраны»), но в статистику групп не
   входят. Отбор строк, семья, глава, система, `NaN`, прежние версии смет — всё из загрузчика
   подбора: своего запроса отбора у правила нет.
2. **Статистика группы** `(family_id, unit_id)` по кандидатам без `price_error`:
   - цена договора — медиана нетто его строк (`price_basis.median`, точная десятичная);
   - обычная цена — медиана цен договоров;
   - Q1, Q3 цен договоров — квартили «включительно» (метод `inclusive` `statistics.quantiles`),
     в `Decimal`; функция модуля `quartiles(values) -> tuple[Decimal, Decimal]`;
   - группа **с обычной ценой** — не меньше `MIN_CONTRACTS = 3` договоров; **однородная** —
     ещё и `Q1 > 0` и `Q3 / Q1 ≤ MAX_SPREAD = 2`.
3. **Выброс.** У кандидата однородной группы `ratio = net / usual`; подозрение при `ratio ≥
   OUTLIER_RATIO = 10` (направление `up`) или `ratio ≤ 1 / OUTLIER_RATIO` (`down`). Строка с
   `price_error` подозрение получает так же, сравниваясь со статистикой без себя.
4. **Двойник.** Соседи строки — строки той же сметы без глав, на 1–3 места раньше или позже в
   порядке `position_items.id`. Пара — кандидат `L` и сосед `N` с одинаковой `unit_cost_total`
   (пригодной, `is_price`) и разными известными `position_items.unit_id`. Отклонение строки —
   `d = |ln(net / usual)|` при обычной цене её группы, иначе `None`. Кто из пары подозрителен:
   1. если у кого-то из двух есть `price_error` — только у него (у кандидатов с отметкой);
   2. иначе **годны** кандидаты пары, у которых `d is None` или `d ≥ ln 2` (цена сама дальше
      чем вдвое от обычной); сосед-не-кандидат не годен никогда;
   3. годны оба и у обоих `d` есть — подозрителен тот, у кого `d` больше (равны — оба);
      иначе — все годные.

   Сосед-не-кандидат в паре называется в факте другого, если тот подозрителен. Строка в двух
   парах получает два факта.
5. **Факты** строки — кортеж в порядке «выброс, затем двойники по `neighbor_item_id`»:

   ```
   OutlierFact = (kind="outlier", family_id, unit_id, direction: "up"|"down",
                  ratio: Decimal, usual: Decimal, net: Decimal)
   TwinFact    = (kind="twin", neighbor_item_id: int)
   Fact = OutlierFact | TwinFact;  basis_of(fact) -> Basis
   ```
6. **Индекс** (`build_suspicion_index(lines, neighbors) -> SuspicionIndex`):

   ```
   ContractPrice = (contract_id, lines: int, price: Decimal, low: Decimal, high: Decimal)
   GroupStats    = (family_id, unit_id, usual: Decimal | None, homogeneous: bool,
                    contracts: tuple[ContractPrice, ...])   # по цене договора
   SuspicionIndex = (facts: Mapping[position_item_id, tuple[Fact, ...]],
                     groups: Mapping[(family_id, unit_id), GroupStats],
                     group_of: Mapping[position_item_id, (family_id, unit_id)],
                     net: Mapping[position_item_id, Decimal])
   ```

   Соседей готовит загрузчик `load_estimate_neighbors(db, estimate_ids)` (`crud/suspicious_lines.py`):
   строки смет без глав с номером места в смете — один запрос с `row_number()` по
   `position_items.id`.
7. **Состояние строки** (`state_of(facts, dismissals, price_error) -> "unresolved" |
   "resolved" | None`), по порядку:
   1. есть «ошибка в цене» — `resolved` (с фактами или без);
   2. есть факт, чьего основания нет среди решений «не ошибка» строки, — `unresolved`; если
      решения у строки есть, они идут в ответ как `previous`;
   3. есть решение «не ошибка» — `resolved` (с фактами или без);
   4. иначе — `None`, строки в списке нет.

   Строка попадает ровно в один блок.

   **Строки решений читаются отдельно от кандидатов** (`load_decided_lines(db)`,
   `crud/suspicious_lines.py`): все строки с «ошибкой в цене» или «не ошибкой» — одним запросом,
   независимо от пула (ред. 2). Решение законно и у строки вне пула: «ошибку в цене» можно
   поставить строке без варианта, без цены, с неизвестной базой НДС, комплекту
   (`_lock_contract_item`), а отмеченная строка уходит из пула, когда к договору загружают
   допсоглашение. Факты у такой строки — только если она есть в индексе (то есть пустые, кроме
   строк последней сметы в пуле).

   Подсказка в панели — у не разобранной строки (факты без решения); у строки, все факты
   которой решены «не ошибкой», — серая строчка.

## 3. Маршруты (`routers/suspicious_lines.py`; только `admin`, у `member` — 403)

1. **«Не ошибка» — `PUT /api/v1/position-items/{position_item_id}/not-error`**, тело
   `{"reason": string, "bases": BasisKey[]}`, где `bases` — основания фактов, которые
   администратор видел в окне (поле `basis` у `FactView`, §4 п. 2). Сервер читает **свежий**
   индекс (сбрасывает кэш и строит заново) и сверяет: каждое переданное основание есть среди
   текущих фактов строки, и каждый текущий факт без решения есть среди переданных. Совпало —
   пишутся переданные основания без решения (у уже решённых записи не меняются: свои причина,
   автор и дата остаются); ответ — `NotErrorDecision[]` строки (§4 п. 1). Не совпало — `409
   suspicion_changed`, ничего не пишется; экран перечитывает строку и показывает «Подозрение по
   строке изменилось — проверьте заново» (ред. 2: окно, открытое по семье A, не подтверждает
   молча семью B, в которую фоновый разбор перевёл строку, или нового двойника).

   ```
   BasisKey = {kind: "outlier", family_id: int, unit_id: int, direction: "up"|"down"}
            | {kind: "twin", neighbor_item_id: int}
   ```

   Отказы `PUT` (строка блокируется `FOR UPDATE`, как `_lock_contract_item`), по порядку:
   - строки нет — `404 position_item_not_found`;
   - строка не из сметы договора, глава или `SYSTEM` — `422 not_analog_not_applicable` (как у
     отметок);
   - `reason` пуст после обрезки или длиннее 300, `bases` пуст — `422` тела;
   - у строки сейчас нет фактов — `422 not_suspicious`;
   - набор оснований разошёлся — `409 suspicion_changed`.
2. **«Вернуть» — `DELETE /api/v1/position-items/{position_item_id}/not-error`** — удаляет все
   решения «не ошибка» строки. Единственный отказ — строки нет (`404`). Ни текущие факты, ни
   пригодность строки для новой отметки (смета, `SYSTEM`) не проверяются: снять существующее
   решение можно всегда, в том числе когда подозрение исчезло или строку перевели в систему;
   без решений — `204`, повтор — `204` (ред. 2).
3. **Список:** `GET /api/v1/suspicious-lines?contract_id={id}` — ответ §4 п. 2; без
   `contract_id` — все договоры. Договора нет — `404`.
4. **Счётчики:** `GET /api/v1/suspicious-lines/counts` — `{"total": int, "by_contract":
   {contract_id: int}}`, только не разобранные; договоры с нулём не перечисляются. Его читают
   вкладка (N) и карточка договора.

## 4. Ответ API

Деньги — строки-десятичные **номинального нетто** (без НДС, без индексации), как
`money_pair(...).net`; подписи единиц — `units_of_measure.symbol`.

1. **Решения «не ошибка»** — массивом, по записи на основание, у каждой свои причина, автор и
   дата (ред. 2: основание семьи A от одного администратора и семьи B от другого — две записи,
   а не одна общая подпись):

   ```
   NotErrorDecision = { basis: BasisView, reason: string, set_by: {id, email},
                        set_at: string }
   BasisView = BasisKey & ({ kind: "outlier", family_title: string, unit: string }
                         | { kind: "twin", neighbor: {item_number: string|null, title: string} })
   ```

   Везде, где решения показываются (`previous`, `resolved`, аналог панели, ответ `PUT`), —
   **все** записи строки, по `set_at`, новые сверху.
2. **Список** (`GET /api/v1/suspicious-lines`):

   ```
   {
     unresolved: SuspectView[],      // по договору, затем по месту в смете
     resolved: ResolvedView[],       // по времени решения, новые сверху
     contracts: [{contract_id, number, object_title, unresolved: int}]  // для фильтра
   }
   SuspectView = LineHead & {
     facts: FactView[],
     previous: NotErrorDecision[],   // решения на другие основания; пусто — не было
     neighbors: NeighborRow[],       // ±3 строки без глав, сама строка — с флагом
     where: {article, chapter_path},  // как у аналога панели
     prices: GroupPricesView | null   // группа строки, если у неё есть обычная цена
   }
   ResolvedView = LineHead & {
     price_error: MarkView | null,
     not_error: NotErrorDecision[],   // хотя бы одно из двух есть
     facts: FactView[]                // пусто — «правило сейчас её не ловит»
   }
   LineHead = { position_item_id, contract: {id, number, object_title},
                item_number: string|null, title, unit: string|null,
                latest: bool,                 // строка последней сметы договора
                net: string | null,           // номинальное нетто за единицу
                gross: string | null,         // цена сметы как есть, когда нетто нет
                raw: string | null,           // значение сметы, которое не цена
                price_note: null | "no_price" | "negative" | "not_finite" | "vat_unknown" }
   FactView = { basis: BasisKey } & (
              { kind: "outlier", direction, ratio: string, usual: string,
                family_title, unit: string, contracts: int }
            | { kind: "twin", neighbor: NeighborRow })
   NeighborRow = { position_item_id, item_number, title, unit, quantity: string|null,
                   unit_price: string|null, materials: string|null, works: string|null,
                   total: string|null, is_self: bool, is_twin: bool }
   GroupPricesView = { family_title, unit, usual: string,
                       contracts: [{contract_id, object_title, lines: int, price: string,
                                    low: string, high: string, is_own: bool}] }
   ```

   `quantity` — `coalesce(suggested_quantity, quantity)`; цены соседей — нетто по базе сметы;
   при неизвестной базе — валовые, с флагом в `NeighborRow` (`gross: true`).

   Цена строки (`LineHead`, ред. 2, ред. 3): у кандидатов — нетто индекса, `price_note = null`.
   У строк решений вне пула — по порядку, остальные денежные поля `null`:

   | `unit_cost_total` | `price_note` | поле | подпись экрана |
   |---|---|---|---|
   | пусто или 0 | `no_price` | — | «цены нет» |
   | `NaN`, `±Infinity` | `not_finite` | `raw` — как хранится (`"NaN"`, `"Infinity"`, `"-Infinity"`) | «в смете: {raw} — не число» |
   | меньше нуля | `negative` | `raw` — десятичная строка | «в смете: {raw}» |
   | база НДС неизвестна | `vat_unknown` | `gross` | «НДС сметы не известен — цена как в смете» |
   | иначе | `null` | `net` по базе сметы | — |

   «Цены нет» значит только пусто и ноль (правило проекта о пустой цене): отрицательное и
   нечисловое значение в смете есть, и экран показывает его как есть, причину не называя
   (ред. 3, ревью Codex: на такую строку законно ставят «ошибку в цене», и значение объясняет
   решение). В статистику такие строки не входят — они не кандидаты. `latest = false` —
   подпись «строка прежней сметы».

   Денежные поля `NeighborRow` — по тем же правилам: конечное значение (в том числе
   отрицательное и ноль) — десятичной строкой (нетто по базе сметы, при неизвестной базе —
   как в смете с `gross: true`), нечисловое — как хранится, пусто — `null`.
3. **Аналог панели** (`analogs[]` в `GET …/lines/{position_item_id}`) — два новых поля, у
   `admin` и `member` одинаковые:
   - `suspicion: { facts: FactView[], net: string, prices: GroupPricesView | null } | null` —
     факты без решения;
   - `not_error: NotErrorDecision[]` — решения строки; серая строчка показывается, когда
     `suspicion` пуст, а решения есть (по строчке на решение).

   Цифры — из того же индекса, что у списка, и не зависят от режима НДС и ряда ИПЦ панели.

## 5. Экран

По дизайну §4 и макету (разделы 1–4). Закрепляется:

1. **`/contracts`** (`ContractsPage`): у `admin` — `Tabs` «Договоры | Подозрительные строки
   (N)», состояние вкладки, фильтра и строки — в адресе: `?tab=suspicious&contract={id}&line={id}`.
   `member` вкладку не видит; адрес со `tab=suspicious` у него открывает «Договоры». Фильтр —
   `Select` из `contracts` ответа. Над списком — счётчики (не разобраны, по правилам,
   разобраны). Пункт — метка правила («↕ цена выбивается», «= та же цена, другая единица»),
   наименование, цена «₽ за {ед.} без НДС», договор и номер позиции; у выброса — крупный
   множитель и полоса цен (`chart` shadcn на recharts, логарифмическая шкала, наведение — договор
   и цена), у двойника — две карточки через «=»; затем два `Collapsible` «Строки рядом в смете»
   и «Цены этой работы в договорах»; кнопки «Ошибка в цене…» (окно фичи «Не аналог») и «Не
   ошибка…». «Разобраны (M)» — `Collapsible`, свёрнут. `line` в адресе — пункт прокручен в вид,
   оба блока раскрыты.
2. **Окно «Не ошибка»** — `AlertDialog` с текстом основания (макет, раздел 4), `Textarea`
   причины (обязательная, до 300, счётчик); «Сохранить» занят до ответа. Окно отправляет
   `basis` фактов, которые оно показало; на `409 suspicion_changed` закрывается, строка
   перечитывается, сверху — «Подозрение по строке изменилось — проверьте заново».
   «Разобраны» у каждого решения «не ошибка» — своё основание, причина, автор и дата.
3. **Карточка договора** (`ContractCardPage`, `admin`): «Подозрительные строки: {n} →» в блоке
   реквизитов, ссылка на `/contracts?tab=suspicious&contract={id}`; при нуле — нет.
4. **Панель строки КП** (`AnalogsTable`): подсказка под наименованием аналога (макет, раздел 3):
   множитель, текст факта с ценой строки и обычной ценой, полоса, подпись «Цены подсказки —
   номинальные, без НДС, без индексации»; у `admin` — ссылка «Разобрать в списке ↗»
   (`/contracts?tab=suspicious&line={id}`, новая вкладка) и три кнопки. После «не ошибки» —
   серая строчка «проверено, не ошибка — {основание}: «{причина}» · {автор} · {дата}».
   Подсказки нет в «Исключены», «Найти в договорах» и справочных блоках.
5. **Узкий экран**: таблицы блоков — минимальная ширина 760 px и прокрутка внутри блока,
   деньги без переноса; полоса цен — своя прокрутка, текст и кнопки — в ширине карточки.
6. **Тексты** — `pages/contracts/suspiciousCopy.ts`; подсказка панели берёт их оттуда же.
7. **Перечитывание.** Мутации «не ошибки» и «ошибки в цене» сбрасывают префиксы
   `qk.suspicious` (список и счётчики) и `qk.tenders.ourPriceAll`. То же делают «ошибка в цене»,
   поставленная и снятая из панели строки КП, и поправка «комплект или ставка»: она меняет пул
   кандидатов, и сервер сбрасывает индекс (раздел 1 п. 3).

## 6. Скорость

- Индекс холодный (сразу после сброса) — не дольше 2,5 с на стенде; тёплый — панель строки не
  медленнее +10 % к сегодняшней (как «Не аналог»), список и счётчики — не дольше 2 с.
- Мерить чередованием «база/ветка» без нагрузки (урок «Не аналог»), тёплый и холодный кэш
  отдельно.

## 7. Проверки

**Критические свойства** (снятие защиты в копии дерева обязано дать красный тест):

1. **Голос договора.** Вход «Лифты»: 35 одинаковых строк одного договора и по строке у пяти
   других, цены договоров разнятся — подозрений нет; при цене договора по строкам — были бы.
   Снятие — медиана по строкам вместо цен договоров.
2. **Границы выброса**: `Q3/Q1 = 2` — группа однородна, чуть больше — нет; 2 договора — нет
   обычной цены; `ratio` ровно 10 и ровно 0,1 — подозрение, рядом — нет. Снятие — строгие
   неравенства.
3. **Статистика без «ошибки в цене» и комплектов**: строка с `price_error` не входит в цену
   своего договора, комплект — не кандидат. Снятие — пропуск в статистике.
4. **Выбор в паре двойника** — пять случаев замера синтетикой: сосед не кандидат при обычной
   цене строки (мрамор) — никто; пара с `price_error` — только она; один из пары в пределах
   ×2 — другой; оба без обычной цены — оба; оба с ценой — дальний. Снятие — без фильтра ×2 и
   без приоритета `price_error`, по одному.
5. **Основание «не ошибки»**: та же семья, единица и направление — факт решён; другая семья,
   другое направление, новый двойник — строка снова «не разобрана» с `previous`. Снятие —
   решение по строке без основания.
5а. **`PUT` подтверждает только увиденное** (ред. 2): окно открыто по выбросу в семье A, до
   сохранения строка переведена в семью B (или появился двойник) — `409 suspicion_changed`,
   записей нет; переданный набор совпадает — пишутся ровно переданные основания. Снятие —
   запись всех текущих оснований без сверки.
6. **«Разобраны» не теряют решение**: вход «три договора 10, 100, 100», «ошибка в цене» у
   дешёвой строки — правило молчит, строка в `resolved` с пустыми `facts`. Ещё три входа вне
   пула (ред. 2): «ошибка в цене» у комплекта, у строки прежней сметы после загрузки
   допсоглашения (`latest = false`) и у строки с неизвестной базой НДС (`net = null`,
   `"vat_unknown"`) — все три в `resolved`. Снятие — `resolved` из текущих фактов или из строк
   индекса.
6а. **Цена отмеченной строки вне пула** (ред. 3): «ошибка в цене» на строках с
   `unit_cost_total` пусто, 0, −100, `NaN` и `Infinity` — `price_note` `no_price`, `no_price`,
   `negative` (`raw = "-100"`), `not_finite` (`raw = "NaN"`), `not_finite` (`raw =
   "Infinity"`); подписи экрана различаются. Снятие — одна ветка «не `is_price`» на всё.
7. **Одни цифры на двух поверхностях**: факт аналога в панели и пункт списка — те же `ratio`,
   `usual`, `net`; панель в режиме «с НДС» и с рядом ИПЦ цифр подсказки не меняет. Снятие —
   подсказка из цены аналога панели.

**Остальные проверки:**

8. Кандидаты — строки загрузчика подбора: строка прежней сметы при допсоглашении, глава,
   `SYSTEM`, архивный контекст, нетто < 1 ₽, `NaN` — не кандидаты (через `load_work_history`,
   без своего отбора).
9. Маршруты: `PUT` с полным набором пишет основания, повтор не меняет записей; два основания
   от разных администраторов с разными причинами — две записи `NotErrorDecision` с каждая своей
   подписью в `previous`, `resolved` и панели; `DELETE` — после исчезновения фактов, после
   перевода строки в `SYSTEM` и повторный — `204` и решений нет; 403 у `member`; 404; у `PUT` —
   `422 not_suspicious`, `not_analog_not_applicable`, тело (пусто, 301 символ, пустые `bases`). Список и счётчики: фильтр по договору, счётчик карточки равен N
   фильтра, 404 договора.
10. Кэш: сброс каждым местом закрытого списка §1 п. 3; запись торга (не из списка) индекс не
    сбрасывает.
11. Миграция вверх и вниз; `CHECK` формы основания; уникальность с пустыми полями.
12. Замена сметы — одно предупреждение с числом строк.
13. Скорость — §6.
14. **Стенд**: список совпадает с замерами гейта (выбросы — `contract_level_measure.py` с
    учётом отметок 24.11.2026, двойники — `twin_pick_measure.py`), расхождения объяснены
    поштучно. Снимки стенда по макету в обеих темах и на 390 px.
