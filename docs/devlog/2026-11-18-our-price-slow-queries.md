вопрос кэша этапа в памяти (карта, пункт 3), и особенно для А12, где каждое нажатие
пересобирает панель.

## Снятие К1

Единственное критическое свойство плана: в конфликт попадает только главный не архивный
параметр со значением `path_conflict` контекста из входа — фильтр решает, какая строка
истории годится в аналоги. Копия дерева, тестовая база `gca_rev_test`, протокол
`BASELINE_GREEN / MUTATION_APPLIED / EXPECTED_TEST_FAILURE / RESTORED`:

| Снятое условие | Покраснели |
|---|---|
| `role = 'main'` | `test_secondary_is_not_returned`, сводный |
| `archived_at IS NULL` | `test_archived_main_is_not_returned`, сводный |
| `source = 'path_conflict'` | `test_main_with_other_source_is_not_returned`, сводный |
| `context_id IN (вход)` | `test_context_outside_the_input_is_not_returned`, сводный |

После каждого снятия файл восстановлен (sha256 совпал), копия удалена.

  А11. Процессный документ не меняется.
- **Красного прогона TDD у новых тестов нет** — так решил план (решение 3): тесты фиксируют
  поведение и зелёные на старом запросе; что они не ложно-зелёные, доказывает К1.
- **Комментарий про `OFFSET 0`** исполнитель поставил внутрь строки SQL; при приёмке он
  перенесён в комментарий Python — иначе русский текст уходил бы в базу при каждом
  выполнении и в `pg_prepared_statements`.

## Найденные грабли и наблюдения

- **Обе ловушки — в `docs/pitfalls/db.md`**: маленькая таблица без статистики после заливки
  дампа и хэш по всей таблице на шаге рекурсии.
- **Повод читать `db.md` уже нынешнего случая.** Строка «Когда читать» (и в файле, и в
  AGENTS §10) называет миграцию, индекс и блокировку; запрос к большой таблице под неё не
  попадает. Править строку значит ревизовать `AGENTS.md`, чего фича не делает (§5 спеки) —
  оставлено наблюдением.
- **Профиль по слоям опроверг направление карты.** Карта предлагала кэш этапа; замер показал,
  что ~13 из 17 с ответа — два запроса с плохим планом, а не сборка этапа. Отдельная
  проверка из разведки: в одной таблице дизайна сперва оказались сведены числа двух разных
  прогонов — Codex это поймал на гейте 1, после чего все цифры снимаются одним скриптом
  в одном процессе.
- **Тест на скорость невозможен на тестовой базе**: на маленьких таблицах планировщик и
  старый запрос исполняет быстро. Скорость держит только замер на данных стенда.
