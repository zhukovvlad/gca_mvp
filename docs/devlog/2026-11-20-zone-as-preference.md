# Devlog: зона как предпочтение подбора, а не фильтр

**Дизайн:** [`docs/superpowers/design/2026-11-20-zone-as-preference.md`](../superpowers/design/2026-11-20-zone-as-preference.md) (редакция 3), макет и замер рядом
**Спека:** [`docs/superpowers/specs/2026-11-20-zone-as-preference-design.md`](../superpowers/specs/2026-11-20-zone-as-preference-design.md) (редакция 3)
**План:** [`docs/superpowers/plans/2026-11-20-zone-as-preference.md`](../superpowers/plans/2026-11-20-zone-as-preference.md) (редакция 2)
**Ветка:** `feat/zone-as-preference`, PR #93 · **Миграция:** 0028 · **Ревизия `AGENTS.md`:** v6.36

Зона раздела была фильтром подбора аналогов: строка КП искала только в своей зоне, а строка
без зоны не сравнивалась вовсе. Замер дизайна показал, что зоны отнимают 16–34 % сравнений и
почти не различают цену. Теперь зона — предпочтение. Подбор идёт так:

- сначала ступени 1–4 в своей зоне (`own`);
- если там ни одна ступень ничего не нашла — ступени 1–4 по всем прочим зонам вместе со
  строками договоров без зоны (`other`);
- строка КП без зоны ищет по всей истории (`any`).

Семьи, у которых зона подменяет тип изделия, держит прежнее правило флажок
«зона обязательна».

## Процесс и отступления

- Пять задач по плану через subagent-driven-development: исполнитель — Sonnet по
  брифу-файлу, коммиты — оркестратор. Узкое ревью Opus — у задач 2 и 3, остальные — приёмка.
- Ревью задачи 2: 0 Critical / 0 Important / 4 Minor. Minor 1 и 3 исправлены, Minor 2
  закрыла задача 3.
- Ревью задачи 3: 0 / 1 / 4. Important — флажок, который сцена передаёт в историю, не
  защищал ни один тест: подмена набора пустым оставляла всё зелёным. Ревьюер сам дописал
  тесты:
  - сцена — семья с флажком, в истории только строки договоров без зоны → `no_family`, а не
    `no_zone_match`;
  - поиск по договорам — `[flagged|unflagged]`.

  Прямой аналог той же подмены в поиске остаётся зелёным по существу: строгость там даёт
  флажок строки КП, а разница только во внутренней причине, которой нет в выдаче.
- Снятия защит и ревью шли только в копии бэкенда вне живого дерева: стенд отдаёт живое
  дерево. Первое ревью задачи 2 с правками в основном дереве отклонил классификатор.
- Задача 4 (только `frontend/`) шла параллельно с ревью задачи 3 (только чтение) и
  закоммичена раньше неё; пути не пересекаются.

**Отступления от плана:**

1. **Архивная семья.** Маршрут флажка отвечает ей 409, а не 422 — по существующей конвенции
   `_STATUS_CONFLICT` у PATCH семьи. Спека — редакция 3 (§4 п. 2, §7 п. 7), план — утв. 4.
2. **Имя миграции.** Файл — `2026_11_21_0028-family_zone_required.py` (имя плана); глоб
   теста паритета поправлен.
3. **Утверждение 10 задачи 2** («без правки ожиданий») для многозонных входов буквально
   невыполнимо. Семь тестов лестницы и сцены «строгой семьи» в интеграции (`_strict`,
   `_underground`) переведены на семью с флажком с прежними ожиданиями. Ожидания поменялись
   только там, где спека меняет результат для семьи без флажка: строка без зоны больше не
   `no_zone`, параметр `undetermined_zone` убран. Ревью обеих задач сочло перевод
   корректным.
4. **Где лежат тесты утверждений задачи 3.** В `test_analog_scene.py` и
   `test_ref_analogs_*`, а не в файлах брифа: поведение загрузчика и состояний живёт там.
5. **Перечень зон, который спека не задаёт.** Для трёх и больше зон и для сочетания «зона +
   строки без зоны» принято «зон «A» (1), «B» (1) и строк без зоны (1)».
6. **Вёрстка пояснений.** Три пояснения — «аналогов нет — взяты из зоны…», «зона раздела не
   определена — аналоги из всех зон…» и «зона обязательна…» — после машинной сверки с
   макетом стали блоком (`80a164e`, см. «Приёмка»).
