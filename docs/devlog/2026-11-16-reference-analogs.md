Реализация 15–16.11.2026, ускоренный режим плана («Режим реализации»): исполнители —
Sonnet, ревью (Opus, узкий бриф) у задач 1, 2, 3, 6, 7, 8, снятия К1–К10 — оркестратор в
копии дерева.

У строки КП, для которой «нет аналога в зоне», панель теперь показывает ту же работу
в другой зоне здания; у строки без истории — связанную семью в другой единице с
пересчётом (м² ↔ м³ через толщину, м ↔ м² через ширину, м³ ↔ т через плотность или
постоянный множитель); у любой строки есть поиск по строкам смет договоров. Любую такую
строку администратор может сделать целью («справочной») с пересчётом, который
запоминается снимком. Справка и справочная цель не входят ни в вилку, ни в суммы.

## Найденные грабли и наблюдения

- **Базы `gca_*_test` conftest не создаёт.** Исполнитель задачи 4 и оркестратор снятий
  заводили базу `createdb` руками; прогон по несуществующей базе даёт ошибки установки, а
  не красные тесты, и выглядит как «снятие сработало».
- **Диск профиля.** ENOSPC у исполнителя 9b: на томе оставалось ≈ 100 МБ; копии
  `mut*/rev*/head*` в scratchpad удалены (2,8 ГБ свободно). Копии дерева для снятий —
  `git archive`, без `node_modules` и `.venv`.
- **Ключ `-p no:logging`** (исполнитель задачи 7) ломает `caplog`: четыре «ошибки
  установки» исчезают без флага.
- **Деньги пересчёта — точный `N` в контексте `_CONTEXT`.** `factor` в ответе — `format(N, "f")`
  (`str` Decimal даёт «1E+1»), сравнивать на клиенте и в `expected_factor` нужно как
  `Decimal`, а не строку («0.100» против «0.1»).
- **Печать числа и вид чисел тестам не видны** — снимки стенда рядом с макетом
  (см. «Стенд и замеры»).
