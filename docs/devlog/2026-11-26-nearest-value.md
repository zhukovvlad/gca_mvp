## Что сделано

Отпущенный главный параметр-шкала на ступенях 2 и 4 берёт сначала ближайшие к КП значения
кругами до трёх договоров; экран называет взятые значения, направление и причину расширения.

- **Шкала** (задача 1) — `services/value_scale.py: scale_numbers`; шкалы главных точных
  параметров действующих схем — одним запросом в `_family_ladder_infos`
  (`FamilyLadderInfo.scales`); ответ схемы — `ParameterOut.scale`.
- **Сужение** (задача 2) — `_narrow_scales` в `services/analog_ladder.py`, вызов в
  `ladder_for` после `first_pair`; `NearestParam`, `WorkLadder.nearest` и `matched`,
  `released` без ближайших и совпавших; `dropped_on` с фильтром `accepts`;
  `ZoneGroup.nearest`.
- **Ответ API** (задача 3) — `work_rung.nearest`, `contracts_count`, `match = nearest |
  matched` с `nearest` у параметра, `side` у ячейки, `nearest` у групп зон.
- **Фронт** (задачи 4–5) — подпись ступени, «N аналогов в M договорах», абзац «почему»
  (`nearest-why`), «При подборе», стрелка со скрытым текстом в ячейке, строка «Шкала…» в
  окне правки схемы. Справочник — `docs/reference/screens.md` (§8 «Ближайшее значение на
  шкале», §9 окно правки).

## Процесс и отступления

Режим — по риску (решение пользователя 28.10.2026, Global Constraints плана): узкое ревью
Opus и снятия оркестратора — у задачи 2, остальные — приёмка оркестратором. Исполнители —
Sonnet, коммиты — оркестратор.

- **Спека, редакция 4** (§4 п. 3): «после отбора по {имя}» ставило имя в именительный падеж
  («по класс бетона…»), а имена пишет администратор, склонять их нельзя («грузоподъемность,
  кг»). Теперь «после отбора по параметру «класс бетона по прочности»». Нашёл исполнитель
  задачи 4; строка плана поправлена той же веткой.
- **Значения круга для `dropped_on`** — решение оркестратора: `value_id` всей шкалы с
  расстоянием не больше взятого, а не только значения кандидатов, — чтобы строка без НДС с
  «В30» при взятом «B30» проходила так же (§2 п. 5 говорит о числе).
- **`params_rule`**: значение по умолчанию `nearest` — неизменяемое пустое отображение,
  а не `{}` плана (ruff B006).
- Исполнитель задачи 2 гонял свои снятия в живом дереве (восстановил; стенд в тот момент
  не работал) — в следующих брифах запрет повторён явно.
- Исполнитель задачи 4 пропустил фикстуру `work_rung` без `nearest` в
  `LineSheet.work.test.tsx` (литерал не типизирован — tsc промолчал, упал рендер); поправил
  оркестратор при приёмке.

побайтное восстановление:

| Снятие | Итог |

| сужение по всем главным, не только отпускаемым | красный «набор прежний без отпущенной шкалы» |
