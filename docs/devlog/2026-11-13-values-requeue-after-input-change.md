## Отступления

- **От дизайна (спека §1).** Отмена «вход изменился» отметку «уточняется» не
  ставит. Признак «контекст ждёт повтора» — сама нужда контекста.
- **От спеки, по ходу реализации (§2.2, §2.3 поправлены той же веткой).**
  Проверка конца пачки сверяет кандидатов ветвью значений
  (`reconcile_context_values`), а не полной сверкой. Полная заодно ставила бы
  задания предложений: на двух кандидатах тестовой семьи — 4 задания вместо 2.
  Таблица исходов для значений та же (`_plan_context_values`), так что прежняя
  волна сверяла ту же ветвь.
- **От процесса.** Режим ускоренный:
  - Task 1 — исполнитель Sonnet, ревью Opus по узкому брифу;
  - снятия — оркестратор лично в копии дерева (решение пользователя
    28.10.2026), а не ревьюер, как требует `docs/process/implementation.md`;
  - Task 2 без ревью, проверка — снимки.

## Ревью Task 1

Продуктовых дефектов нет. Ревьюер сам укрепил тесты (10 правок):

- ложно-зелёные места:
  - запрет сверки при пустых кандидатах стоял не на той функции;
  - оживление под барьером не проверялось;

  - проверка прохода была зелёной при упавшем проходе — проход глотает

- новый тест на семью `coalesce(pending_family_id, work_family_id)`.

Низкие замечания, не чинились:

- **Потолок события.** Сверка обработчика берёт его из переданных настроек,
  проверка конца пачки — из модульных. В проде это один объект.
- **Двойной вопрос.** Ответ, расширивший сразу два параметра A и B: волна A
  ставит задания по A, волна B видит пачку и ждёт. Контекст с пустыми A и B
  спросят дважды. Раньше волна B терялась целиком; теперь лишний вызов
  модели, но ничего не теряется.
