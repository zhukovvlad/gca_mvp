## Что сделано

Экран этапа, разбор участника, панель строки и предпросмотр файла берут собранный этап из
памяти процесса. Перезапросы после решения по строке тоже идут из кэша, при этом цифры не
устаревают. Пункт карты «Скорость 4а и 4б», вторая часть.

- **Кэш сцен** (задача 1) — `services/stage_cache.py: SceneCache`, `stage_scene_cache`.
  - Ключ — `(тендер, этап, оффер | весь этап, ряд ИПЦ | без ряда)`.
  - Срок жизни — `STAGE_SCENE_CACHE_TTL_S`, по умолчанию 600 с; 0 выключает кэш. Объём —
    `STAGE_SCENE_CACHE_SIZE`, по умолчанию 8 сцен, вытесняется самая давно использованная.
  - Поколение общее на весь кэш. `put` сверяет его и вставляет сцену в одной критической
    секции.
- **Отслеживание записей** (задача 2) — события класса `Session`.
  - Записанные таблицы копятся в `session.info` до конца внешней транзакции.
  - После коммита записи вне закрытого списка сбрасываются сначала `typical_rates_cache`,
    затем кэш сцен. Закрытый список: согласовано, комментарий, ступень, цель, отправленный
    файл. Исключение действует только для помеченной транзакции.
  - `RELEASE SAVEPOINT` не сбрасывает: в SQLAlchemy 2.0.35 `after_commit` приходит и на
    вложенную транзакцию, её отсекает `in_nested_transaction()`.
  - Записанное забывается в `after_transaction_end` корневой транзакции: так чистят и
    коммит, и откат, и `close()`.
  - CTE-чтение `_chapter_chain_rows` помечено опцией `stage_cache_read`.
- **Точка входа** (задача 3) — `crud/our_price.py: _scene_for`.
  - Поколение берётся до первого чтения.
  - При попадании решения и отправленные файлы читаются заново.
  - Попадание с отсутствующей строкой даёт тот же 404, что и холодный путь.
  - Пометку ставят `_write_decision` и `export_file`.
- **Грязная транзакция** (задача 4). Транзакция, уже записавшая что-то вне списка, идёт
  мимо обоих общих кэшей: точка входа и `crud/lump_sum.py: typical_rates` считают сами
  (спека §5).

## Процесс и отступления

Режим проверок — по риску (решение пользователя 28.10.2026).
- Задачу 1 принимал оркестратор, задачи 2–4 прошли узкое ревью Opus (`task-reviewer`).
- Исполнители — Sonnet, коммиты — оркестратор.
- Снятия из таблицы плана делал оркестратор в копии дерева (`git archive`) на отдельной
  тестовой базе.

- **Спека §4.1, ревью задачи 2.** Отслеживание не видело трёх путей записи:
  - `sa.text(...).columns(...)` (`TextualSelect`) — теперь разбирается как текст;
  - массовые `bulk_*`;
  - DML внутри CTE выборки.

  Ловить последние два в обработчике значит обходить каждую выборку на сборке сцены, а это
  дорого. Решение оркестратора: в коде приложения таких путей быть не должно, держит их
  страж `tests/unit/test_stage_cache_guard.py` (grep).
- **Спека §5, ревью задачи 3.** Спека ссылалась на «обход вызывающих в плане», а в плане
  его не было. Обход сделал ревьюер, результат вписан в спеку: записи вне списка до сборки
  нет ни на одном пути.
- **Существующие тесты кэша ставок.** Это `test_lump_sum_load.py::TestCache` и
  `test_ref_analogs_lines.py::TestQueryShape::test_each_loader_runs_one_query`.
  - Они писали фикстуры в той же транзакции и ждали попадания в кэш ставок.
  - После правила §5 такая транзакция грязная, и ставки грузятся на каждом вызове. Семь
    тестов `TestCache` стали проходить по пустоте: ревьюер в копии снял сбросы прослойки,
    импорта и срок — набор остался зелёным.
  - Исправлено фиксацией фикстур перед проверкой (`_settle` с проверкой `is_dirty`).
    Ожидания не ослаблены, это следствие спеки.
- **Копии.** Ревьюер задачи 2 удалил общий каталог копии в scratchpad вместе с копией
  оркестратора. С задачи 3 у каждого своя копия и своя тестовая база
  (`gca_mut_test`, `gca_review_test`). После финала обе базы удалены.

## Приёмка

**Снятия из таблицы плана.** Оркестратор, копия дерева, побайтное восстановление; каждое
снятие уронило названный тест:

| Снятие | Упало |
|---|---|
| пометка в `_write_decision` | API: «решения сохраняют сцены» — 10 из 11 вариантов (выгрузка цела: у неё своя пометка) |
| подписка `after_commit` | отслеживание: коммит ORM-записи; API: база НДС сметы КП, «не аналог», фоновый импорт |
| проверка поколения в `put` | единица: `put` со старым поколением; гонки: сборка, пересёкшая коммит |
| сверка и вставка в разных критических секциях | единица: чередование внутри `put` |
| поколение после `_load_head` | гонки: пауза после шапки, площадь объекта |
| сброс ставок на коммите | отслеживание: порядок; гонки: ставки сразу после коммита, пауза между сбросами |
| сброс ставок после сброса сцены | отслеживание: порядок; гонки: пауза между сбросами (по смыслу — сборка сохранена, проверено ревьюером) |
| `is_dirty` в `_scene_for` | гонки: оба теста грязной транзакции и кэша сцен |
| `is_dirty` в `typical_rates` | гонки: тёплый и пустой кэш ставок |
| пометка чтения в `_chapter_chain_rows` | отслеживание: `chapter_steps`; API: выгрузка со справочной целью |

Сверх таблицы сняты ещё две защиты, и обе уронили свои тесты:
- пометка в `export_file` — выгрузка со справочной целью;
- отсечка `in_nested_transaction` — выход из точки сохранения без внешнего коммита.
