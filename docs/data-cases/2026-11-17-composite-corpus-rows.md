# 2026-11-17 · Строки «по корпусам»: тип конструкции только в заголовке раздела, и строка становится сборной

## Симптом

КП C5/MIND (тендер 7, этап 23, оффер 76), статья 4.1.2 «Устройство
горизонтальных монолитных ж/б конструкций подземной части» → «1 Этап ЖК» →
«Ж/Б конструкции подземной части» → «Балки, капители, трансферные
конструкции, лестницы». В разделе три строки в м³:

- «Лестницы B30 W6 F150 …» — аналог есть (1 аналог);
- 223662 «Корпус 6 B50 W6 F150 …» — в КП нет цены;
- 223663 «Корпус 1,2,3,4,5,7,9 В40 W6 F150 арматурой класса А500С, А240» —
  876,86 м³ по 60 055,67 ₽/м³, на экране «Против нашей цены»: «нет аналога:
  в строке несколько значений параметра «Тип конструкции»».

Пользователь (17.11): «почему тут опять нет аналогов?»

## Как нашли

1. **Ответ строки** (построение панели строки на чтение,
   `crud.our_price.build_line_view`, без ступени): `state = no_history`,
   `no_history_reason = composite`, `composite_parameter` — «Тип
   конструкции» (id 344, `source = path`), вариант «Устройство жб конструкций · B40 · W6 ·
   трансферные конструкции + балки + капители», `zone = underground`,
   аналогов 0.
2. **Откуда составное.** В наименовании строки типа конструкции нет — только
   корпуса и класс бетона. Модель взяла значение из пути разделов: заголовок
   «Балки, капители, трансферные конструкции, лестницы» перечисляет типы, и
   она прочла строку как работу «сразу по всем» (`several`, `combine = all`;
   промпт значений — `backend/services/variant_request.py`). Лестницы в набор
   не вошли — у них в разделе своя строка.
3. **Правило лестницы.** Составное значение совпадает только с тем же
   составным (спека упрощения каталога
   [§2.8](../superpowers/specs/2026-11-10-catalog-simplify-design.md)): нужна
   строка договора, где «трансферные + балки + капители» оценены одной ценой.
   Таких в договорах нет — пусто на всех ступенях.
4. **«По частям»** (`parts_reference` в ответе панели; на цифры строки не
   влияет), без НДС, ₽/м³:

   | Часть | Аналоги | Цена |
   |---|---|---|
   | трансферные конструкции | 0 | — |
   | балки | 4, один договор (12-СИТ-МР, другой класс) | 52 100 – 53 475 |
   | капители | 1 (МИРА, СДП-1-МР) | 41 370 |

   Трансферных конструкций в подземной зоне при B40 в договорах нет; над землёй
   они есть (Тушино), но зону лестница не отпускает.
5. **Масштаб.** Тот же прогон по всем строкам оффера 76, чьё наименование
   начинается с «Корпус» (смета разбита по корпусам, тип стоит только в
   заголовке раздела): 13 строк — `composite`, ещё 6 — `path_conflict`
   («параметры расходятся по разделам»), с аналогами — 2 (стены корпуса 8).
   Почти весь монолит этого КП «по корпусам» остаётся без сравнения.

## Причина

Данные заказчика плюс правило сборной строки. Ведомость считает объём бетона
по корпусу, а не по типу конструкции; тип — в заголовке раздела, и заголовок
перечисляет несколько типов. Модель честно читает это как сборную работу, а у
сборной строки аналогом бывает только такая же сборная. «Нет аналога» — ответ
по правилу, не дефект кода.

Попутно видно два места, где чтение спорное:

- **Один заголовок — разные наборы.** «Корпус 6 B50» из того же раздела
  получил набор с лестницами («… + балки + лестницы + капители»), а «Корпус
  1,2,3,4,5,7,9» — без них. На экран не влияет: у «Корпуса 6» в КП нет цены.
- **«Или» тоже без аналогов.** Строка 223765 получила «перекрытия **или**
  плиты покрытий» (`combine = any`) и тоже `composite`, хотя по частям у неё 2
  и 11 аналогов. Спека §2.8 требует то же составное и для «вместе», и для
  «или»; по смыслу «или» — «годится любое одно».

## Что сделали

Ничего в данных не меняли. Свести строку к одному типу (например,
«трансферные конструкции») — значит выдать цену одной части за цену
смешанного объёма, доли частей неизвестны. Решение по конкретной строке — за
пользователем через журнал каталога.

## Что осталось

- Аналоги для составного `any` («или») по любой из частей — вопрос к спеке
  упрощения каталога §2.8, в карту пока не внесён; решает пользователь.
- Сметы, разбитые по корпусам с типом только в заголовке раздела, будут
  давать сборные строки и дальше: наименования и разбивку пишет заказчик, это
  свойство его ведомости, а не отдельной сметы.

Признак для следующего раза: `no_history_reason = composite` — сначала
смотреть, откуда составное (`source = path` и заголовок-перечисление), потом
`parts_reference` в ответе панели: он и есть ориентир по цене.
