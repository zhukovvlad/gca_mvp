# 2026-08-23 · Версии одного файла: суммы те же, объёмы разделов разные

## Симптом

Дважды за день неверный вывод о данных: сначала «импорт выбрасывает объёмы
разделов», потом «у объекта фасада вдвое больше на м²». Оба раза виноватым
казался парсер.

## Как нашли

1. Одна и та же оферта лежит в `samples/` в нескольких версиях: суммы
   совпадают до копейки, а «предлагаемое количество» на строках-разделах
   заполнено только в некоторых. У МИРА старый файл давал 0 разделов с
   объёмом, новый — 128.
2. UB9 пользователь перезалил дважды за четыре минуты; промежуточная версия
   несла две секции фасадов вместо одной. Замер пришёлся между перезаливками.
3. Сверка того, что в базе, с тем, что на диске:

   ```sql
   SELECT filename, file_sha256, finished_at
   FROM import_jobs
   ORDER BY id DESC;
   ```

   и `sha256sum` файла из папки объекта. Хэши не совпали — в базе лежала
   другая версия, чем та, с которой сравнивали.

## Причина

Числа из базы сравнивались с одноимённым файлом из папки, а не с тем, который
импортирован. Парсер ни при чём в обоих случаях.

## Что сделали

Ничего в коде. Порядок проверки: прежде вывода о парсере или данных — сверить
`file_sha256` из `import_jobs` с хэшем файла на диске.

## Что осталось

Ничего. Попутно: номера на скриншотах Excel — колонка «№ п/п», а не строки
листа.

Признак для следующего раза: расхождение базы с файлом, которое «не может
быть», — сначала хэш файла, потом код.
