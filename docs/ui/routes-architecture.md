# Архитектура роутов SaaS-платформы анализа закупок

Документ описывает информационную архитектуру и карту роутов системы для семантического анализа счетов-фактур от поставщиков. Цель — спроектировать интерфейс вокруг **бизнес-сущностей** (объекты, поставщики, материалы), а не вокруг технических процессов (загрузка файлов, парсинг, очереди).

---

## Принципы архитектуры

**Сущностно-ориентированная навигация.** Пользователь работает не с файлами и не со страницами, а с бизнес-сущностями: объектами строительства, поставщиками, материалами. Каждая сущность имеет собственный раздел в навигации и собственную карточку с аналитикой.

**Три оси данных.** Любая информация в системе доступна с трёх сторон — через объект, через поставщика, через материал. Это даёт пользователю гибкость в постановке вопросов: «что у меня с этим объектом», «как ведёт себя этот поставщик», «что происходит с ценой на этот материал».

**Прогрессивное раскрытие технического слоя.** На уровне навигации и сводных экранов технические детали (распознавание, статусы парсинга, проценты уверенности модели) скрыты. Внутри детальных карточек, где пользователь приходит работать с конкретной сущностью, технический слой раскрывается полностью — включая редактирование распознанных данных и доступ к оригиналу документа.

**Действия живут внутри сущностей.** Загрузка документа — это не раздел навигации, а действие, привязанное к объекту. Кнопка «Добавить счёт» доступна из карточки объекта, drag & drop работает поверх его страницы.

**Конфигурация живёт там же, где сущность.** Базовые цены, привязанные к договору и объекту, настраиваются внутри карточки объекта, а не в отдельном разделе. Сводный взгляд на цены доступен через карточку материала.

**Глобальные сущности доступны двумя путями.** Поставщик и материал — кросс-объектные сущности. Они доступны как из собственного раздела (полный профиль), так и из контекста связанных сущностей (срез в рамках конкретного объекта).

---

## Главное меню

Пять пунктов, каждый соответствует бизнес-сущности или бизнес-задаче. Никаких технических действий и конфигурационных разделов в навигации.

| Пункт меню       | Роут            | Тип контента                         |
|------------------|-----------------|--------------------------------------|
| Дашборд          | `/dashboard`    | Кросс-объектная аналитика            |
| Объекты          | `/projects`     | Реестр + детальные карточки          |
| Поставщики       | `/suppliers`    | Реестр + детальные карточки          |
| Номенклатура     | `/materials`    | Справочник + детальные карточки      |
| Отчёты           | `/reports`      | Готовые отчёты и экспорт             |

Настройки доступны через меню пользователя в правом верхнем углу, а не через главное меню.

## Описание роутов

### Корневые

#### `/`

Редирект на `/dashboard`.

#### `/dashboard` — Дашборд

Кросс-объектная аналитическая витрина. Главная страница для руководителя тендерной дирекции, который хочет одним взглядом понять состояние портфеля.

Содержит крупный финансовый вердикт по портфелю (общая переплата к базовым ценам, оборот, число объектов, требующих внимания), график динамики цен на ключевые материалы за последние шесть месяцев, блок топ-поставщиков по средней наценке и ленту событий «Требует внимания» (крупные отклонения, документы с низкой уверенностью распознавания, устаревшие базовые цены).

Не дублирует никакую другую страницу. Отвечает на вопрос «что происходит в портфеле в целом», который не может быть отвечен ни на одной карточке отдельной сущности.

### Объекты

#### `/projects` — Реестр объектов

Список всех объектов строительства с метриками на карточках. Поиск по названию и номеру договора, фильтр по статусу (активен, закрыт, требует внимания), сортировка по переплате, обороту или дате последней активности.

Каждая карточка показывает название объекта, номер договора, число счетов, переплату или экономию к базовым ценам, общий оборот. Цветная полоса слева кодирует статус: красная — крупная переплата, жёлтая — умеренная, зелёная — экономия, нейтральная — без активных сигналов.

В правом верхнем углу кнопка «+ Новый объект».

#### `/projects/:id` — Карточка объекта

Главная рабочая страница системы. Сюда пользователь возвращается чаще всего — здесь он добавляет счета, проверяет распознавание, разбирает отклонения, настраивает базовые цены для договора.

Шапка карточки содержит название, номер договора, дату создания, кнопки «Экспорт» и «+ Добавить счёт». Под шапкой — переключатель направлений материалов (см. ниже), затем табы:

`Обзор` (открыт по умолчанию) — крупный баннер-вердикт с величиной переплаты и кнопкой «Разобрать», операционные счётчики (оборот, объём в родной единице направления, число счетов, число счетов к проверке), бар-чарт отклонений от базовых цен с центральной осью «базовая цена». Позиция без настроенной базовой цены показана как «настроить» со ссылкой на таб базовых цен.

`Счета` — таблица всех счетов объекта с поиском, фильтрами по дате, поставщику и сумме. Клик по строке открывает карточку документа.

`Базовые цены` — настройка эталонных цен в рамках договора. Базовая цена — это атрибут связки «объект ↔ материал», она определяется условиями конкретного контракта (даты, объёмы, согласованные тарифы), поэтому её естественное место — внутри объекта. Таб содержит таблицу «материал → базовая цена → дата установки → текущее отклонение фактических цен». Возможность редактирования цен, индикатор устаревших значений (>6 месяцев).

`Поставщики` — список поставщиков, работающих с объектом, с разбивкой метрик: показаны локальные значения (наценка на этом объекте, оборот именно здесь) и средние глобальные (наценка поставщика в целом, для сравнения). Это позволяет понять, ведёт ли поставщик себя на этом объекте лучше или хуже обычного.

По всей странице активен drag & drop: перетаскивание файла в любую область открывает панель добавления счёта.

#### Направления материалов на карточке объекта

Карточка объекта мультикатегорийна: данные сгруппированы по **направлениям** материалов (бетон, арматура, …). Направление в API — это `material_types.code`; список направлений объекта выводится из его позиций (`summary.directions[]`), тип «Прочее» направления не образует.

**Переключатель направлений.** Segmented control между шапкой и табами: `Все направления | Бетон | Арматура | …`. Рендерится только когда у объекта есть хотя бы одно направление с данными; направления без данных в переключатель не попадают.

**Состояние в URL.** Выбранное направление живёт в query-параметре `?direction=` (`all` или code направления): ссылки шарабельны, back/forward работают из коробки. Явный выбор пользователя всегда пишется в URL (включая `?direction=all`); автодефолт URL не переписывает. Мусорный code откатывается на автодефолт и не порождает запросов к API (скоупнутые запросы не стартуют, пока не загружен summary). Дополнительный флаг `?view=errors` читается только при `direction=all` и открывает представление «Ошибки объекта». Активная вкладка в URL не хранится; при смене направления она сбрасывается на «Обзор».

**Правило дефолта** (когда `?direction=` отсутствует или невалиден): направлений нет (пустой объект) → legacy-режим; ровно одно направление → открывается это направление (привычные табы сразу, без лишнего клика); два и больше → «Все направления».

**Четыре режима рендера:**

| Режим | Условие | Состав |
|---|---|---|
| Legacy | направлений нет (объект без счетов) | текущие табы без скоупа, переключатель скрыт — путь «создал объект → задал базовые цены из договора до прихода счетов» сохраняется |
| Сводка «Все направления» | `?direction=all` | четыре KPI с разбивкой по направлениям (оборот, объёмы в родных единицах, счета, переплата), алерт о нераспознанных документах, отклонения секциями по направлениям (top-5 классов, ссылка «открыть →»); без line-табов, таблицы периодов и кнопки настройки базовых цен |
| Ошибки объекта | `?direction=all&view=errors` | контент вкладки «Ошибки» с заголовком «Ошибки объекта» и ссылкой «← к сводке»; контекст направления не меняется — ошибки глобальны для объекта |
| Направление | `?direction=<code>` | полный состав табов (Обзор, Счета, Базовые цены, Коридоры, Поставщики, По месяцам, Ошибки), всё содержимое и счётчики табов в скоупе направления; смешанные счета видны в каждом своём направлении; вкладка «Ошибки» и её бейдж глобальны; экспорт наследует направление (фильтр + суффикс в имени файла) |

#### Панель добавления счёта

Открывается из карточки объекта по кнопке «+ Добавить счёт» или автоматически при drag & drop файла. Реализована как slide-over панель справа (`Sheet` в shadcn/ui), а не как отдельная страница — пользователь не теряет контекст объекта.

Содержит drop-zone для одного или нескольких файлов, прогресс парсинга по каждому файлу, индикатор статуса распознавания. После успешного завершения панель закрывается, новые строки появляются в табе «Счета» с подсветкой. Объект уже известен из контекста, спрашивать его не нужно.

### Поставщики

#### `/suppliers` — Реестр поставщиков

Таблица всех поставщиков, работающих с компанией. Колонки: название, категории поставок, общий оборот, число счетов, средняя наценка к базовым ценам, объекты (с превью первых двух и счётчиком «+N»).

Сортировка по умолчанию — по наценке от большей к меньшей. Это главная бизнес-метрика раздела: с кем мы переплачиваем больше всего и с кем стоит вести переговоры в первую очередь.

Внизу страницы — блок-подсказка с автоматическими рекомендациями для переговоров вида «поставщик X дешевле поставщика Y на N% по бетону В40, возможно стоит расширить с ним сотрудничество». Это превращает раздел из пассивного справочника в активный инструмент.

#### `/suppliers/:id` — Карточка поставщика

Полный профиль поставщика по всему портфелю объектов. Доступен из реестра поставщиков, из карточки объекта (таб «Поставщики»), из карточки материала (через список поставщиков материала) и через глобальный поиск.

Шапка — название, ИНН, категории поставок, общая сводка (оборот за период, средняя наценка, число объектов, число счетов).

Опциональный фильтр по объекту в шапке: позволяет пересчитать карточку под один конкретный объект, не уходя в карточку объекта. Полезно, когда пользователь хочет посмотреть, как поставщик ведёт себя именно на одном проекте.

Табы:

`Обзор` — график изменения цен поставщика по ключевым материалам, помесячная история заказов, общие метрики.

`Счета` — все счета от этого поставщика по всем объектам, с фильтром по объекту и по периоду.

`Объекты` — таблица объектов, где работает поставщик, с разбивкой метрик по каждому: оборот, наценка, число счетов. Это ключевой таб для аналитики «почему один и тот же поставщик ведёт себя по-разному на разных объектах».

`Сравнение` — сравнение средних цен этого поставщика с другими поставщиками по тем же материалам. Готовая аргументация для переговоров о снижении цен.

### Материалы

#### `/materials` — Номенклатура

Справочник классов материалов (бетон, арматура, прочие материалы), к которым в системе ведётся учёт цен. Таблица: код класса, описание, текущая средняя рыночная цена по данным портфеля, число поставщиков, поставляющих этот материал, число объектов, где он используется.

Поиск по коду и названию. Фильтр по группе материалов (бетон, арматура, прочее).

Это переименованная версия раздела «Классы материалов» из текущего интерфейса. Название «Номенклатура» лучше передаёт смысл сущности с точки зрения тендерной работы.

#### `/materials/:id` — Карточка материала

Полная история и аналитика по конкретному материалу. Доступна из реестра номенклатуры, из таблицы позиций в любом счёте, из карточки поставщика (через список поставляемых материалов).

Табы:

`Обзор` — график изменения рыночной цены за период с несколькими линиями: одна на каждого поставщика этого материала. Это позволяет увидеть, у кого цена растёт быстрее рынка, кто стабильнее, кто демпингует.

`Поставщики` — список поставщиков материала со средними ценами и числом поставок.

`Базовые цены` — сводная таблица «объект → базовая цена на этот материал → отклонение фактических цен». Это сводный взгляд на цены, который раньше планировался в отдельном разделе. Здесь он живёт правильно — под углом «один материал, разные объекты» — и отвечает на вопросы вида «почему на Меридиане базовая цена В30 выше, чем на Сити Бэй 3». Редактирование цен также доступно — это вторая точка входа к данным, которые редактируются в табе «Базовые цены» внутри карточки объекта.

`Объекты` — список объектов, где материал используется, с фактическим расходом по каждому.

### Документы

#### `/documents/:id` — Карточка документа

Детальная страница счёта-фактуры или универсального передаточного документа. Доступ — кликом из таблицы счетов в карточке объекта, из таблицы счетов в карточке поставщика, из ленты «Требует внимания» на дашборде, через глобальный поиск.

Это место, где **технический слой раскрывается полностью**. Здесь пользователь исправляет ошибки распознавания, сверяет данные с оригиналом, утверждает корректность документа.

Шапка содержит номер документа, дату, поставщика, объект (с бредкрамбами для возврата), словесный статус распознавания («Распознано надёжно», «Требует проверки», «Разобрать вручную») и статус проверки пользователем («На проверке», «Подтверждён», «Есть отклонения»). Точные проценты уверенности модели доступны в тултипе для тех, кому интересно.

Табы:

`Шапка` — реквизиты документа с возможностью inline-редактирования.

`Позиции` — таблица распознанных строк с редактируемыми полями: наименование, класс материала, количество, единица измерения, цена за единицу, сумма.

`Распознавание` — поля, в которых модель не уверена. Заменяет текущий таб «Проблемы», название более точное.

`Цены` — позиции, отклоняющиеся от базовых цен, с указанием величины отклонения.

Внизу страницы — встроенный PDF-просмотрщик оригинала документа. Пользователь может одновременно видеть распознанные данные и источник.

В меню «...» — действия: скачать PDF, распознать заново, удалить документ. Эти действия редкие и не выносятся на видное место.

Глобального реестра документов в навигации нет. Документы доступны через свои родительские сущности (объект, поставщик) или через глобальный поиск. Глобальный список с фильтрами и экспортом живёт в разделе «Отчёты».

### Отчёты

#### `/reports` — Отчёты

Готовые отчёты для выгрузки и анализа. Каждый отчёт — пресет с фильтрами, превью результата и экспортом в Excel или PDF.

Типовые отчёты:
- «Все документы за период» — глобальный реестр счетов с фильтрами по объекту, поставщику, материалу, дате, сумме. Замена раздела «Все документы» в навигации.
- «Отклонения по объекту» — детальный разбор переплат и экономии по выбранным объектам.
- «Сравнение поставщиков» — таблица сравнения по материалам и средним ценам.
- «Динамика цен» — выгрузка истории цен по материалам и поставщикам.
- «Базовые цены по портфелю» — сводный экспорт всех базовых цен всех объектов в одной таблице, для квартальной ревизии и индексации.

Сюда же относится глобальный поиск по всем документам системы, когда пользователю нужен табличный режим с фильтрами и экспортом.

---

### Системные

#### `/settings`

Профиль пользователя, управление командой (приглашения, роли), интеграции с внешними системами (1С, бухгалтерские системы), настройки уведомлений. Доступ — через аватар в правом верхнем углу шапки, не через главное меню.

#### `/login`, `/signup`, `/forgot-password`

Авторизация и регистрация.

#### `/404`, `/500`

Служебные страницы ошибок.

## Глобальные элементы

Эти элементы доступны поверх всех страниц приложения и снимают необходимость в дополнительных разделах навигации.

**Глобальный поиск (Cmd+K).** Ищет по объектам, поставщикам, материалам, номерам счетов, ИНН. Открывает соответствующую карточку. Снимает потребность в отдельном разделе «Все документы» и упрощает навигацию между связанными сущностями.

**Колокольчик уведомлений.** Лента событий: новое крупное отклонение, документ требует проверки, базовая цена устарела, новый поставщик в системе. По клику — список последних событий с переходом на источник.

**Меню пользователя.** Аватар в правом верхнем углу: профиль, настройки, переключение организации (если будет), выход.

## Где живут базовые цены

Поскольку базовая цена — это атрибут договора, а не глобальная сущность, отдельного роута для базовых цен нет. Управление базовыми ценами распределено по двум естественным точкам входа, в зависимости от задачи пользователя:

**Точечная настройка** — внутри карточки объекта, таб «Базовые цены». Пользователь приходит сюда, когда подписал новый договор, обновил цены по факту переговоров с подрядчиком, или хочет настроить эталон для одного конкретного объекта.

**Сводный взгляд по материалу** — внутри карточки материала, таб «Базовые цены». Пользователь приходит сюда, когда хочет понять, как один и тот же материал оценён по разным объектам — например, при подготовке к новым переговорам или при квартальной ревизии цен.

**Массовый экспорт** — через раздел «Отчёты», отчёт «Базовые цены по портфелю». Используется для офлайн-ревизии всех цен сразу.

Это покрывает все основные сценарии работы с эталонами без создания отдельного раздела в навигации.

---

## Чего специально нет

Эти элементы намеренно исключены из архитектуры по итогам обсуждения:

`/upload` — отдельный роут загрузки документов отсутствует. Загрузка реализована как slide-over панель внутри карточки объекта. Объект всегда известен из контекста.

`/documents` — общий реестр всех документов в навигации отсутствует. Документы доступны через родительские сущности (объект, поставщик) или через глобальный поиск. Табличный режим с экспортом живёт в «Отчётах».

Отдельный раздел «Базовые цены» в навигации отсутствует. Базовая цена привязана к договору и объекту, поэтому управляется внутри карточки объекта. Сводный взгляд доступен через карточку материала. Массовый экспорт — через «Отчёты».

`/etalons` или `/standards` — терминология «эталон» в интерфейсе не используется. Используется «базовая цена» — это лучше считывается тендерным менеджером и точнее передаёт смысл (договорная согласованная цена, а не идеальный образец).

`/upd-tracker` или упоминания УПД — отсутствуют. Документы в интерфейсе называются «счёт-фактура» или «счёт», что соответствует тому, как пользователь говорит о них в работе. УПД остаётся внутренним типом данных, но не выходит в название продукта или раздела.

Технические индикаторы в навигации (статусы микросервисов, очереди обработки, проценты ИИ) — отсутствуют. Они доступны только внутри карточки документа, где пользователь приходит работать с конкретной задачей распознавания.

## Карта связей между сущностями

Любая точка данных в системе доступна с трёх сторон через бизнес-сущности первого уровня:

**Объект** содержит счета, использует материалы, работает с поставщиками, хранит базовые цены договора. На странице объекта видны все связанные сущности в табах.

**Поставщик** работает на нескольких объектах, поставляет несколько материалов, генерирует счета. На странице поставщика видны все связанные сущности в табах.

**Материал** закупается на разных объектах, поставляется разными поставщиками, фигурирует в позициях счетов, имеет базовые цены в разных договорах. На странице материала видны все связанные сущности.

**Счёт (документ)** — единственная сущность, у которой однозначные родители: один объект, один поставщик. Поэтому документы не имеют собственного раздела в навигации — они всегда доступны через родителей.

**Базовая цена** — не сущность первого уровня, а атрибут связки «объект ↔ материал». Поэтому она живёт в карточках обеих этих сущностей, но не имеет собственного раздела.

Эта модель совпадает с тем, как тендерный менеджер мыслит о работе: у него есть объекты, есть поставщики, есть номенклатура, и его задача — управлять пересечениями этих трёх осей.

## Итоговая структура файла роутера

```text
/                       → redirect /dashboard
/dashboard              Дашборд
/projects               Реестр объектов
/projects/:id           Карточка объекта (?direction=, ?view=errors; табы: обзор, счета, базовые цены, коридоры, поставщики, по месяцам, ошибки)
/suppliers              Реестр поставщиков
/suppliers/:id          Карточка поставщика (табы: обзор, счета, объекты, сравнение)
/materials              Номенклатура
/materials/:id          Карточка материала (табы: обзор, поставщики, базовые цены, объекты)
/reports                Отчёты
/documents/:id          Карточка документа

/settings               Настройки
/login                  Вход
/signup                 Регистрация
/forgot-password        Восстановление пароля
/404, /500              Служебные
```

Всего десять содержательных роутов и пять системных. Главное меню — пять пунктов, никаких технических или конфигурационных разделов.
