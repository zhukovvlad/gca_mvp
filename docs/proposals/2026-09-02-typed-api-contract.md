окружении сделаны 2026-09-02.

**Связанное:** `AGENTS.md` §3 (инвариант «numeric ↔ Decimal ↔ строка в JSON»),

## 1. Проблема с замерами

В `backend/routers/` — 81 роут-декоратор и **ноль** `response_model`. Ответы
собираются как `dict` и уходят через `responses.decimal_json`. Обвязка вокруг
каждого эндпоинта: 47 блоков `except DomainError`, 31 вызов
`raise_domain_error`, 33 вызова `decimal_json`.

Форма ответа при этом описана **пять раз**:

| Где | Объём |
|---|---|
| словарь в `crud/*` | внутри 11 910 строк слоя |
| `frontend/src/types/domain.ts` | 1907 строк, 140 интерфейсов, вручную |
| `frontend/src/test/fixtures.ts` | 2589 строк, вручную |
| `frontend/src/test/handlers.ts` | 1640 строк, вручную |
| текст плана фичи | до 6010 строк на фичу |

Коммит `572572f` называет это прямо: «четвёртый круг ревью плана — …и **три
пересказа контракта**».

Кодогенерации нет: в `frontend/package.json` не найдено ни `openapi-typescript`,
ни `orval`, ни `swagger`.

Шестое место, где живёт та же форма, — `frontend/src/test/fixtures.test.ts`,
948 строк, 30 тестов. Они проверяют, что **рукописные заглушки** не
противоречат правилам бэкенда: «`amount = null` ⇔ `amount_unavailable_reason
≠ null`», «`cells` везде одной длины с `columns`», «все коды причин — из
контракта». То есть инварианты, сформулированные в `money/vat.py` и в
`v_category_totals`, реализованы второй раз на TypeScript — ради моков.

## 2. Причина, по которой `response_model` не использовался, на типизированном пути не действует

Докстринг `routers/analytics.py` (строки 8–16) фиксирует причину: FastAPI
прогоняет `dict` через `jsonable_encoder` до рендера и превращает `Decimal` во
`float`. Это верно — и относится только к нетипизированному пути.

Проверено на окружении проекта (fastapi 0.139.2, pydantic 2.13.4):

```
typed  : {"title":"x","amount":"123.4500","rate":null}   # response_model=Row
untyped: {"amount":123.45}                                # dict, как сейчас
schema : {'type': 'string', 'pattern': '...'}             # OpenAPI: деньги — строка
```

`response_model` не только не ломает инвариант §3 — он **вносит его в схему**:
OpenAPI объявляет денежное поле строкой, и это становится машинно проверяемым
фактом, а не докстрингом. Сегодня забытый `decimal_json` в новом роутере
молча отдаёт `float`.

## 3. Выбранный вариант

**Схема как источник, кодоген как способ доставки.**

1. `backend/schemas/` — по модулю на роутер. Денежный тип объявляется один раз:
   `Money = Annotated[Decimal, …]`.
2. Пилот на одном роутере, где `BaseModel` уже есть (`references` или
   `settings`), плюс тест: **во всей схеме OpenAPI каждое денежное поле имеет
   `type: string`**. Один тест на 81 эндпоинт вместо дисциплины ревью.
3. `openapi-typescript` в рецепт `just`; `types/domain.ts` заменяется импортом
   из сгенерированного файла. Расхождение падает на `tsc`.
4. Остальные роутеры — по одному, в темпе фич. Отдельной большой ветки нет.
5. `app.add_exception_handler(DomainError, …)` — вместо 47 блоков
   `except DomainError` в эндпоинтах.
6. `decimal_json` остаётся только там, где ответ принципиально нетипизируем
   (если такие найдутся).
7. Фикстуры фронта — снимки со сгенерированной схемы; `fixtures.test.ts`
   уходит вместе с рукописными заглушками.

Ключи запросов трогать не нужно, и первая редакция этого документа утверждала
обратное — ошибочно. Фабрика ключей в проекте **уже есть**:
`frontend/src/services/queryKeys.ts`, 177 строк, объект `qk` с корневым
префиксом на сущность. Из 99 мест в `queries.ts` её используют 97; инвалидация
идёт по префиксам (`qk.rateClasses.all`), то есть ровно так, как «предлагалось».
Ошибка была в чтении замера: 104 вхождения `queryKey:` — это не литералы, а
вызовы фабрики.

Остаётся ровно одна мелочь, и она не тянет на предложение: две инвалидации
администраторских пользователей обходят фабрику литералом
`["admin", "users"]` (`queries.ts` строки 153 и 165), потому что у `qk.admin`
нет префиксного ключа — `qk.admin.users(q, page, pageSize)` требует
параметров. Правка на две строки: завести префикс и подставить его.

## 4. Отвергнутые альтернативы

1. **Оставить `dict` + `decimal_json`, добавив тест на «все ответы через
   decimal_json».** Такой тест возможен, но он сторожит обёртку, а не форму:
   контракт по-прежнему не описан, и фронт по-прежнему типизируется вручную.
2. **Генерировать TypeScript из `dict`-ответов, снимая их с живого API.**
   Снимок описывает то, что вернулось на конкретных данных, а не контракт:
   `null` в поле не отличим от «поле необязательное».
3. **Описать типы вручную в общем файле и сверять тестом.** Это нынешнее
   состояние плюс ещё один рукописный документ.
4. **`response_model` со `float` для денег.** Прямо нарушает §3.
5. **Перевести все 81 эндпоинт одной веткой.** Ветка на несколько тысяч строк
   без единой поведенческой правки; каждый роутер требует сверки формы ответа
   с фронтом, и делать это разом значит потерять возможность локализовать
   расхождение.

## 5. Что придётся изменить

- Завести `backend/schemas/` и тип `Money`.
- Пилотный роутер + тест «деньги в OpenAPI — строки».
- `backend/main.py` — обработчик `DomainError` на приложении.
- `justfile` — рецепт генерации TS из OpenAPI; шаг проверки «сгенерированное
  совпадает с закоммиченным» в `ci-frontend`.
- `frontend/src/types/domain.ts` → импорт из сгенерированного.
- `frontend/src/test/fixtures.ts`, `handlers.ts`, `fixtures.test.ts` — по мере
  перевода роутеров.
- `frontend/src/services/queryKeys.ts` — префиксный ключ для `qk.admin`,
  чтобы две инвалидации в `queries.ts` перестали обходить фабрику литералом.
- `AGENTS.md` §3 — инвариант денег дополняется словами «проверяется тестом по
  OpenAPI»; §11 — пункт про деньги-строки закрывается механизмом
  (см. [§11 механизмом](2026-09-02-pitfalls-as-mechanisms.md)).

## 6. Чем проверяется, что сработало

- Тест по OpenAPI зелёный и **падает**, если в схеме появляется денежное поле
  с `type: number`. Негативная проверка обязательна: без неё тест доказывает
  только то, что схема существует.
- `types/domain.ts` не содержит рукописных интерфейсов ответов.
- На следующей фиче: форма ответа описана один раз. Проверяется по диффу — в
  нём нет ручной правки типов, фикстур и хендлеров под одну и ту же форму.
