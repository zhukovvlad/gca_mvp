# Предложения: проработано, но не запланировано

Здесь лежат решения, **доведённые до готовности к реализации и осознанно
отложенные**: проблема названа, замеры сделаны, вариант выбран, отвергнутые
названы — но фича не поставлена в работу.

## Зачем отдельный класс документов

Такому материалу нет места в существующей таксономии (`AGENTS.md` §9.2), и обе
попытки пристроить его портят приютивший документ:

* **Спека** (`docs/superpowers/specs/`) означает пройденный гейт 2, то есть
  «реализация следующая». Отложенное решение, положенное туда, читается
  исполнителем как задание — и однажды будет взято в работу без вашего решения.
  Это не гипотетика: агент, открывающий `specs/`, ориентируется именно по
  наличию файла и строке статуса.
* **`TECH_DEBT.md`** — реестр **известных проблем действующего кода**: «что не
  так, чем закрыто сейчас, чем выстрадано». Проектное решение с разбором
  альтернатив и списком правок туда не помещается по природе, а не по объёму:
  долг описывает то, что есть, предложение — то, чего ещё нет.

## Что сюда можно и чего нельзя

**Можно:** решение, у которого есть проблема с замерами, выбранный вариант,
отвергнутые альтернативы и список того, что придётся изменить.

**Нельзя:** идеи без замеров, «хорошо бы когда-нибудь», списки пожеланий. Такому
место в разговоре, а не в репозитории. Папка ценна ровно до тех пор, пока каждый
файл в ней можно взять и реализовать без нового исследования.

## Как отсюда уходят

Файл живёт здесь **временно** и обязан кончиться одним из двух:

1. фича планируется → материал переносится в спеку (`docs/superpowers/specs/`),
   файл отсюда удаляется, чтобы не осталось двух правд об одном решении;
2. предпосылка умерла (данные, требование или код изменились) → файл удаляется,
   а причина смерти записывается в тот документ, который её пережил.

Предложение, пролежавшее без движения и потерявшее связь с кодом, — мусор,
который выглядит как решение. Удалять такое не жаль.
